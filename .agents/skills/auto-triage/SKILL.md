One brave **sweep** over the issues that need attention, applying `triage`'s
per-issue rules autonomously.

**It composes `/triage`.** Every per-issue rule — the label state machine, claim
verification, the Agent Brief format, the redundancy / prior-rejection checks —
lives in `/triage` and its `AGENT-BRIEF.md` / `OUT-OF-SCOPE.md`. This skill adds
only what a **batch, unattended** pass needs, and never restates them. One
override: skip `/triage`'s "generated by AI" disclaimer. The ADR-0017 header
already marks the post as an agent's.

**Verify Public-authored issues and PRs by reading only** — the rule and why
live in `triage`'s Skill Inventory entry.

## What it acts on — the issues that need attention

Scan every **open** issue and in-scope external PR (external-PR scoping is
`/triage`'s own filter — a collaborator's in-flight PR is never triage work).
Never scan a `wayfinder:map` (an index, not work), whoever last commented on it.

For everything else, fetch the **most recent comment** and check who wrote it:

- **No state label, `needs-triage`, or no comments.** Always eligible, whoever
  filed it or commented last, except an on-hold spec or sub-issue
  (`docs/agents/issue-tracker.md`'s Specs), which follows the next bullet.
- **Any other state** (`needs-info`, `ready-for-human`, even `ready-for-agent`)
  **is eligible when its most recent comment is human-authored.**
  Every agent comment carries an ADR-0017 mark, so a comment without one is human (`isAiAuthored`). Never go by the author or `author_association`: agents post as the owner.

Skip any other ticket whose most recent comment is already AI's own. That keeps
repeated sweeps **idempotent**: once an agent answers the human's comment,
the ticket stays quiet until a human writes again, whatever its label reads.

Scan every open issue and fetch its comments: no label query can express a state/comment combination. Add pagination or caching only after a sweep visibly costs time or API budget, not at a guessed issue count.

## Be brave — bounded by determinability

Default to deciding. Stamp `ready-for-agent` and post a full Agent Brief whenever
the repo **determines** a concrete, well-understood design. Escalate to
`ready-for-human` only on a genuine judgment call or genuine design uncertainty,
as ADR-0022 defines them.

**Ordinary implementation latitude is not uncertainty.** The impl choices every
Agent Brief deliberately leaves open — naming, which helper, exact wording — stay
with the implementing agent; never escalate for them. When the reporter can
supply the missing piece, prefer `needs-info` (`/triage`'s Triage Notes template)
over `ready-for-human`. But a dependency major bump with no stated concrete
benefit, or a bug where which behaviour is right is a policy choice, is a judgment
call: `ready-for-human`.

## Closing

Auto-close as `wontfix` only the two **objective, repo-verifiable** kinds:
**already-implemented** (point to where it lives; `state_reason: completed`) and
**duplicate** (point to the canonical issue). A reject-as-out-of-scope is a
judgment call → `ready-for-human`; write `.out-of-scope/` only on a Trusted user's
confirm (see `OUT-OF-SCOPE.md`).

## Approval

What a run may label `ready-for-agent`, and what goes to `ready-for-human`:
ADR-0022.

## Coexisting with wayfinder

Much of the backlog is wayfinder tickets. Overlay triage readiness **without
fighting wayfinder's mechanics** (read `/wayfinder` for them):

- **Skip** a **claimed** (assigned) ticket and a **blocked** ticket (an open
  native dependency *or* a `Blocked by:` body line; `docs/agents/issue-tracker.md`'s
  Wayfinding operations): wayfinder's frontier is open + unblocked + unclaimed,
  so a blocked ticket is not takeable and must not be stamped `ready-for-agent`.
- **Preserve** every `wayfinder:*` label — this is an overlay, never a replacement.
- Honour the ticket type: `wayfinder:grilling` and `wayfinder:prototype` are
  **HITL** (human-in-the-loop) → `ready-for-human`; `wayfinder:research` is
  **AFK** and, when unblocked and unclaimed, is eligible for `ready-for-agent`.
  `wayfinder:task` is HITL or AFK **per ticket**, and no label splits the two:
  by wayfinder's definition it is AFK where the agent can drive it alone, HITL
  where it must hand the human a checklist. Judge the ticket body by that test;
  where it fails (e.g. external access the agent lacks), fall back to the
  judgment-call escalation above rather than grant `ready-for-agent`.

## Coexisting with the guest pipeline

`guest-intake` grants `ready-for-agent` on a **Public** guest's own confirmation
(ADR-0023). That human comment makes the ticket eligible here, and ADR-0022's
rule that a Public-authored issue goes to `ready-for-human` would undo the grant.
But `guest-intake`'s provenance-marked reply lands right after, so the "skip once
AI's own" rule closes the gap. If a sweep inside that gap recurs, add an
explicit skip here instead of relying on timing.

## Run it

**Full-sweep mode.** Pass `full-sweep` as this Skill's argument (e.g.
`/auto-triage full-sweep`) to disable the AI-last-comment idempotency skip
above for this run only — every open, in-scope issue is eligible regardless of who commented last. Use it only when
a human directs a brave re-triage; an agent never picks it on its own.

1. **Resolve the set.** List every open issue via `pnpm exec tsx scripts/github/list-open-issues.ts`
   (overflow-safe — see `docs/agents/github-integration.md` — not raw
   `list_issues`/`search_issues`) plus in-scope external PRs (`issue-tracker.md`'s
   "List external PRs"); for each, check its most recent comment
   against the human-authorship rule above — skip that check entirely in
   full-sweep mode; keep the eligible set; apply the wayfinder skips.
2. **One subagent per issue** (parallel — the eligible set is usually small).
   Brief each with `/triage`'s per-issue rules plus
   the read-only rule, the brave/uncertainty line, and the wayfinder overlay above. Each subagent
   verifies every claim against a primary source in the repo, and reports a claim
   only a write or an external probe could check as unverifiable, naming what
   would verify it. Before judging, it
   reads the git history and session logs that touched the issue's area since
   the issue was filed: later work may have done, superseded or changed it
   (an obsolete or superseded issue is a judgment call, so `ready-for-human`).
   It then applies its own
   labels and posts its own single comment, with the provenance header and no disclaimer; on an issue with no comments it always posts one, so the issue no longer counts as uncommented. A label
   update **replaces** the set, so each passes the complete final label set and
   preserves any `wayfinder:*` label. Each returns to you — not in its brief,
   which stays path-free — the repo files a `ready-for-agent` fix would touch.
3. **Report** a one-line-per-issue roll-up (`#N | category | state | rationale |
   action`). Where a `ready-for-agent` issue shares a file with any other open
   `ready-for-agent` issue (not only this run's), say so, and mark the
   higher-numbered one blocked by the other (`issue-tracker.md`'s Blocking); it
   unblocks when that one closes.
