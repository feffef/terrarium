# 8. The Journal documents the Platform

The `journal` Tenant is how the Platform documents itself. It is Platform
infrastructure, not a demo Tenant. It holds derived Inventories, session logs
that agents write themselves, and Digests; the session logs are ground truth
that nothing else can rebuild.

## Scope and limits

- The Journal is the one Tenant with an ADR, because the self-improvement
  Skills depend on it (ADR-0021 keeps demo Tenants out of ADRs).
- It holds three kinds of content:
  - **Inventories:** derived current-state readouts, refreshed in place. Today
    these are the Skill Inventory and the Friction Ledger.
  - **Session logs:** primary, append-only records, one per Session, that the
    agent writes honestly. How a log is written and lands is ADR-0009.
  - **Digests:** derived, append-only daily pages (ADR-0010).
- Session logs are ground truth, not a projection of the repo. Inventories and
  Digests can be rebuilt from the repo and the logs; session logs cannot.

## Why

The most valuable record of the Platform is what each Session did and where it
hit Friction. That record is primary content that grows over time. A status
readout derived from the repo and overwritten each run cannot hold it, and the
self-improvement Skills need it to find recurring Friction.

## Rejected alternatives

- **A status report derived entirely from repo state.** It labels a logbook as
  a snapshot and leaves no home for content only a Session can author.

## Consequences

- Agent Authorship's split between authored and derived content maps onto this
  Tenant: session logs are authored; Inventories and Digests are derived.
- The name `journal` is baked into the Tenant's collection keys and routes, so
  renaming it would break existing links.
