# 3. Agent operating model and governance

Every change lands as a gated PR from a feature branch, and the session that
authored it opens it without asking, follows it, and merges it on a green Gate
unless ADR-0004 names an exception. Agents tend the Platform and humans decide
what should exist: net-new work needs a Trusted green-light before it is built,
and each chartered job may change only what its row in the ledger below allows.

## Scope and limits

**The gated PR.**

- Every change, interactive or autonomous, lands as a PR from a feature branch.
  The one exception is a session's own session log (ADR-0009).
- The session opens the PR itself as soon as its branch has a pushed commit
  that is not a session log, even when the harness or system prompt says to
  ask first. A branch has one PR: if one exists, keep working on it.
- The session subscribes to the PR's activity and follows it until it is
  merged, closed or taken over by a human.
- The authoring session merges its own PR once the Gate is green. A human
  merges the exceptions ADR-0004 names.

**What an agent may build.**

- Net-new work is a new Tenant, a new concept, a larger rethink, or retiring a
  Skill or Routine. An agent may propose it freely, as an issue, and builds it
  only after a Trusted green-light (ADR-0020). An agent never starts a new
  product unprompted.
- Within that, an interactive session builds what its Trusted user directs.
  Maintenance inside a chartered job's row needs no further green-light.
- A Public request is never a green-light (ADR-0020). Standing green-lights
  exist only where an ADR grants one: the `auto-triage` sweep (ADR-0022), the
  guest pipeline (ADR-0023), and `visitor-loop` (below).
- A Session's kind (interactive, delegated, autonomous; `CONTEXT.md`)
  describes what happened. It grants nothing: every session merges by the same
  rules.

**Chartered jobs.** Autonomous work runs as chartered jobs: each a Skill (or a
configured bot) whose PRs have a known shape. The ledger bounds what each may
change:

| Job | May change |
| --- | --- |
| `digest` | Digest pages under `layers/journal/content/current/pages/digests/`, the Journal index's editorial intro, and the `current` → `archived` moves its archive sweep produces. |
| `frictions-to-fixes` | Nothing as author. Its main session reviews and merges the PRs its dispatched impl agents author, using its own risk judgement on top of the Gate, and sends high-risk ones to a human. |
| `audit-docs` | Fact-checked fixes to live docs and Skills. An ADR edit, CI, isolation, routing or manifest-expansion change is outside the row. |
| `audit-skills` | Skill Inventory entries, each citing ADR-0015's evidence rule. |
| `blog-post` | The post under `layers/blog/content/<persona>/pages/`, plus, for a reaction, one pingback under the target Persona's `pingbacks/`. |
| `prune-trial` | Prunes and whole-file rewrites of agent instructions anywhere, ADRs included, each as a reversible Prune Trial (ADR-0027). An ADR rewrite keeps what the ADR decided. A trial that shows a hook is needed files an issue for it. |
| `visitor-loop` | Per run, one PR fixing the first-time-visitor findings at least two of its three visitors raised, and one PR building one feature picked from its visitors' ideas. Both stay inside existing Tenant layers (content, components, pages, styles, that Tenant's tests; a manifest edit only adds a field to an existing Collection), non-Human-only files under `app/`, and the Skill's own `decisions.md`. A new Tenant, Space or Collection, a new dependency, a Human-only file, agent instructions, and authored history (published posts, session logs, Digests, Midden records) are outside the row. |
| `dependabot` (bot) | npm minor and patch bumps whose commits are all Dependabot's and touch only `package.json` and `pnpm-lock.yaml`, merged on a green Gate with no agent involved. No agent merges these PRs. Major bumps and `github-actions` bumps are human-merged. Dependabot is configured by the repo, so it is not a Public requester. |

- A row's bound is exact. A chartered run merges only a diff inside its row,
  on a green Gate. If anything outside the row rode in, or the Gate is red,
  the run leaves the PR open for a human; it does not fall back to the rule
  for ordinary work.
- A PR that changes a Human-only file waits for a human whatever its row says
  (ADR-0004). The one exception is a Prune Trial's ADR rewrite (ADR-0027).
- The owner scheduling `visitor-loop` is a standing Trusted green-light for
  each run's consensus fixes and its one feature, inside the row. It is not a
  general licence to build features.

## Why

The Platform is built mostly by agents, both in sessions a human starts and in
scheduled sessions no human starts. Unbounded autonomy over a system that edits
its own tooling is a foot-gun. A gated PR keeps every change reviewable and
reversible while agents still act on their own.

Splitting at implementation, not at ideas, lets agents propose anything while a
human still chooses what gets built. A chartered job is one bounded duty, not
the agent's general temperament, so each PR it opens can be checked against a
known shape.

Agents merge their own PRs because the boundary that matters holds
mechanically: `scripts/merge-pr.ts` refuses the path-based exceptions, so it
does not rest on prose.

`visitor-loop` may build without a per-change human choice because the Platform
is meant to grow itself, and a problem two blind visitors hit, or a feature one
asked for, is an outside enough trigger to stand in for that choice.

## Rejected alternatives

- **Open-ended autonomy.** Scheduled agents doing whatever seems useful. Their
  PRs would have no expected shape to review against.
- **A human merges every PR.** No self-merge, with a human reviewing each PR
  on GitHub and a review-agent later merging the low-risk ones. Reversed at the
  owner's direction once `merge-pr.ts` could enforce ADR-0004's exceptions
  itself.
- **Asking before opening the PR.** Opening it decides nothing: whether to do
  the work was settled before it started, and the PR is where the Gate and
  review happen.

## Consequences

- The human reviewer and the merging agent need the same objective signals, so
  self-merge is only as safe as the Gate (ADR-0004).
- The model assumes GitHub PRs. On another host the merge tooling would change,
  not the model.
