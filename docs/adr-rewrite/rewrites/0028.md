# 28. Navigation reads server-rendered payloads

In-app navigation takes a page's data from the target route's server-rendered
`_payload.json`, so the browser skips `@nuxt/content`'s SQLite DB. Only cached
routes get a payload, so `/` and `/t/**` are cached on the server for 60 s,
with no stale serving and a bounded cache. Navigation stays client-side, and
links prefetch on interaction.

## Scope and limits

- **Payloads.** The first page load carries its payload inline. Each later
  navigation fetches the target route's `_payload.json`, and `useAsyncData`
  takes its data from it without running the query in the browser.
- **Cached routes.** `/` and `/t/**` are cached for 60 s with no stale serving.
  A route outside the cache has no payload, so navigating to it queries Content
  in the browser.
- **Bounded cache.** In production the page cache holds a fixed number of
  entries and evicts the least recently used. Each URL, query string included,
  and each `varies` variant is its own entry. Eviction costs only a re-render,
  since freshness is checked on every read. Dev uses Nitro's default disk cache.
- **Request-dependent pages.** A cached page renders once for every visitor.
  A page that reads a request header or cookie needs `varies` on that header,
  or it serves the first visitor's version to everyone. Tinkerfund's pages vary
  on `accept-language`, because its money and dates follow the visitor's
  locale.
- **Server "now".** A value computed from the clock on the server can be about
  two minutes old on a first page load: 60 s in the server cache plus the
  response's `max-age=60` in the browser. This covers Atlas's `useGlassToday`,
  Tinkerfund's `useTinkerfundClock` and the home page's daily picks. On
  navigation they recompute in the browser, because a payload carries data, not
  state.
- **Where the browser DB still loads.** A query outside a payload runs in the
  browser: Tinkerfund search, whose route is uncached on purpose; a re-query
  after mount; and a failed payload fetch, where Nuxt runs the handler in the
  browser. ADR-0019's recovery covers these.
- **Prefetch.** Links prefetch on interaction, not on sight. A route's code
  downloads on hover, or on tap on a touch device.

## Why

The browser DB is heavy and fragile. The first in-browser query downloads the
SQLite WASM runtime and its loader (about 450 KB gzipped), and each queried
Collection adds its `sql_dump.txt`. That load is also the failure path ADR-0019
recovers from. Payloads cut navigation to a fraction: measured gzipped, a blog
post fell from about 494 KB to 7 KB, journal skills from 579 to 144 KB, a
Tinkerfund page from 578 to 19 KB, and the Commons Timeline from about 1.85 MB
to 72 KB.

Payload extraction is documented Nuxt config. It needs no Content internals and
no server code, so it survives Content upgrades.

Server caching is safe because Content is baked per deploy (ADR-0001). The 60 s
lifetime without stale serving bounds how old a server-computed "now" can get.

## Rejected alternatives

- **Full page loads.** They would lose client-side navigation, and with it
  Tinkerfund's view transitions and in-memory state.
- **A Content switch that sends browser queries to its server endpoint.**
  `@nuxt/content` has none.
- **Stale-while-revalidate caching.** It would serve an arbitrarily old copy
  once after an idle period.
- **Prefetch on visibility.** It fetched the payload of every visible link, and
  some pages carry about 550 KB payloads, so navigations got heavier than
  before.
- **An unbounded cache.** Each junk query string adds an entry, so memory grows
  until the next deploy or restart.
- **Prerendering the page routes.** Same client benefit without a runtime
  cache, but it costs build time and needs the routes listed.
- **Pointing `queryCollection` at Content's server endpoint from app code.**
  More round trips, and it relies on an undocumented seam.
- **Patching or aliasing Content internals, or hiding `WebAssembly`.** Each
  works against implementation details; ADR-0019 already reverted one patch.

## When to revisit

- `@nuxt/content` ships a supported switch to keep queries off the browser DB.
- Payloads prove insufficient, for example for queries outside `useAsyncData`;
  then rewiring `queryCollection` to the server endpoint can complement them.
