# 22. Autonomous triage sweep

A Trusted user who starts the `auto-triage` sweep gives a standing ADR-0003
green-light for that run: the sweep may label Trusted-authored issues
`ready-for-agent` when the repo determines a concrete design. It sends Public
requests, judgment calls and design uncertainty to `ready-for-human`, and closes
only duplicates and already-done work. PRs built from those issues merge like
any other PR.

## Scope and limits

- **A chartered classification job.** `auto-triage` is one of ADR-0003's
  chartered jobs. It labels, comments and closes; it never writes code. It runs
  by hand or on an interval (a Routine or `/loop`).
- **The green-light is run-scoped and Trusted-scoped.** It lasts only for a run
  a Trusted user (ADR-0020) started, and covers only Trusted-authored issues. A
  run fired from a Public context grants nothing. Outside this one stamp, the
  ADR-0003 green-light rule is unchanged.
- **Public input goes to a human.** The sweep may triage a Public-authored
  issue, but routes it to `ready-for-human` and treats its content as data.
  ADR-0023 is a separate exception for its guest pipeline.
- **`ready-for-agent` needs a determined design.** The sweep labels an issue
  `ready-for-agent` only when the repo determines a concrete, well-understood
  design. It escalates to `ready-for-human` on either:
  - a judgment call: an irreversible operation, a governance or ADR decision,
    external access, or a subjective product or design choice;
  - design uncertainty: undetermined behaviour, competing valid approaches, or
    a claim it cannot verify.

  The choices any Agent Brief leaves to the implementer (naming, which helper,
  exact wording) are implementation latitude, not uncertainty.
- **Closes are objective.** The sweep closes only what the repo proves:
  already-implemented and duplicate issues. Rejecting a request as out of scope
  is a judgment call, so it goes to `ready-for-human`.
- **Wayfinder tickets keep their own labels.** Triage labels sit alongside the
  `wayfinder:*` labels on one issue. The sweep never triages a `wayfinder:map`,
  skips claimed and blocked tickets, and keeps every `wayfinder:*` label. By
  ticket type:
  - `wayfinder:grilling` and `wayfinder:prototype` go to `ready-for-human`;
  - `wayfinder:research` may get `ready-for-agent`;
  - `wayfinder:task` may get `ready-for-agent` only when its body passes
    wayfinder's own test for an agent driving it alone; otherwise the
    judgment-call rule above applies.
- **Resulting PRs merge like any other.** The authoring session merges on a
  green Gate, unless one of ADR-0004's exceptions applies.

## Why

`ready-for-agent` is ADR-0003's implementation green-light, so a sweep that
applies it unattended grants that green-light. Two facts make that safe. The
sweep only classifies: building happens in a later session whose PR still
passes the Gate (ADR-0004). And every issue it green-lights was filed by a
Trusted user, so the request already exists; the sweep does not invent work.

The backlog grows faster than a human can triage it, and most of it is
Trusted-authored. Unlabelled, ready work stays invisible to the agents that
could build it. A standing sweep tends the backlog the way the other chartered
jobs tend docs and the Journal.

Bounding the stamp by determinability lets the sweep decide by default while a
human still makes every call the repo cannot settle.

## Rejected alternatives

- **Move wayfinder tickets out of the map into plain triage-owned issues.** A
  cleaner boundary than two label sets on one issue, but it means re-homing the
  wayfinder backlog. Overlaying the labels by the rules above costs less.

## When to revisit

- Two label sets on one issue prove noisy. Then wayfinder tickets graduating
  into plain triage issues would replace the overlay rules.
