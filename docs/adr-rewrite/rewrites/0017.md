# ADR-0017: Every agent write names the session that made it

Agents act on GitHub through the owner's own account, so GitHub cannot tell
an agent's post from the owner's. Every agent write to GitHub, git or any
other outside system therefore carries a mark that names the session that
made it, with no exceptions. A GitHub body opens with a one-line header; a
commit ends with a two-line trailer.

## Scope

- **What it covers.** Issues, PR descriptions, comments, inline review
  comments and reviews, and every commit, including session-log commits and
  commits made through the GitHub API tools. A call that writes no text, such
  as a label change or a bare approval, carries nothing.
- **The mark names this session.** A link to another session counts as a
  wrong mark, so a body copied from another session gets its header replaced.
  The model name is optional on GitHub bodies; the session log records it.
- **GitHub bodies are blocked without the header.** The tool-call guard
  checks each write and denies one that lacks this session's header, carries
  it in another shape, or cannot be checked. When in doubt it denies.
- **Commits are repaired, never blocked.** The commit hook adds a missing
  trailer or corrects a wrong one. If the hook fails, the commit goes through
  unmarked, so agents check that the trailer landed.
- **Reading is wider than writing.** Code that asks "did an agent write
  this?" also accepts the old two-line footer on GitHub bodies and the Claude
  Code tool's own "Generated with Claude Code" line. A bare session link in
  prose does not count. No mark means a human wrote it.
- **The tool's own footer stays.** Agents leave it in place beside the header.
- **Older posts are not rewritten.** Content from before this rule has no
  mark, and posts with the old footer keep it.

## Why

The login and `author_association` show the owner for every agent write.
Agents misread who did what because of it, and pipelines that skip their own
earlier comments need some way to find them. A mark in the content itself is
the one signal every reader can check.

No exceptions, because each narrower rule ("top-level comments only",
"GitHub only") is one more gap to remember.

GitHub writes are blocked rather than trusted to the agent. Prose versions of
this rule were missed again and again, including by sessions that had read
it. The deny message teaches the exact format at the moment of the mistake.
Commits can be fixed in place by the hook, so blocking them buys nothing and
a hook bug would stop all work.

## Rejected alternatives

- **A separate bot account** (a machine user or GitHub App, issue #124). It
  would fix the login fields at the source, but GitHub access is a managed
  connection set up outside this repo. Each kind of session (local CLI, cloud
  connector, future scheduled runs) would need re-pointing. Set aside, not
  ruled out.
- **A footer at the end of GitHub bodies.** It fought the Claude Code tool's
  own footer for the last line, and agents dropped it. The first line is a
  place nothing else claims.
- **Accept any shape that names the session.** Agents then invented their own
  shapes, which readers could not rely on.
- **Let the guard add a missing header instead of blocking.** Nobody has shown
  that a tool-call hook can rewrite the call it checks.
- **A check in the gate.** The gate sees the repo, not what was posted to
  GitHub.

## When to revisit

- A separate bot account becomes possible for every kind of session (#124).
- A tool-call hook can rewrite its call, so the guard could add the header.

## Consequences

- Threads are noisier: every inline review comment repeats the header.
- Changing the mark's shape is cheap for writers but not for readers: code
  that finds agent posts must keep accepting every shape ever written, or it
  will treat old agent posts as human ones.
- The guard checks only the GitHub tool calls. A write through `gh api` goes
  unchecked.
