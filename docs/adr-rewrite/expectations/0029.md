## Checklist

Most relied-on first.

1. **When does an instruction reach an agent?** Claim: a rule shows up by
   itself, either at session start or when the agent reads or edits the files
   it lists, or runs the Skill it names. Decision. 4 refs (enforces 1,
   explains 2, points 1). CONTEXT.md:242, scripts/validate-adr-rules.ts:121.
2. **Must every rule that is not an ADR summary list the files it covers?**
   Claim: yes; one without a file list fails the check. Mechanic, home
   `scripts/validate-adr-rules.ts`. 3 refs (enforces 3).
   scripts/validate-adr-rules.ts:8, tests/unit/validate-adr-rules.spec.ts:113.
3. **When a Bash command reads a file, does the matching rule load?** Claim:
   only when the command is one plain read of one file; a piped, chained
   (`cd … &&`) or multi-file read loads nothing. Mechanic, home
   `scripts/shell-reads.ts` (`bashReadPaths().simple`) and
   `scripts/bash-rules-hint.ts`. 3 refs (enforces 1, explains 1, repeats 1).
   scripts/bash-rules-hint.ts:4, CLAUDE.md:220.
4. **Must every how-to doc for agents (`docs/agents/*`) be reachable?** Claim:
   each is named either in CLAUDE.md's "Docs you must read first" list or by a
   rule; `docs/research/` is deliberately left out. Decision. 2 refs
   (explains 1, repeats 1). .agents/skills/audit-docs/SKILL.md:135,
   .agents/skills/frictions-to-fixes/SKILL.md:160.
5. **May a rule name a doc that does not exist?** Claim: no; a non-ADR rule may
   name only `docs/` files that exist. Mechanic, home
   `scripts/validate-adr-rules.ts`. 2 refs (enforces 2).
   scripts/validate-adr-rules.ts:8, scripts/validate-adr-rules.ts:121.
6. **What can a rule be?** Claim: either an ADR's summary (the ADR stays the
   source; the summary brings its key parts to agents) or an instruction about
   specific files, which the rule holds itself or points to. Decision. 2 refs
   (explains 1, points 1). CONTEXT.md:242,
   docs/adr/0030-adrs-document-a-decision-not-its-history.md:6.
7. **Where do instructions that apply to every session go?** Claim: in
   CLAUDE.md, not in a rule. Decision. 1 ref (enforces 1).
   scripts/validate-adr-rules.ts:121.
8. **Are instructions tied to an action (a commit, a push) rules?** Claim: no.
   Where they live instead is unclear from callers (probably CLAUDE.md's
   read-first triggers). Decision. 1 ref (explains 1). CONTEXT.md:242.
9. **What happens when a rule loads where it does not apply?** Claim: the
   agent logs it as a Friction naming the rule file, the file or Skill it was
   on, and the narrower file list that would have avoided it. Decision. 1 ref
   (explains 1). .agents/skills/log-session/SKILL.md:188.
10. **Is the gap for Bash reads closed?** Claim: a hook adds the matching rules
    after a Bash read that Claude Code skipped; it is a hint, not a guard, and
    adds nothing on error. Mechanic, home `scripts/bash-rules-hint.ts`. 1 ref
    (enforces 1). scripts/bash-rules-hint.ts:4. **Conflict:** CLAUDE.md:220
    tells agents to use the Read tool because such Bash reads "load no rule",
    while bash-rules-hint.ts:4 says the hook fills that gap. The ADR should say
    whether the hook is a backstop or the Read-tool advice is the rule.
