## Checklist

Most relied-on first. Roles: E enforces, Q quotes, X explains, P points,
R repeats.

1. **How are logs from outside agents treated?** A log written by a different
   agent or toolchain carries `external: true` (absent means ours). It stays
   visible and is marked on the dashboard (no session web page). Friction
   mining and the Skill audit skip it entirely; its ideas still surface; its
   learnings are dropped. *Decision.* 19 refs: E10 Q5 X3 R1. Home of the check:
   `shared/schemas/session.ts` (`isExternalSession`). E.g.
   `shared/schemas/session.ts:90`, `layers/journal/app/utils/dashboard.ts:301`.
2. **Which changes may go to `main` without a PR?** Only one session's own log
   file, in the sessions folder, pushed by a script. The reason: it is inert,
   schema-checked data the gate can't protect and a PR would suppress. Logs never
   travel through a feature branch or PR (one exception: item 8). Opening PRs
   automatically does not change this. *Decision.* 9 refs: X3 P3 E2 R1. E.g.
   `docs/adr/0003-agent-operating-model-and-governance.md:141`,
   `scripts/log-session.ts:438`. **Conflict:** `scripts/merged-since.ts:8,67`
   speak of direct-to-`main` "session/doc" commits; every other caller limits it
   to the one session-log file.
3. **When does a shell command count as reading a doc?** Credit comes from the
   command's output: the doc counts as read when the output shows enough of its
   distinctive lines (a line must be at least 30 chars; at least 10 lines
   shown). Parsing the command only explains near-misses. Which docs are in
   scope is a path-shape test. Shell reads now fold into `docsRead`; the old
   `docsReadViaShell` field stays only so older logs validate. *Mechanic*, home
   `scripts/shell-reads.ts` (`MIN_DISTINCTIVE_LINE`, `MIN_LINES_SHOWN`). 11 refs:
   Q9 E1 P1. E.g. `scripts/shell-reads.ts:770`, `scripts/session-trace.ts:532`.
   **Conflict:** `docs/research/shell-reads-by-output-matching.md:129` quotes the
   ADR saying the trace is "derived from `tool_use` calls, not results"; the
   output-matching callers read results.
4. **What does the agent write, and what is derived?** The agent writes only
   the judgment half (goal, status, outcome, summary, every friction, optional
   ideas and learnings, chosen `docsRead`/`skillsUsed` with reasons). Timings,
   models, tool counts, files, subagents (folded in), branch and rules loaded
   come from the transcript and are never self-reported; uncited reads get a
   placeholder reason. *Decision.* Home `scripts/session-trace.ts`. 8 refs: E6
   R2. E.g. `scripts/session-trace.ts:22`, `.agents/skills/log-session/SKILL.md:10`.
5. **Can the log's shape change, and how?** The schema is frozen and strict.
   Additive optional fields need no version bump; `schemaVersion` absent means 1
   until the first breaking change. Other append-only collections (pingbacks)
   follow this same policy, so the ADR is its single home. *Decision.* Home
   `shared/schemas/session.ts`. 7 refs: P3 X2 Q1 E1. E.g.
   `layers/blog/tenant.config.ts:86`, `docs/adr/0012-cross-persona-pingbacks-via-authored-denormalization.md:72`.
6. **When must a session write its log?** When it opens a PR (status
   `in-review`: PR open, not merged), and again when the work is done or
   blocked. `completed` is only for work that landed. The rule loads at session
   start so it can say when to act. *Decision.* 6 refs: P3 X2 R1. E.g.
   `docs/adr/0003-agent-operating-model-and-governance.md:46`,
   `docs/adr/0029-instructions-load-with-the-files-they-govern.md:66`.
   `docs/diagrams/interactive-map/terrarium-overview.md:869` (PRs row) is
   unclear.
7. **What enforces the boundary?** `scripts/log-session.ts` is the single
   enforcement point and the only module that lands a log: it refuses a file
   outside the sessions folder, a commit that changes more than one path, and a
   wrong filename (`<startedAt-date>-<session>.yml`); it validates against the
   schema. GitHub can't scope by path, so this script is the only path-level
   check. *Mechanic*, home `scripts/log-session.ts`. 5 refs: E3 Q1 X1. E.g.
   `scripts/log-session.ts:1097`, `tests/unit/log-session.spec.ts:1`.
   `scripts/session-logs.ts:2` (keep it dependency-light) is unclear.
8. **How does an outside agent's log land?** It has no hook and no push to
   `main`, so it commits its log inside its fork PR, the one allowed case of a
   log in a PR; marked `external: true`; one log per unit of work, revisions
   included. *Decision.* 5 refs: Q3 P1 E1. E.g.
   `docs/agents/guest-contributions.md:61`, `layers/journal/tests/e2e/journal.spec.ts:49`.
9. **How does the push get past `main`'s protection?** The `protect-main`
   ruleset lets the repo admin (the owner's credential, which the lander uses)
   bypass "Always"; each bypass is recorded, which is the audit trail the
   exception should leave. Classic branch protection would block it.
   *Mechanic*, home the GitHub ruleset, recorded in
   `docs/research/github-branch-protection-vs-autonomous-log-commits.md`
   ("Current state"). 5 refs: X4 Q1. E.g. that file :210, :269.
10. **When and how does a log land?** The agent's authoring writes a gitignored
    scratch; hooks stitch it with the trace and push it, with `Stop` as primary
    and `SessionEnd` and `SessionStart` (resume) as fallbacks; each log records
    which hook landed it (`landedBy`). An unchanged re-derive never commits.
    *Mechanic*, home `scripts/log-session.ts` and `.claude/settings.json`. 5 refs:
    Q3 E1 X1. E.g. `scripts/log-session.ts:11`, `shared/schemas/session.ts:103`.
    **Conflict:** `shared/schemas/session.ts:53` and `.gitignore:33` call the
    lander the "SessionEnd" extractor/handler; `scripts/log-session.ts:11` and
    `.agents/skills/log-session/SKILL.md:10` make `Stop` primary.
11. **What is a session log for?** One honest self-report per session, the
    Platform's main record of itself (not a Tenant's private content), and the
    input the self-improvement Skills mine. *Decision.* 5 refs: X5. E.g.
    `shared/schemas/session.ts:1`, `.agents/skills/frictions-to-fixes/SKILL.md:9`.
12. **How are old logs archived?** Aged-out logs move from `current` to
    `archived` by `git mv`, keeping the newest 7 session dates; the move goes
    through a normal reviewed PR, not the direct path. *Mechanic*, home
    `scripts/archive-journal-content.ts`. 5 refs: X3 R1 Q1. E.g.
    `docs/adr/0010-digests-derived-append-only-journal-pages.md:20`,
    `.agents/skills/midden-survey/scripts/midden-survey.ts:111`.
13. **What does not qualify for the direct path?** Digests, pingbacks and blog
    content, Skill-audit output, archive moves, and changes to the lander's own
    code all go through a normal PR. *Decision.* 4 refs: X3 R1. E.g.
    `docs/adr/0010-digests-derived-append-only-journal-pages.md:62`,
    `.agents/skills/log-session/SKILL.md:160`.
14. **What happens to a derived read the agent never actually read?** The agent
    marks it `(not read)` and the stitch drops it; a dropped shell credit becomes
    a Friction. A real read the detector missed is logged as a Friction marked
    `SHELL-READ-DETECTION`, severity at least `moderate`, with the command and the
    expected path. *Mechanic*, home `scripts/session-trace.ts`
    (`NOT_READ_REASON`) and the `log-session` Skill. 4 refs: Q3 P1. E.g.
    `scripts/session-trace.ts:768`, `CONTEXT.md:142`.
15. **How do read reasons and usefulness work?** `docsRead` and `skillsUsed`
    merge the agent's picks with derived entries; a `useful` verdict (yes,
    partly, no) is written only by the agent, and is absent on derived reads and
    on logs before 2026-10-11; loaded rules also get verdicts. *Mechanic*, home
    `shared/schemas/session.ts`. 3 refs: Q2 E1. E.g.
    `shared/schemas/session.ts:47`, `scripts/log-session.ts:810`.
16. **How does the log commit carry its session id?** It gets the same
    `Claude-Session` trailer, built in repo code, and `log-session` reads the id
    from it. *Mechanic*, home unclear (`scripts/log-session.ts`?). 2 refs: X2.
    E.g. `docs/adr/0017-provenance-footer-on-agent-authored-content.md:31`, :59.
17. **What decides when the fallback hooks can be retired?** **Conflict:**
    `shared/schemas/session.ts:103` says the exit measure counts `landedBy`
    rather than orphaned sessions; `scripts/audit-skills.ts:169` calls ADR-0009's
    measure the `close-session` invocation rate (orphan count). *Decision.* 1 ref
    (+1 shared): X1.
18. **Can a landed log be changed?** **Conflict:**
    `scripts/validate-content.ts:97` treats older logs as untouchable (skipped by
    a check, "ADR-0009's bounded exception", unclear); `shared/schemas/session.ts:37`
    has a later session flip `in-review` to `completed`, and
    `docs/agents/guest-contributions.md:61` updates a log on revision.
    *Decision.* 1 ref (+2 shared): X1.
19. **Is re-deriving a log repeatable?** A re-derive must give the same bytes
    and a superset of entries; a doc edited between derivations can break this
    under output matching. *Mechanic*, home `scripts/log-session.ts`. 1 ref:
    Q1. `docs/research/shell-reads-by-output-matching.md:132`.
