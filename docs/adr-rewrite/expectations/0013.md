## Checklist

Most relied-on first.

### C1. `content.config.ts` builds the collections from the manifests when the config loads (decision)
Claim: `content.config.ts` is an ordinary, hand-edited module. It is not
generated, has no banner and no drift check, and is linted. Each time it loads,
it reads every Tenant manifest and builds one collection for each Tenant ×
Space × Collection. Agents edit only the manifest and never write that list by
hand.
- Relied on by: 23 (enforces 1, repeats 6, explains 10, quotes 3, points 3)
- e.g. content.config.ts:1, layers/journal/tenant.config.ts:3, shared/manifest.ts:4, docs/adr/0007-generated-config-committed-drift-checked.md:6
- **conflict (wording):** CONTEXT.md:51 says each Collection "is generated per
  Tenant × Space at build time", and .claude/rules/adr-0002.md:13 says "at build
  time". content.config.ts:1 and every manifest header say "config-evaluation
  time" and "no generated file". The ADR should say which word is exact.

### C2. No generator or code-generation step remains (decision)
Claim: nothing is regenerated or committed. There is no `pnpm gen` and no
generator to "fail fast before", and validating a manifest is a standalone
check.
- Relied on by: 12 (explains 6, repeats 5, quotes 1)
- e.g. shared/manifest.ts:150, shared/manifest.ts:163, layers/midden/content/trench/artifacts/the-generator.yml:8
- **conflict:** most callers credit "ADR-0013/0014" jointly with removing the
  generator (shared/manifest.ts:150, docs/adr/0004-objective-safety-gate.md:81,
  the-generator.yml:8). docs/adr/0014-build-time-virtual-routing-module.md:31,
  docs/adr/0007-generated-config-committed-drift-checked.md:11 and the-generator.yml:21
  say ADR-0013 **kept** `scripts/generate.ts`, `pnpm gen`, `pnpm gate:drift` and the
  committed routing map, and that ADR-0014 removed them. The rewrite must say plainly
  that ADR-0013 alone removed only the generated `content.config.ts`.

### C3. What ADR-0013 replaced in ADR-0007, what it kept, and what replaced that (decision)
Question: which part of ADR-0007 does ADR-0013 replace, which part did it keep
(the committed routing map `shared/routing.generated.ts`), and does that kept
part still stand? The callers say ADR-0014 replaced it.
- Relied on by: 10 (quotes 5, points 4, explains 1)
- e.g. docs/adr/0007-generated-config-committed-drift-checked.md:4, docs/adr/0014-build-time-virtual-routing-module.md:26
- The ADR's file name still says "committed-routing-map", which is no longer
  true (see Repoint).

### C4. Collections are defined only in the root `content.config.ts`, and Tenant layers define none (decision)
Claim: a Tenant's Nuxt layer is presentation only and declares no content
collections.
- Relied on by: 7 (repeats 6, explains 1)
- e.g. layers/blog/nuxt.config.ts:7, layers/tinkerfund/nuxt.config.ts:2, nuxt.config.ts:3
- unclear whether ADR-0013 or ADR-0002 owns this. Every caller cites "ADR-0002/0013".

### C5. The collections and the routing map come from one shared pure function (mechanic)
Claim: `content.config.ts` and `modules/routing.ts` both run the same pure
`expand()`, so one source of truth gives both the collections and the routes.
- home: `shared/expand.ts`; tested by `tests/unit/expand.spec.ts`
- Relied on by: 5 (explains 4, enforces 1)
- e.g. shared/expand.ts:4, tests/unit/expand.spec.ts:5, .claude/rules/adr-0002.md:13

### C6. When the collections are rebuilt, and the dev-server gap (mechanic)
Claim: every `nuxt prepare`, every build and every dev-server start rebuilds the
collections from scratch. Nuxt Content's config loader watches only
`content.config.ts`, not the files it imports, so a manifest edit during a
dev-server session is picked up by `modules/routing.ts` (ADR-0014, #325).
- home: `content.config.ts`, `modules/routing.ts`
- Relied on by: 2 (enforces 1, quotes 1)
- e.g. content.config.ts:1, docs/adr/0014-build-time-virtual-routing-module.md:31

### C7. Why: the failure this removes, and what it gave up (decision)
Question: which failure does this remove? Callers say it removes "a manifest
was edited but the regenerated config was not committed". They also say the
committed file's one-line-per-collection diff was valued as a review signal
(ADR-0014 later gave that up for the routing map).
- Relied on by: 3 (quotes 2, explains 1)
- e.g. docs/adr/0014-build-time-virtual-routing-module.md:31, docs/adr/0014-build-time-virtual-routing-module.md:96, layers/midden/content/trench/artifacts/the-committed-config.yml:16
