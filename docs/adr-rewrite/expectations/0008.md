### 2. Conflicts

- **What an Inventory is (item 3 vs item 4).** ADR-0010 quotes ADR-0008's
  Inventory as "derived from repo state, overwritten each sync". The Friction
  Ledger, which 11 historical callers file under ADR-0008 as an Inventory, was
  "seeded from the analysis" of session logs and is edited by an agent
  (`01V3b…:9`), so it is curated from logs rather than derived from repo state.
  A rewrite should say whether "derived from repo state" is essential to an
  Inventory.
- **Where "logs are ground truth" lives (item 5).** Callers credit ADR-0008;
  the always-loaded ADR-0009 summary also says to treat landed logs as fixed.
  Not a contradiction, but two homes for one fact.
- **When the rule loads (not the ADR's concern).** The fixture in
  `always-loaded.spec.ts:8` expects the rule path-scoped to `layers/journal/**`,
  and most historical notes agree ("loaded on reading journal layer file");
  three say "loaded at session start" (`01YVC…:308`, `01Dz5…:248`,
  `01FJu…:277`). This is rule frontmatter, not ADR content.

### 3. Misplaced expectations (ADR-0030)

- **File mapping:** the overview map ties `scripts/archive-journal-content.ts`
  to ADR-0008 (`terrarium-overview.md:865`). A script path belongs in the map,
  not the ADR; the ADR need only state the decision the script implements.
- **Collection/Space list:** the 2026-07-04 digest says ADR-0008 gave the
  Journal three Collections (`pages`, `skills`, `sessions`) across `current`
  and `archived`. That list lives in `tenant.config.ts`; it has since grown
  (Friction Ledger), so an ADR copy would drift.
- **Inventory membership:** callers use ADR-0008 to confirm that a specific
  Inventory (Friction Ledger) belongs to the Journal. The membership list
  belongs in the glossary (`layers/journal/CONTEXT.md`); the ADR should
  define the kind, not enumerate instances.
