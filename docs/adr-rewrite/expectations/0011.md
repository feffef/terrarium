## Checklist (most relied-on first)

1. **Claim: the live site runs in one container that downloads `main`, builds
   it and serves it; a push to `main` never needs a new image.** Decision.
   8 refs: enforces 3, points 3, quotes 1, explains 1.
   e.g. deploy/Dockerfile:3, README.md:34.
2. **Claim: merging to `main` runs that code on the server, so whoever can
   merge can run code there; merge is the code-execution boundary.** Decision.
   6 refs: explains 5, points 1.
   e.g. docs/adr/0020-requester-trust-tiers.md:36, docs/adr/0023-guest-driven-demo-pipeline.md:44.
3. **Question: how far does this bend ADR-0001's "nothing is created at
   runtime"?** Callers say: only the build runs at runtime, only in the deploy
   runner; content is still declared and baked at build time; nothing creates
   Tenants or collections at runtime. Decision.
   4 refs: quotes 1, points 1, explains 1, enforces 0 (+deploy/README.md:4 "trade-off against ADR-0001").
   e.g. docs/adr/0001-single-container-baked-multitenancy.md:6, .agents/skills/guest-intake/SKILL.md:88.
4. **Mechanic: the update cycle** — poll `origin/main`, build new commits
   beside the live copy, swap atomically (about 1-2 s restart); a failed build
   never touches the live server; the supervisor does not exit on one failing
   command. Home: `deploy/entrypoint.sh`.
   3 refs: enforces 2, explains 1.
   e.g. deploy/entrypoint.sh:3, deploy/docker-compose.yml:1.
5. **Question: is this a temporary trial, and what is the way back to a
   fixed image built by CI?** Callers call it a "PoC" and "scoped trade-off"
   with a "migration path"; the README says it is the public deployment. Decision.
   4 refs: points 3, quotes 1.
   e.g. docs/adr/0001-single-container-baked-multitenancy.md:12, deploy/README.md:4.
6. **Mechanic: which files make up the deploy** — `deploy/Dockerfile`,
   `deploy/docker-compose.yml`, `deploy/entrypoint.sh`, `deploy/.env.example`,
   with `deploy/README.md` as the how-to. Home: `deploy/README.md`
   (and the interactive map's file table).
   2 refs: points 2. e.g. docs/diagrams/interactive-map/terrarium-overview.md:872.
7. **Mechanic: secrets** — the GitHub token lives only in the server's
   `.env`, is handed to git at runtime and never written to `.git/config`; the
   real `.env` is never committed. Home: `deploy/.env.example`.
   2 refs: enforces 2. e.g. deploy/.env.example:1.
8. **Question: does the deploy install run package install scripts?** One
   caller suggests a locked, script-free install to shrink the code-execution
   risk; no caller says what is decided. Mechanic, home `deploy/entrypoint.sh`.
   Unclear. 1 ref: explains 1. docs/research/public-readiness-review.md:52.
9. **Mechanic: network** — the container is reached only through the shared
   Caddy proxy on the external `web` network; it publishes no host port.
   Home: `deploy/docker-compose.yml`. 1 ref: enforces 1.
10. **Mechanic: base image** — Node 22 or later (for the built-in SQLite the
    content module uses), pnpm from corepack at the repo's pinned version.
    Home: `deploy/Dockerfile`. 1 ref: enforces 1. Likely too fine for the ADR.

No conflicts found. Item 5 is the closest: "PoC" with a way back (ADR-0001)
versus "publicly deployed" as the standing setup (README.md:34); not
contradictory, but the rewrite should say whether the way back is still planned.
