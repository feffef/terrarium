## Checklist (most relied-on first)

Each item shows code / docs counts. A reference can count toward more than one
item.

1. **Claim: some surfaces are Human-only to merge, whatever the gate says.**
   These are:
   - the isolation-critical family: `content.config.ts`, `shared/expand.ts`,
     `modules/routing.ts`, `shared/routing.ts`, `modules/catalog.ts`,
     `shared/kinds.ts`, `shared/schemas/`, `app/composables/catalog.ts`
   - CI: `gate.yml` and `action.yml`
   - governance and ADRs
   - root `nuxt.config.ts`
   - the generator

   Code 6 / docs 27. Examples: `modules/catalog.ts:13`, `shared/kinds.ts:13`,
   `docs/adr/0025-…:177`, `docs/adr/0014-…:87`.

2. **Claim: a layer page that reuses `resolveSpaceRoute` read-only stays
   outside the Human-only core.** This covers "isolation-respecting" and
   "presentation-only" code. Question: what keeps such a change out of the
   human-merge set? Code 22 / docs 2. Examples:
   `layers/blog/app/pages/t/blog/[space]/[...slug].vue:6`,
   `layers/atlas/nuxt.config.ts:6`, `docs/adr/0016-…:37`.

3. **Question: what is the Gate?** Callers expect an objective, layered bar,
   cheapest first, that runs locally and in CI, with CI authoritative. They
   expect these layers:

   | Layer | Checks |
   |---|---|
   | L0 | typecheck and lint |
   | L1 | content/schema validation |
   | L2 | build plus smoke e2e |
   | L3 | isolation invariant |

   Code 11 / docs 8. Examples: `.github/actions/gate/action.yml:2`,
   `tests/e2e/smoke.spec.ts:1`, `nuxt.config.ts:47`, `CONTEXT.md:269`.

4. **Question: which paths are Human-only, and where does the list live?**
   Callers claim the list is the `paths` of
   `.claude/rules/adr-0004-human-merge.md`, and that `merge-pr.ts` reads it
   from `origin/main` and refuses to merge a PR that touches one. Code 7 /
   docs 8. Examples: `scripts/merge-pr.ts:168`, `docs/agents/pr-workflow.md:5`.

5. **Claim: an unattended hook or guard is Human-only to merge.** It must also

## Flag 2: conflicts

1. **Who merges an ordinary agent PR?** Two sets of callers disagree.
   - Agents self-merge, and ADR-0004 names the exceptions: `CLAUDE.md:52`,
     `docs/adr/0003-…:96,101`, `docs/adr/0022-…:129`, the adr-0022 rule,
     `pr-workflow.md:91`.
   - A human merges every PR, with no self-merge:
     - `docs/adr/0022-…:35,58,87`
     - `docs/adr/0020-…:51`
     - `docs/adr/0003-…:150,159`: auto-merge is a future "TBD" that waits on
       defining the gate
2. **Tiers or exceptions?** Some callers expect ADR-0004 to define
   blast-radius or low-risk auto-merge tiers: `docs/adr/0020-…:41,111,121,156`,
   `pr-workflow.md:75`. Others expect an exceptions-only model: item 7.
3. **Where does the Human-only list live?**
   - In the rule's `paths`, called its single home: `merge-pr.ts:168`,
     `CONTEXT.md:298`, `docs/adr/0029-…:54`.
   - In ADR-0004 itself, as a "named high-risk file list" or "high-risk set":
     `docs/adr/0019-…:111`, `docs/adr/0026-…:64`, `gate.yml:5`.
   - `docs/adr/0023-…:83` and `docs/adr/0013-…:86` also enumerate surfaces
     themselves.
4. **Does Human-only constrain edit or only merge?**
   - Merge only: `CONTEXT.md:298`, `docs/adr/0026-…:88`.
   - Edit as well: `frictions-to-fixes/SKILL.md:230` says "never edit an ADR
     (human-only, ADR-0004)", and `docs/adr/0014-…:87` says "CI is human-only,
     so this change cannot remove it".
5. **Are ADRs always Human-only?** `docs/adr/0020-…:12` and
   `docs/adr/0023-…:11` say governance and ADRs are Human-only. ADR-0027 and
   `merge-pr.ts --prune-trial` exempt a Prune Trial's ADR rewrite (item 11).
   The rewrite must state the carve-out.
