## Checklist (most relied-on first)

1. **Claim: collections are defined in one place only.** Every content
   collection is defined in the root `content.config.ts`, built from the
   manifests. A Tenant's Nuxt layer only changes how things look and defines no
   collections. *Decision.* 12 refs: 6 explains, 6 repeats. E.g.
   `layers/journal/nuxt.config.ts:8`, `nuxt.config.ts:3`.
2. **Claim: each Tenant is described by one small file of settings, and that
   file is what agents edit.** The file is `layers/<tenant>/tenant.config.ts`;
   it states what the Tenant contains, not how to build it. *Decision.* 9 refs:
   2 enforces, 5 repeats, 2 explains. E.g. `shared/manifest.ts:1`,
   `nuxt.config.ts:45`, `docs/adr/0013-…:20`.
3. **Claim: a manifest is checked against a schema, so a mistake fails when the
   file is written, before any build.** Includes: a data collection needs a
   schema or a kind; a bad kind fails there too; manifests are type-checked by
   the gate. *Mechanic.* Home: `shared/manifest.ts` (`validateManifest`,
   `collectionDefSchema`); type check via `nuxt.config.ts`
   `typescript.tsConfig.include`. 6 refs: 3 enforces, 2 quotes, 1 explains.
   E.g. `shared/manifest.ts:164`, `docs/adr/0025-…:84`.
4. **CONFLICT — Question: does a generator write config files into the repo?**
   - Side A (a generator writes `content.config.ts` and
     `shared/routing.generated.ts`, as ADR-0002 said):
     `docs/adr/0007-…:19`, `docs/adr/0012-…:26` (explains); also the two
     midden noise entries; `CONTEXT.md:51` still says collections are
     "generated … at build time".
   - Side B (nothing is generated; collections are built when the config is
     loaded): `layers/atlas/tenant.config.ts:7`, `layers/marquee/tenant.config.ts:7`,
     `layers/midden/tenant.config.ts:9`, `layers/journal/tenant.config.ts:3`
     (repeats), `shared/manifest.ts:164` ("no separate generator or codegen
     step exists").
   The rewrite must say whether ADR-0002 still owns the generator (now
   superseded by ADR-0013/0014) or only the manifest decision. *Decision.*
   7 refs (excluding noise): 2 explains, 4 repeats, 1 quotes (+1 points
   leaning A).
5. **Claim: code, not people, turns each Tenant × Space × Collection
   combination into its own collection.** Nobody writes that list by hand.
   *Mechanic.* Home: `shared/expand.ts` (`expand()`). 4 refs: 2 enforces,
   1 explains, 1 points. E.g. `shared/expand.ts:1`, `CONTEXT.md:51`.
6. **Claim: one expansion feeds both the collections and the URL routing
   map.** *Mechanic.* Home: `shared/expand.ts`, `modules/routing.ts`. Mostly
   ADR-0014's mechanism, cited jointly as ADR-0002/0013/0014. 4 refs:
   1 enforces, 3 repeats. E.g. `shared/expand.ts:1`,
   `layers/midden/tenant.config.ts:9`.
7. **Claim: adding a Tenant only adds a folder** (`layers/<name>/` plus
   `pnpm install`); no shared config file is edited. *Decision.* 2 refs:
   1 quotes, 1 explains. E.g. `docs/adr/0018-…:17`, `docs/adr/0018-…:65`.
