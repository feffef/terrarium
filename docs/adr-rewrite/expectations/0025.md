## 3. By part of the Platform

**Code and tests** (43) need the ADR as the authority for one mechanism: the
`kind` opt-in on a manifest collection, minimum-contract merge, the derived
`#catalog`, and `queryAcrossTenants` as the only cross-Tenant read. Seven Tenant
manifests cite it on their `kind:` line only to say "opt in". The core files
(`shared/kinds.ts`, `shared/expand.ts`, `shared/manifest.ts`, `modules/catalog.ts`)
already hold the details; the ADR need only state the rules (C1–C4, C10) and
name these files. One comment quotes a "Consequences" section (C17).

**Agent docs and CLAUDE.md:** no references.

**Other ADRs** need two dated, linked facts: ADR-0004 (amended 2026-07-22) relies
on ADR-0025's Consequences explaining why three files are Human-only (C7);
ADR-0009 (amended 2026-07-22) relies on ADR-0025 having moved the session schema
to a shared `session` kind (C5). The interactive map cites ADR-0025 for Tenant
content directories, which it is not about.

**Glossaries:** root `CONTEXT.md` defines Collection kind, Catalog and Aggregator
and points to ADR-0025 "for the mechanism"; it states the isolation default
itself. It also claims only a governed set of Aggregators may read across, which
the Blog contradicts (C6). `layers/commons/CONTEXT.md` needs the ADR as the
"read-model decision" the Commons consumes, including the dollhouse (#631)
motivation.
