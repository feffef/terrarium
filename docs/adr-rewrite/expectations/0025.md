## Checklist

Most relied-on first. Counts are references by role; one reference can back
several items.

**C1. Claim — A collection is hidden from every cross-tenant reader unless its
tenant's manifest opts it in by naming a shared shape (`kind`). Hidden is the
default.** Decision. 15 refs: explains 7, enforces 5, repeats 2, points 1.
E.g. layers/atlas/tenant.config.ts:62, shared/expand.ts:191.

**C2. Claim — A tenant that opts in keeps its own private fields: the shared
shape is only a minimum set of fields, added to the collection's own schema.**
Decision. 10 refs: explains 4, enforces 4, points 1, repeats 1.
E.g. shared/kinds.ts:26, layers/blog/tenant.config.ts:69.

**C3. Claim — Code reads across tenants only through one shared read function
(`queryAcrossTenants`, and `queryPages` on top of it), never by importing
another tenant's manifest or a hard-coded list of tenants.** Decision. 9 refs:
explains 7, repeats 2. E.g. app/composables/catalog.ts:1,
layers/commons/app/components/commons/Search.vue:5.

**C4. Claim — The list of opted-in collections is built automatically at build
time from the tenant manifests, by the same step that builds routing; nobody
writes it by hand, so a new tenant shows up and a removed one drops out.**
Mechanic; home `modules/catalog.ts` (derivation in `shared/expand.ts`
`catalogFrom`). 7 refs: enforces 5, explains 1, points 1.
E.g. modules/catalog.ts:1, CONTEXT.md:229.

**C5. Question — Which code may read across tenants: only a few governed
"aggregator" views (the Commons tenant), or any tenant?** Decision.
**Conflict.** 6 refs: explains 3, points 2, repeats 1.
Side A: CONTEXT.md:238, "Normal Tenants never read across; only a small,
governed set of Aggregators may." Side B:
layers/blog/app/pages/t/blog/[space]/[...slug].vue:49, the Blog (an ordinary
tenant) reads Journal pages through `queryPages`, called "the one cross-Tenant
read the Blog makes" and sanctioned by ADR-0025. Also unclear: who decides
which views join the set.

**C6. Mechanic — How the manifest checks a `kind`: it must name a known shape;
the shape's collection type (page or data) must match the collection's; a data
collection needs its own schema, a `kind`, or both. `kind` is separate from
`type`.** Home `shared/manifest.ts`. 6 refs: enforces 4, explains 1, points 1.
E.g. shared/manifest.ts:104, tests/unit/expand.spec.ts:125.

**C7. Mechanic — Which shared shapes exist and what they hold: `page` (optional
publish time and one-line summary) and `session` (the whole session-log
shape).** Home `shared/kinds.ts`. 6 refs: enforces 3, explains 3.
E.g. shared/kinds.ts:64, layers/marquee/tenant.config.ts:26.

**C8. Mechanic — The session-log schema has one home and is the `session`
shape; the Journal's `sessions` collection uses it, and `scripts/log-session.ts`
checks new logs against it.** Home `shared/schemas/session.ts`. 6 refs:
explains 4, enforces 1, quotes 1. E.g. shared/schemas/session.ts:1,
docs/adr/0009-session-logs-commit-directly-to-main.md:11.

**C9. Claim — Cross-tenant reads see only content committed and built into
the app; nothing is fetched live.** Decision (base rule is ADR-0001's; callers
cite both). 6 refs: explains 5, enforces 1.
E.g. layers/commons/app/components/commons/Timeline.vue:6.

**C10. Question — Why must a person merge changes to `shared/kinds.ts`,
`modules/catalog.ts` and `app/composables/catalog.ts`?** Decision; the full
human-merge file list lives in `.claude/rules/adr-0004-human-merge.md`
(per ADR-0004:170). 5 refs: quotes 2, enforces 2, explains 1.
E.g. docs/adr/0004-objective-safety-gate.md:167, shared/kinds.ts:1.

**C11. Claim — Cross-tenant reading is read-only; nothing writes into another
tenant.** Decision. 5 refs: explains 2, enforces 1, points 1, repeats 1.
E.g. app/composables/catalog.ts:1, CONTEXT.md:229.

**C12. Claim — The shared read function stays generic; each aggregator decides
for itself how to turn rows into its view (what counts as a post, how a digest
is dated), as an ordinary edit to its own layer.** Decision. 4 refs: explains 3,
repeats 1. E.g. layers/commons/app/composables/timeline.ts:1.

**C13. Claim — An aggregator never lists itself (its own pages carry no
`kind`), and a new cross-tenant view becomes a new space in the Commons, not a
new tenant.** Decision. 4 refs: explains 2, enforces 1, points 1.
E.g. layers/commons/tenant.config.ts:22, layers/commons/tests/e2e/commons.spec.ts:2.

**C14. Question — Why have shared shapes and a shared read path at all?**
Callers' answers: one sanctioned way to look across every tenant, instead of the
"dollhouse" fork's hard-coded list and fake data; copying schemas drifts and
importing other tenants' internals couples them. Decision. 4 refs: explains 1,
enforces 2, points 1. E.g. layers/commons/CONTEXT.md:29, shared/kinds.ts:1.

**C15. Claim — Every cross-tenant result links to the item's real page
address; aggregators invent no URLs.** Decision; mechanic home
`shared/routing.ts` (`documentUrl`). 3 refs: explains 3.
E.g. shared/routing.ts:62, layers/commons/app/composables/timeline.ts:13.

**C16. Mechanic — The read function trims each row to the needed fields while
fetching (keeps large bodies out) and tags each row with its tenant, space and
collection; one type cast there is accepted, and typing results from the shape
name is out of scope.** Home `app/composables/catalog.ts`. 2 refs: quotes 1,
enforces 1. E.g. app/composables/catalog.ts:44, shared/expand.ts:175.

**C17. Mechanic — Timestamps are stored as UTC text ending in `Z`, not as
dates (a date column drops the time of day).** Home
`shared/schemas/timestamp.ts`. 1 ref: explains 1 (shared/schemas/timestamp.ts:1).
Unclear whether ADR-0025 decides this or only introduced the file.
