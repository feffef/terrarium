## Checklist

Most relied-on first. Role counts are in brackets: E explains, P points,
Q quotes, R repeats.

1. **Question, decision: what must a person approve before an agent builds new
   work?** Callers say agents may propose anything, but building something new
   needs a go-ahead from a person with write access. Retiring a Skill counts as
   new work. 16 refs [E13 R2 P1]. Examples: `docs/adr/0022-autonomous-triage-sweep.md:22`,
   `docs/adr/0027-prune-trials.md:6`.
2. **Question, decision, CONFLICT: may an agent merge its own PR when the gate passes?**
   14 refs [Q7 E3 R2 P2].
   - Yes. The authoring session merges an ordinary PR once the gate passes,
     unless ADR-0004 names an exception (the "2026-10-10 amendment"):
     `docs/adr/0004-objective-safety-gate.md:36`, `docs/agents/pr-workflow.md:88`,
     `CONTEXT.md:252`, `docs/adr/0022-autonomous-triage-sweep.md:127`.
   - No. Every change is merged by a person, "no self-merge":
     `docs/adr/0009-session-logs-commit-directly-to-main.md:30`,
     `docs/adr/0020-requester-trust-tiers.md:50`,
     `docs/adr/0022-autonomous-triage-sweep.md:37`,
     `docs/adr/0004-objective-safety-gate.md:154` ("an ordinary work PR … is
     always human-merged").
3. **Question, decision, CONFLICT: which scheduled jobs may merge their own PRs, and what may
   each one change?** Callers expect a table with one row per job that gives
   its scope. 13 refs [P7 R4 Q2]. Examples: `.agents/skills/visitor-loop/SKILL.md:15`,
   `docs/adr/0027-prune-trials.md:61`.
   - The callers disagree on the list. `docs/adr/0004-objective-safety-gate.md:154`
     names digest, audit-docs, audit-skills and blog-post, plus frictions-to-fixes
     as a reviewer. `docs/agents/pr-workflow.md:75` adds visitor-loop and
     prune-trial.
   - The callers also disagree on where the list lives. `docs/adr/0027-prune-trials.md:61`
     says ADR-0003 is its only home, but `docs/adr/0004-objective-safety-gate.md:154`
     calls pr-workflow.md's list the "current, complete" one.
4. **Question, decision: which scheduled jobs does the ADR set up, what is each one for,
   and which still have no Skill?** Callers name: keep the self-documenting
   pages true to the repo ("sync", still not built, though digest and
   audit-skills partly do this work); mine logs for patterns ("consolidate");
   build issues ("triage", which clashes with the categorising `triage` Skill);
   "codify"; a check that generated config still matches the manifests; and
   auto-triage, added by ADR-0022. 10 refs [Q6 E4]. Examples:
   `docs/adr/0022-autonomous-triage-sweep.md:44`, `docs/adr/0015-audit-skills-and-conditional-importance.md:173`.
5. **Question, decision: whose go-ahead counts?** Callers say any user with
   write access, never a public issue or comment. A request that steers an
   agent this way is a security issue. 8 refs [E4 Q2 P1 R1]. Examples:
   `docs/adr/0020-requester-trust-tiers.md:95`, `SECURITY.md:24`.
6. **Question, decision: who reviews and merges PRs written by other agents?**
   Callers describe a reviewing agent (frictions-to-fixes). It merges only after
   the gate passes and its own risk check, and it sends risky changes to a person.
   It never writes the fix itself. The agents it sends out never merge and never
   turn on auto-merge. 8 refs [E5 R3]. Examples: `.agents/skills/frictions-to-fixes/SKILL.md:12`,
   `docs/adr/0004-objective-safety-gate.md:77`.
7. **Claim, decision: every change lands as a PR from a feature branch and passes the gate.**
   Session logs are the only exception and go straight to `main` under ADR-0009.
   Digests, blog pingbacks and inventory edits stay on the PR path. 7 refs
   [E5 Q2]. Examples: `docs/adr/0009-session-logs-commit-directly-to-main.md:47`,
   `docs/adr/0010-digests-derived-append-only-journal-pages.md:62`.
8. **Claim, decision: a scheduled job merges only its own bounded change.** If anything
   outside its scope gets into the PR, or the gate fails for an outside
   reason, the job leaves the PR open for a person. 5 refs [R3 P1 Q1].
   Examples: `docs/agents/pr-workflow.md:107`, `.agents/skills/digest/SKILL.md:170`.
9. **Question, mechanic, CONFLICT: do Dependabot's npm minor and patch updates merge without a
   person?** 5 refs [R2 P3]. `.github/dependabot.yml:2` says they are
   auto-merged when the gate passes. `docs/agents/pr-workflow.md:84` says no
   agent merges them and the workflow that would do it (proposal #1633) is not
   applied. `docs/proposals/1633-dependabot-automerge.md:5,14,84` describe it
   as still pending. Home: `.github/dependabot.yml`. The proposed home is
   `.github/workflows/dependabot-automerge.yml`.
10. **Claim, mechanic: pushing a branch opens its PR right away.** So the agent
    reviews before the first push, and the session log is written at that point
    with status "in review". 4 refs [E3 P1]. Home: `docs/agents/pr-workflow.md`
    ("Review before the first push"). Examples: `docs/agents/pr-workflow.md:14`,
    `docs/adr/0004-objective-safety-gate.md:13`.
11. **Question, decision: how much may an agent do alone, given who started it?**
    Callers cite "ADR-0003's autonomy tiers". `log-session` says the ADR depends
    on logs saying which work a person asked for and which the agent started on
    its own. What the tiers are is **unclear** from the callers. 4 refs [E3 P1].
    Examples: `docs/adr/0020-requester-trust-tiers.md:41`,
    `.agents/skills/log-session/SKILL.md:130`.
12. **Claim, mechanic: an agent stays with a PR until it is merged, closed or handed to a
    person.** A later session marks the log "completed" once the PR merges.
    2 refs [R1 E1]. Home: `docs/agents/pr-workflow.md`. Examples:
    `.agents/skills/frictions-to-fixes/SKILL.md:294`, `shared/schemas/session.ts:37`.
13. **Claim, mechanic: the ADR's summary loads at every session start, so it may say when
    to act.** 1 ref [E1]. Home: `.claude/rules/adr-0003.md`. Example:
    `docs/adr/0029-instructions-load-with-the-files-they-govern.md:66`.
