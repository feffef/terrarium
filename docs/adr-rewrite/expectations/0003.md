## Checklist (most relied-on first)

### 1. Who may merge which chartered job's PR, and within what bounded scope? (the ledger)
Callers expect one ledger in ADR-0003: one row per chartered Skill/job, each the
single home of that job's merge remit and scope. A chartered run merges only
its own bounded diff, and a run whose diff goes out of scope leaves the PR for
a human.

### 2. Before an agent implements net-new work, what green-light does it need? (propose vs implement)
Claim: agents may propose anything, but implementing net-new work needs a
human's green-light before building. That human must be Trusted, and a Public
issue never counts. The `ready-for-agent` label is the green-light. Retiring a
Skill counts as net-new.

### 3. Which chartered jobs or remits exist?

realise and to still be deferred. They also expect a drift-check job and a

### 4. What is the reviewer-agent's role (frictions-to-fixes)?
Claim: a review-agent reviews and merges PRs that impl agents author. It never
authors them itself, and impl agents never merge or arm auto-merge. It merges
on a green gate plus its own risk judgement, and it escalates high-risk PRs to
a human even when the gate is green.
- Live code 0 · live docs 8
- `.agents/skills/frictions-to-fixes/SKILL.md:172` ("You review and merge; you never author (ADR-0003's row for this Skill)"); `docs/agents/pr-workflow.md:81`
- Others: frictions-to-fixes:12/253/265, ADR-0004:86/194/198.

### 5. When does an agent open the PR, and what does it owe the PR afterwards?
Claim: pushing opens the PR. The agent keeps working the PR until it is
merged or closed. A PR is finished at merge, not at push. Opening it is a
closure point for `close-session` (session status `in-review`). The ADR-0003
rule loads at session start, so it can say when to act.

## Flag 2: Conflicts

1. **Self-merge.** ADR-0009:30/47 ("no-self-merge rule") and ADR-0020:50 ("'no self-merge' rule … unchanged") contradict CONTEXT.md:252 ("agents merge their own"), ADR-0004:37, ADR-0022:127 and pr-workflow:91, where authoring sessions merge their own PRs on green.
2. **Dependabot.** `.github/dependabot.yml:2` and proposals/1633:14 say the ledger row auto-merges npm minor/patch PRs on green. pr-workflow:87 says an agent never merges them and the workflow (#1633) is not applied.
3. **Who merges after a green-light.** ADR-0022:37/90 ("lands a gated PR a human merges", "a human still gates the build at merge") contradicts ADR-0022:127 and pr-workflow:91 (self-merge on green).
4. **Is the review-agent future or present?** ADR-0004:198 calls it "mid-term" and frictions-to-fixes:12 says "foresaw", while frictions-to-fixes:265 and pr-workflow:81 treat it as current.
5. **Trust assumption.** ADR-0020:16 and public-readiness-review:44 say ADR-0003 assumes a single trusted human. ADR-0020:154 and CONTEXT.md:252 expect it to name a Trusted green-light.
6. **Remit model.** ADR-0022:44 expects a fixed enumerated set of chartered remits, while ADR-0015:173 treats `sync` as a remit realised by several Skills. ADR-0007:21/37 still expect a chartered drift-check job.
