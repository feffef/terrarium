## Summary by part of the Platform

**Code and tests.** Callers need ADR-0019 to be the live authority for two behaviours. First, an error dialog plus a manual reload for any failed content load. Second, a single automatic reload for the chunk-load class, with a fallback to the dialog. They also need it to record the reasons: a reload loop is worse than a modal, and the server DB render is what recovers. They cite two dated amendments by date (2026-07-16 no patch, 2026-08-04 chunk reload), so both must stay findable. Two Midden content files treat the ADR as historical and "superseded". That conflicts with the live code citations.

**Agent docs (research, diagrams).** These use ADR-0019 as the record of the client-DB failure history, including the dependency patch that was reverted. The overview map lists it with ADR-0028 as governing `ContentLoadErrorDialog.vue`.

**Other ADRs.** ADR-0028 relies on ADR-0019 for the root failure (#236) and owns the client-DB recovery that ADR-0028 keeps.

Skills, CLAUDE.md and glossaries have no references.
