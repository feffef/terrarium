## Checklist

Most relied-on first. Counts are references per role; one reference can back
more than one item.

1. **How does code tell an agent's comment from a human's?** (mechanic) It
   carries a deliberate mark: the header at the body's start, the old two-line
   footer, or the tool's own "Generated with Claude Code" line. A bare session
   link in prose does not count; no mark means a human wrote it. Home:
   `scripts/provenance-header.ts` (`hasAuthorshipMarker`), wrapped by
   `scripts/check-triage-drift.ts` (`isAiAuthored`). 18 refs: enforces 7,
   explains 9, repeats 1, quotes 1. E.g. `scripts/check-triage-drift.ts:111`,
   `.agents/skills/guest-intake/scripts/guest-intake-scan.ts:159`.
2. **Claim: every agent write to GitHub or git names the session that made it,
   with no exceptions** (issues, PRs, comments, reviews, commits, session-log
   commits, outside agents too). (decision) 12 refs: enforces 2, repeats 7,
   points 3. E.g. `scripts/log-session.ts:370`, `.agents/skills/guest-build/SKILL.md:107`.
3. **Claim: agents act on GitHub through the owner's own account, with no
   separate bot account, so the login and `author_association` cannot tell agent
   from owner. A separate bot account was set aside (issue #124).** (decision)
   10 refs: explains 8, repeats 1, quotes 1. E.g. `scripts/check-triage-drift.ts:13`,
   `docs/research/github-branch-protection-vs-autonomous-log-commits.md:97`.
4. **What exactly goes on a commit?** (mechanic) Two lines last:
   `Co-Authored-By: <Model> <noreply@anthropic.com>` and `Claude-Session: <url>`;
   the model name comes from a known list; the last `Claude-Session:` line is the
   commit's own. Home: `scripts/provenance-footer.ts`, `scripts/git-helpers.ts`
   (`SESSION_TRAILER`), `scripts/session-trace.ts` (`formatModelId`). 9 refs:
   enforces 8, explains 1. E.g. `scripts/provenance-footer.ts:133`,
   `tests/unit/provenance-footer.spec.ts:68`.
5. **What exactly goes on a GitHub body?** (mechanic) First line
   `🤖 [Model](<session url>)`, read only at the very start of the body so a
   quoted header elsewhere never counts. Home: `scripts/provenance-header.ts`.
   8 refs: enforces 3, explains 1, quotes 2, repeats 1, points 1. E.g.
   `scripts/provenance-header.ts:26`, `tests/unit/audit-skills.spec.ts:329`.
6. **Which write paths are checked, and by what?** (mechanic) The tool-call
   guard covers GitHub bodies and commits made through the GitHub API tools
   (`create_or_update_file`, `push_files`; merges are left out because
   `merge-pr.ts` sends no message); the git hook covers local commits;
   `log-session.ts` writes the trailer on its own commits. Home:
   `scripts/github-provenance-guard.ts` (`GITHUB_PROVENANCE_TOOLS`),
   `.githooks/commit-msg`, `scripts/log-session.ts`. 8 refs: enforces 4, quotes 3,
   repeats 1. E.g. `scripts/github-provenance-guard.ts:126`, `.githooks/commit-msg:2`.
7. **Claim: the mark must name this session, and an agent never types a session
   id from memory.** Ids come from `CLAUDE_CODE_REMOTE_SESSION_ID` or the
   transcript; a body copied from another session must get its header line
   replaced. (decision) 8 refs: enforces 5, quotes 1, explains 1, points 1. E.g.
   `scripts/github-provenance-guard.ts:242`, `docs/agents/github-integration.md:60`.
8. **What happens when the session can't be confirmed?** (decision) The guard
   blocks the write (fails closed); the remaining gap, where the hook command
   itself can't start, is accepted. 6 refs: quotes 5, enforces 1. E.g.
   `scripts/github-provenance-guard.ts:208`, `:385`.
9. **Why the header replaced a trailing footer on GitHub bodies, and does the
