# ADR-0004: Objective safety gate

Every PR passes the gate, a set of automated checks whose CI run decides
whether the PR may merge. A branch passes the gate locally and a code review
before its first push. Agents merge their own green PRs, except a few kinds a
person with write access must merge.

## Scope and limits

- **What the gate checks.** L0: manifests validate, the app builds, lint and
  typecheck pass. L1: every Document matches its Collection's schema. L2:
  every entry route renders with no console errors. L3: a query for one Tenant
  and Space never returns another's Documents.
- **Skipping the slow steps.** The gate skips tests, build and e2e only for a
  change that can't affect them. Any doubt runs everything. A change to a
  Skill's own files skips only build and e2e, so nothing they load may live
  there.
- **Before the first push.** `pnpm gate:scoped` passes and the `code-review`
  Skill reviews the branch. A later push of prose may rely on CI.
- **Who merges.** A person with write access merges a PR that adds a
  dependency, changes behaviour no test covers, decides which Tenant's data a
  request can reach, or changes a Human-only file. The same holds for a PR from
  a fork, the guest pipeline or someone without write access (ADR-0020,
  ADR-0023). The agent that wrote any other PR merges it once the gate is green.
- **Behaviour no test covers** means effects no layer can see: unasserted
  client-side behaviour, an unattended hook or script with no dry run, timing
  or ordering logic, or an outside effect such as a webhook.
- **Tenant data reach** excludes a Tenant page that reads only its own Space
  through `resolveSpaceRoute`.
- **Human-only files** are where a mistake could mix Tenants' data, weaken the
  gate or the merge rules, or change governance. The list lives only in the
  `paths` of `.claude/rules/adr-0004-human-merge.md`. Agents edit these files
  freely; only the merge waits.
- **Enforcement.** `scripts/merge-pr.ts` refuses listed files, forks and
  authors without write access. The other exceptions rest on the agent.

## Why

- Agents write nearly everything, including the checks on themselves.
  Automated checks make that safe enough, so here we do not keep things
  minimal.
- The gate judges what a PR produces, not who wrote it. It cannot see a new
  dependency, untested behaviour or a hostile request, hence the exceptions.
- A green gate shows the change works; a review shows it is the right change.

## Rejected alternatives

- **A person merges everything but content.** Every ordinary PR then waited on
  a person. The owner chose agent merges with named exceptions.
- **Listing Human-only files here.** Each copy went stale.
- **The build validates content.** Nuxt Content coerces bad frontmatter, so L1
  is its own step.

## When to revisit

- CI passes a skipped change the full gate would have failed.
