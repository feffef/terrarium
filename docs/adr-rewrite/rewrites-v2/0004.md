# ADR-0004: Objective safety gate

Every PR passes the Gate: layered, machine-checkable checks that run locally
and, with the final say, in CI, and that skip a costly step only when the
changeset provably cannot affect it. A branch passes `gate:scoped` and a code
review before its first push. Agents merge their own green PRs, but a Trusted
human merges one that adds a dependency, changes behaviour no test covers,
decides which Tenant's data a request can reach, comes from a Public author, a
fork or the guest pipeline, or changes a Human-only file.

## Scope and limits

- **The Gate.** Every PR passes it. CI's run decides whether a PR may merge.
  `gate:scoped` is the same bar run locally; the full `pnpm gate` is CI's to
  run.
- **Four layers.**
  - L0, build: every manifest validates and expands, the app builds, and lint,
    typecheck and the drift checks pass.
  - L1, content: every Document validates against its Collection's schema.
    `pnpm validate:content` does this; the build validates no content.
  - L2, smoke render: every (Tenant, Space) entry route returns 200 and
    hydrates in a real browser with no console errors.
  - L3, isolation: a query scoped to one Tenant and Space never returns another
    Tenant's or Space's Documents. Collection keys are unique and correctly
    scoped, checked both when manifests expand and when a request resolves.
- **Floor and Heavy.** The Heavy tier is skipped only when every changed path
  is Inert. Any doubt runs the Full gate: no usable diff base, a shallow
  checkout, a failed decision step, an empty changeset, or a push to `main`. CI
  and `gate:scoped` take the decision from the same classifier.
- **Skill files.** A changeset of Inert paths and Skill files (`.agents/skills/`,
  `.claude/workflows/`) skips build and e2e but still runs unit tests. This
  holds only while nothing the build or an e2e spec loads lives in those
  folders.
- **Before the first push.** `pnpm gate:scoped` passes and the `code-review`
  Skill reviews the branch, even when the Stop hook asks you to push.
  `docs/agents/pr-workflow.md` names the review's skips.
- **Later pushes.** A code change runs `gate:scoped` first. Prose or docs may
  rely on CI's gate.
- **CI red after a green `gate:scoped`.** Check for base drift, then log a
  `major` Friction.
- **Where tests live.** A test lives with the code it exercises: a Tenant's in
  `layers/<tenant>/tests/`, the Platform's in `tests/`, a Skill helper's beside
  its Skill.
- **One build for e2e.** L2 reuses the gate's build: an e2e spec never builds.
  Each Tenant has its own specs, and they run in parallel.
- **Who merges.** Agents merge their own PRs on a green gate (ADR-0003). A
  Trusted human (ADR-0020) merges a PR that:
  - adds a dependency;
  - changes behaviour no test covers;
  - decides which Tenant's data a request can reach;
  - comes from a Public author, a fork or the guest pipeline (ADR-0020,
    ADR-0023);
  - changes a Human-only file.
- **Behaviour no test covers.** Runtime behaviour no gate layer can vouch for.
  For example: new client-visible JS behaviour no test asserts; a hook, cron
  job or script meant to run unattended with no dry run or test harness; logic
  that depends on timing, ordering or concurrency that a unit test can't
  reliably exercise; and effects L0–L2 can't observe, such as an external side
  effect or a webhook delivery. A change with real test coverage does not
  qualify just because it touches unfamiliar code.
- **Which Tenant's data a request can reach.** A Tenant layer page that
  resolves through the shared `resolveSpaceRoute` and reads only its own
  Space's collections is presentation: it decides nothing about reach and
  merges normally.
- **The Human-only list.** It is the `paths` of
  `.claude/rules/adr-0004-human-merge.md` and lives nowhere else. It holds the
  files where a mistake could cross Tenants, weaken the Gate or the merge
  boundary, or change governance. `scripts/merge-pr.ts` reads it from
  `origin/main`, so a PR cannot shrink the list for itself, and refuses a PR
  that changes a listed path. An empty list fails closed.
- **Exceptions without a path.** `merge-pr.ts` also refuses fork and
  Public-authored PRs. A new dependency, untested behaviour and Tenant reach
  have no mechanical check: the authoring agent recognises them and leaves the
  merge to a human, even on a green gate.
- **Merge, not edit.** Agents author changes to Human-only files routinely;
  review at merge is the control.

## Why

- Agents write nearly everything, on a Platform that edits its own tooling.
  Automated checks are what make that autonomy tolerable, so this is the one
  place the Platform does not keep things minimal. A human and an agent need
  the same objective signals to trust a PR.
- The Gate asks machine-checkable questions about a PR's output, not the intent
  behind it, so it can be trusted without trusting the author. For the same
  reason it is blind to some risks: a new dependency, untested runtime
  behaviour or a hostile request can all pass a green gate, and a path cannot
  show them. Those exceptions stand beside the path list.
- A green gate shows the change builds and passes its tests; a review shows it
  is the right change, written to the repo's standards. Pushing opens the PR
  (ADR-0003), so both come first.
- A skip errs only toward running more. The Inert set holds paths no Heavy step
  reads. The build reads `.agents/skills/` only to list which folders hold a
  `SKILL.md`, which a non-`.md` file cannot change, and reads only
  `.claude/rules/` under `.claude/`; no e2e spec reads either folder.
- One list in the rule's `paths` does two jobs: it loads the warning when an
  agent touches a listed file and drives `merge-pr.ts`'s refusal.
- Homing tests with their code keeps clear which tests are a Tenant's and lets
  the suite grow with each Tenant. Every extra build would add the gate's
  slowest step again, so specs share one.

## Rejected alternatives

- **Listing the Human-only files in this ADR.** Two attempts each went stale
  the next time the list changed.
- **Classifying risk by path alone.** A path cannot show a new dependency,
  untested runtime behaviour or where a PR came from.
- **A low-risk tier (content only, or one Tenant's layer) as the only PRs that
  merge without a human.** In practice only a few chartered Skills ever merged
  on green, and every ordinary PR waited for a human. At the owner's direction
  agents now merge their own PRs, and this ADR names the exceptions
  (ADR-0003).
- **One e2e spec for every Tenant, to keep L2 to one build.** It assumed each
  spec builds the app. Once specs reuse the gate's build, a spec per Tenant
  costs no build and runs in parallel.
- **Relying on the build to validate content.** Nuxt Content coerces
  wrong-typed frontmatter and skips an unparseable file with a warning, so the
  build catches neither.

## When to revisit

- CI goes green on an Inert-classified PR that a Full gate would have caught.
  The classifier is wrong: tighten `isInert` or drop the skip.

## Consequences

- Strict Collection schemas do double duty: they are the content contract and
  the L1 check.
- The files that decide the Gate's steps and who merges (`scripts/gate.ts`,
  `scripts/merge-pr.ts`, the rule's `paths`) are themselves Human-only.
- `tests/unit/gate-scope.spec.ts` catches code outside a Skill importing from
  its folder, but not a new build-time file read. Keeping build inputs out of
  Skill folders stays review's job.
