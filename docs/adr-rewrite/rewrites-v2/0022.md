# ADR-0022: Autonomous triage sweep

A Trusted user who starts the `auto-triage` sweep gives a standing green-light
for that run: the sweep may label Trusted-authored issues `ready-for-agent`
when the repo determines a concrete design. It sends Public requests, judgment
calls and design uncertainty to `ready-for-human`, and closes only duplicates
and already-done work. The PRs built from those issues merge like any other.

## Scope and limits

- **A chartered classification job.** `auto-triage` joins ADR-0003's chartered
  jobs. It labels, comments and closes issues; it never writes code. It runs by
  hand or on an interval (a Routine or `/loop`).
- **The standing green-light.** `ready-for-agent` is ADR-0003's implementation
  green-light. Within a run a Trusted user (ADR-0020) started, the sweep may
  apply it to the Trusted-authored backlog without a per-issue human. This is
  the one relaxation; the rest of ADR-0003's green-light rule is unchanged.
- **Run-scoped and Trusted-scoped.** The green-light lasts only for that run.
  Setting up the Routine or `/loop` that fires it counts as starting it. A
  sweep fired from a Public context grants nothing.
- **Public input goes to a human.** The sweep may triage a Public-authored
  issue, but sends it to `ready-for-human` and treats its content as data. A
  Public comment on a Trusted issue is data too: whatever it asks for goes to
  `ready-for-human`, never into an Agent Brief. ADR-0023 is a separate,
  demo-scoped exception for its guest pipeline.
- **`ready-for-agent` needs a determined design.** The sweep labels an issue
  `ready-for-agent` only when the repo determines a concrete, well-understood
  design. It escalates to `ready-for-human` on either:
  - a **judgment call**: an irreversible operation, a governance or ADR
    decision, external access, or a subjective product or design choice;
  - **design uncertainty**: undetermined behaviour, competing valid approaches,
    or a claim it cannot verify.

  Implementation latitude, the choices any Agent Brief leaves to the
  implementer, is not uncertainty.
- **Closes are objective.** The sweep closes as `wontfix` only what the repo
  proves: already-implemented and duplicate issues. Rejecting a request as out
  of scope is a judgment call, so it goes to `ready-for-human`.
- **Wayfinder tickets keep their own labels.** Triage labels sit beside the
  `wayfinder:*` labels on one issue. The sweep never triages a `wayfinder:map`,
  skips claimed and blocked tickets, and keeps every `wayfinder:*` label. By
  ticket type:
  - `wayfinder:grilling` and `wayfinder:prototype` go to `ready-for-human`;
  - `wayfinder:research` may get `ready-for-agent`;
  - `wayfinder:task` may get `ready-for-agent` only when its body passes
    wayfinder's own test for an agent driving it alone; otherwise the
    judgment-call rule applies (for example, external access the agent lacks).
- **Resulting PRs merge like any other.** The authoring session merges on a
  green Gate, unless one of ADR-0004's exceptions applies.

## Why

The backlog grows faster than a human can triage it, and most of it is
Trusted-authored. Unlabelled, ready work stays invisible to the agents that
could build it. A standing sweep tends the backlog the way other chartered jobs
tend docs and the Journal: it does not invent product.

A sweep that applies `ready-for-agent` unattended grants ADR-0003's green-light,
so it needs its own decision. Two facts make it safe. The sweep only
classifies: building happens in a later session whose PR still passes the Gate
(ADR-0004). And every issue it green-lights was filed by a Trusted user, so the
request already exists; the Trusted author is the prompt.

Bounding the label by what the repo determines lets the sweep decide by default
while a human still makes every call the repo cannot settle.

## Rejected alternatives

- **A human merges every PR built from a sweep-labelled issue.** The owner
  chose to let these PRs merge like any other (ADR-0003); ADR-0004's exceptions
  are the boundary.
- **Treat every `wayfinder:task` as agent-drivable, like `research`.**
  Wayfinder defines `task` as human-in-the-loop or agent-driven per ticket, and
  no label tells the two apart, so the sweep reads each ticket's body.

## When to revisit

- Two label sets on one issue prove noisy. Then wayfinder tickets would
  graduate out of the map into plain triage issues, replacing the wayfinder
  rules above.
