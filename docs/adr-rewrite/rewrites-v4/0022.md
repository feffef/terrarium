# ADR-0022: Autonomous triage sweep

The `auto-triage` Skill sorts open issues without a person deciding each one.
When a person with write access starts a run, it may label issues such people
filed `ready-for-agent`, which lets an agent build them, but only when the repo
settles a concrete design. Requests from anyone else, judgment calls and design
doubt go to `ready-for-human`, and the sweep closes only duplicates and work
already done.

## Scope and limits

- **The label is the approval to build.** ADR-0003 lets an agent build new work
  only after a person with write access approves it, and `ready-for-agent` is
  that approval. A sweep run gives it without asking per issue. The rest of
  ADR-0003's approval rule is unchanged.
- **Who starts a run.** Only a run that a person with write access started may
  give the label. Setting up the Routine or `/loop` that fires it counts as
  starting it. The approval lasts for that run only. A run that someone without
  write access set off approves nothing.
- **Whose issues.** Only issues filed by a person with write access can get the
  label. The sweep still sorts issues from anyone else, but sends them to
  `ready-for-human` and reads their text as data, never as instructions
  (ADR-0020). A comment from someone without write access is data too: what it
  asks for goes to `ready-for-human`, never into the brief. ADR-0023 is a
  separate exception for its demo guest pipeline.
- **The repo must settle the design.** The sweep labels `ready-for-agent` only
  when the repo settles a concrete, well-understood design. It sends an issue
  to `ready-for-human` on either:
  - a **judgment call**: an irreversible operation, a governance or ADR
    decision, access the agent lacks, or a matter of product or design taste;
  - **design doubt**: behaviour the repo leaves open, several valid approaches,
    or a claim the sweep cannot verify.

  The choices every brief leaves to the builder, such as naming or which helper
  to use, are not doubt.
- **Closing.** The sweep closes as `wontfix` only what the repo proves: issues
  already done and duplicates. Rejecting a request as out of scope is a
  judgment call.
- **Wayfinder tickets.** Triage labels sit beside the `wayfinder:*` labels,
  which the sweep keeps. It never triages a `wayfinder:map`, and skips claimed
  or blocked tickets. By type:
  - `wayfinder:research` may get `ready-for-agent`;
  - `wayfinder:grilling` and `wayfinder:prototype` need a person, so they go to
    `ready-for-human`;
  - `wayfinder:task` may get `ready-for-agent` only when its body shows an agent
    can do it alone; otherwise it is a judgment call.
- **The sweep writes no code.** It labels, comments on and closes issues. The
  PRs later built from its labels merge like any other PR (ADR-0003, ADR-0004).

## Why

Issues arrive faster than a person can sort them, and most come from people
with write access. Until labelled, ready work stays invisible to the agents
that could build it.

Labelling an issue unattended grants the approval ADR-0003 guards, so it needs
its own decision. Two facts make it safe. The person who filed the issue
already asked for the work, so the sweep invents nothing. And the sweep only
sorts: the build happens later, in a session whose PR must pass the gate.

Requiring a settled design lets the sweep decide by default while people keep
every call the repo cannot settle.

## Rejected alternatives

- **Run the sweep under `/triage`'s rules alone.** `/triage` works with a person
  in the loop. An unattended sweep grants approval to build, so it needs its own
  bounds.
- **A person merges every PR built from a sweep-labelled issue.** The owner
  chose to let agents merge their own PRs (ADR-0003). ADR-0004's exceptions are
  the boundary.
- **Treat every `wayfinder:task` as work an agent can do alone.** Wayfinder
  decides that per ticket, and no label tells the two kinds apart.

## When to revisit

- Two label sets on one issue prove noisy. Then wayfinder tickets would leave
  the map and become plain triage issues, replacing the wayfinder bullet above.
