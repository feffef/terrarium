# ADR-0004: Objective safety gate

Every PR passes the gate: automated checks that run locally and in CI, where
the result decides whether the PR may merge. A branch passes the local gate and
a code review before its first push. Agents merge their own green PRs, except a
few kinds that a person with write access must merge.

## Scope and limits

- **CI's run counts.** Locally, `pnpm gate:scoped` runs the same checks before
  a push. The full `pnpm gate` is left to CI.
- **Four layers.** L0: every Tenant manifest validates, the app builds, and
  lint, typecheck and the drift checks pass. L1: every Document matches its
  Collection's schema. L2: every entry route of every Tenant and Space loads in
  a real browser with no console errors. L3: a query for one Tenant and Space
  never returns another's Documents. Its collection keys are unique and
  correctly scoped, checked when manifests expand and when a request resolves.
- **Skipping the slow steps.** When no changed file can affect them, the gate
  skips unit tests, build and e2e. A change to a Skill's own files skips only
  build and e2e, so nothing the build or an e2e spec loads may live in a
  Skill's folder. Any doubt about what changed runs everything. CI and
  `gate:scoped` take this decision from the same code.
- **Before the first push.** `gate:scoped` passes and the `code-review` Skill
  reviews the branch, even when the Stop hook asks you to push. A later push of
  prose or docs may rely on CI; a code change runs `gate:scoped` first.
- **CI fails after `gate:scoped` passed.** Check whether the base moved, then
  log a `major` Friction.
- **Tests.** A test lives beside the code it exercises. All e2e specs share the
  gate's one build; a spec never builds the app.
- **Who merges.** The agent that wrote a PR merges it once the gate is green
  (ADR-0003). A person with write access merges a PR that adds a dependency,
  changes behaviour no test covers, decides which Tenant's data a request can
  reach, changes a Human-only file, or comes from a fork, the guest pipeline or
  someone without write access. ADR-0020 and ADR-0023 own those last cases.
- **Behaviour no test covers.** Runtime behaviour no layer can vouch for: new
  client-side behaviour no test asserts; a hook, scheduled job or script that
  runs unattended with no dry run or test; logic that depends on timing or
  ordering; an effect outside the app, such as a webhook. Touching unfamiliar
  code with real test coverage does not count.
- **Which Tenant's data a request can reach.** A Tenant page that finds its
  Space through the shared `resolveSpaceRoute` and reads only that Space's
  collections is presentation. It merges normally.
- **Human-only files.** The list is the `paths` of
  `.claude/rules/adr-0004-human-merge.md` and lives nowhere else. It holds the
  files where a mistake could mix Tenants' data, weaken the gate or the merge
  rules, or change governance. Agents edit these files freely; only the merge
  waits for a person.
- **What is enforced.** `scripts/merge-pr.ts` reads the list from `origin/main`
  and refuses a PR that changes a listed file, or every PR if the list reads
  empty. It also refuses fork PRs and PRs from someone without write access.
  The other exceptions rely on the agent that wrote the PR, even on a green
  gate.

## Why

- Agents write nearly everything, including the tooling that checks them.
  Automated checks make that safe enough, so this is the one place we do not
  keep things minimal.
- The gate checks what a PR produces, not what its author meant, so it can be
  trusted without trusting the author. A new dependency, untested behaviour or
  a hostile request can still pass it, and no file path reveals them. Hence
  the exceptions beside the file list.
- A green gate shows the change works; a review shows it is the right change.
  Pushing opens the PR (ADR-0003), so both come first.
- A skip may only ever err toward running more.

## Rejected alternatives

- **Listing the Human-only files in this ADR.** Each copy went stale the next
  time the list changed.
- **A person merges every PR except content or one Tenant's layer.** In
  practice every ordinary PR waited for a person. The owner chose to let agents
  merge their own PRs, with named exceptions.
- **One e2e spec for all Tenants.** It assumed each spec builds the app; specs
  that share one build can be split per Tenant and run in parallel.
- **Letting the build validate content.** Nuxt Content coerces wrong-typed
  frontmatter and skips an unreadable file with a warning, so L1 is a separate
  step.

## When to revisit

- CI passes a PR the skip classified as safe that the full gate would have
  failed. Then tighten the classifier or drop the skip.
