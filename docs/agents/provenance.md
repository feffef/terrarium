# Provenance & identity

The single home for two rules that travel together — **never fabricate an
identifier**, and **every agent-authored artefact carries a full session URL**
(ADR-0017) — plus the map of which mechanical guard covers which surface.

**The requirement is the session URL, not a spelling.** Two different markers
carry it, on two different surfaces, and they are not interchangeable:

| Surface | Marker | Position |
| --- | --- | --- |
| GitHub bodies — issues, PR descriptions, comments, reviews | the **provenance header** | body's **first** line |
| Commits | the **two-line trailer** | message's last lines |

Moved out of `CLAUDE.md` so that file could stay an index (the same treatment
`pr-workflow.md` got in #448). This
doc is deliberately *not* split along a git/GitHub line: the same footer rule
spans local commits, GitHub posts, and commits made through the GitHub API, and
the coverage map below is only legible whole. Splitting it is what produced
#605 (the commit-trailer guard can't see GitHub surfaces) and its recurrence
#628 two days later.

ADR-0017 remains the single home for *scope* — what the footer covers and why
it is convention rather than gate-enforced. This doc holds the mechanics.

## The rules

- **Never predict or reconstruct an identifier — a line number, a blob SHA, an
  issue/PR number — from memory.** Always resolve it via a fresh tool call (a
  Read, `git rev-parse`/`git log -1 --format=%H`, or the actual `issue_write`
  response) at the moment you write it down. For a session id specifically,
  resolve it from the system-prompt commit-footer template / session context at
  the moment of writing — never construct one from a plausible-looking pattern.
  This rule alone has repeatedly failed to hold (issue #387).
- **Every agent-authored GitHub body opens with the provenance header** — a bot
  icon, the model name, linked to the session (ADR-0017's 2026-07-31 amendment;
  read the ADR for the full rationale and the no-exemptions scope):

  ```
  🤖 [Claude Opus 5](https://claude.ai/code/session_019hdkXjoebyR8etKVNyjn7S)
  ```

  It goes **first**, as its own paragraph. Resolve the model name and session URL
  from the harness's own commit-footer template in your system prompt — never
  reconstruct either from memory. Code home: `scripts/provenance-header.ts`.

- **Leave the harness's own footer alone.** The harness appends
  `_Generated by [Claude Code](…)_` to PR bodies and comments. Do not delete it,
  and do not try to make it match this convention. The header sits at the top
  precisely so the two never compete — which is why the old footer lost. Both
  markers satisfy the guard.

- **Commits keep the two-line trailer**, unchanged — the harness's own template
  emits it and `scripts/provenance-footer.ts` backstops it. A commit message
  renders no markdown, so the header does not apply there:

  ```
  Co-Authored-By: <model name> <noreply@anthropic.com>
  Claude-Session: <session URL>
  ```
- **GitHub strips bare `<...>` angle-bracket text in a rendered issue/PR body
  as HTML markup.** This has silently garbled both the footer's own
  `<noreply@anthropic.com>` and an unrelated placeholder written in prose
  (e.g. `<slug>`) — the text simply vanishes from the rendered body, with no
  error. Verify the rendered body after posting when angle brackets are
  involved, or avoid bare angle-bracket placeholder syntax in prose (issue
  #779).

## Guard coverage map

Four surfaces, three guards, one hole. Read the whole table before concluding
you are covered — every recorded failure here came from an agent who knew about
one row and assumed it generalized.

| Surface | Guard | What it does |
| --- | --- | --- |
| Local `git commit` | `.githooks/commit-msg` → `scripts/provenance-footer.ts` | Appends the footer when absent; **corrects it in place when present but mismatched** (issue #710). Installed via `core.hooksPath` in `postinstall`. Fail-open. |
| A commit trailer, after the fact | `scripts/session-id-guard.ts`, wired into the `Stop`-hook path (`scripts/session-end.ts`) | Compares every `Claude-Session:` trailer on this session's own commits against resolved ground truth and **records** a mismatch. Detection only — it does not prevent one. |
| Seven GitHub write tools | `scripts/github-provenance-guard.ts`, a `PreToolUse` hook | **Blocks** a call whose body carries **no** session URL (`missing`, issue #737) or one naming a **different** session (`mismatch`, issue #628), before the post. Format-agnostic: header, legacy footer, or the harness's footer all satisfy it. Registry: `GITHUB_PROVENANCE_TOOLS`; matcher in `.claude/settings.json`. |
| MCP-API commits — `create_or_update_file`, `push_files` | **none** | Neither hook fires. The commit-msg hook only sees a local `git commit`; the guard's registry deliberately excludes these (their `message` is a commit message, so it belongs to the trailer surface). Append the trailer by hand. |

One further gap worth holding in mind:

- The commit-msg hook can silently no-op if pnpm/tsx isn't on PATH. It usually
  works, so you should rarely need to amend by hand — but glance that a
  commit's footer actually landed rather than assuming it.

**A call with no body field at all is passed deliberately** — a label- or
state-only `issue_write` has nothing to stamp, and denying it would wedge the
triage sweep. Only a body that exists is policed.

## Remedies, which differ by surface

This asymmetry is the reason the two halves cannot be documented apart:

- **A commit** is fixable in place: `git commit --amend -F <file>` on the tip
  commit only. **Never** use `git commit-tree` or other history-rewriting
  techniques to inject a missing footer — see
  [`git-conventions.md`](./git-conventions.md) for why (it can silently
  re-parent the chain and drop intervening commits).
- **A GitHub post is not.** No edit-comment tool exists. The standing remedy
  for a bad footer caught after posting — a guard miss, or a post that wasn't
  tool-mediated — is to post a **visible follow-up correction comment**, never
  to try to rewrite the original.

## Backward compatibility

Nothing is backfilled (ADR-0017's "asymmetric history" consequence), so both
readers accept the legacy two-line footer on GitHub bodies. The two deprecations
have deliberately different lifetimes:

- **`isAiAuthored` (`check-triage-drift.ts`) keeps matching the legacy footer
  permanently.** Historical comments are immutable; drop it and every
  pre-amendment comment stops reading as agent-authored, which would make
  `guest-intake-scan.ts` re-answer threads it already answered.
- **The guard's legacy-trailer branch is temporary** — it exists only for an
  agent still writing the footer mid-transition. Scheduled for removal about a
  week after the amendment lands, tracked on **issue #784**, which also lists
  what must *not* be removed with it.

## Why this keeps recurring

The prose-only rule has now failed four recorded times (#387, #605, #628, and
the pattern #723 tracks), each time surviving a strengthening of the prose. The
guards above exist because prose alone did not hold. The 2026-07-31 amendment
adds a fifth data point of a different kind: the two misses in the window after
this doc landed (PRs #755, #782) were not agents forgetting the rule but agents
resolving a **conflict** with the harness's own footer instruction — which is
why the fix moved the marker rather than restating the rule. Two consequences
for how you read this doc:

- A guard that *detects* (row 2) is not a guard that *prevents*. Resolving the
  real identifier at write time is still the primary control.
- A surface with no guard (row 4) is not a surface with no rule.
