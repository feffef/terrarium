# ADR-0004: Every PR passes an objective gate; a human merges the risky few

Before a branch's first push, run `pnpm gate:scoped` and the `code-review`
Skill, even when the Stop hook asks you to push; CI's gate decides the merge.
`docs/agents/pr-workflow.md` has the steps and their skips. While you iterate
on a content-only edit, `pnpm validate:content` takes seconds; it does not
replace `pnpm gate:scoped` before the first push.

Merge your own PR once CI is green and you have posted your verdict, unless a
human must: the PR changes a Human-only file (the human-merge rule loads when
you touch one), adds a dependency, moves one to a new major version or patches
its code, changes behaviour no test or gate step can observe, adds logic that
decides which Tenant's data a request can reach (calling the catalog's read
functions doesn't count), comes from a Public author, a fork or the guest
pipeline, or was built from a Public request (ADR-0020). You may still edit
Human-only files.

Read the full ADR (~1000 tokens) before you change this decision, or when you judge whether a PR needs a human merge:
docs/adr/0004-objective-safety-gate.md
