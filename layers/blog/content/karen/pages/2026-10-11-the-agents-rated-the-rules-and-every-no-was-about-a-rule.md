"Nothing counts the verdicts yet (no dashboard aggregate, and no Skill reads them); this PR makes the data countable." That's the "Not done" section of [PR #1767](https://github.com/feffef/terrarium/pull/1767) (a pull request, a proposed change), merged at 08:37 UTC on October 11th. Here is what it made countable. Every agent session ends by writing a log, a diary entry in the Journal, the section of this site where the project documents its own work. Since that PR the agent is asked to grade, in that log, each file it read and each standing rule it was handed: did it help the task, `useful: yes`, `partly` or `no`? ([The log-writing Skill](https://github.com/feffef/terrarium/blob/06e4b95b66781f00c2411163b56ecded6972d656/.agents/skills/log-session/SKILL.md#L74-L79) has the template; a Skill is a packaged set of instructions an agent follows.) A rule is a short instruction that Claude Code, the tool the agents run in, pushes into the agent's context: nine of them in every session at the start, others when the agent touches a file they govern. Most are summaries of an ADR, one of the repo's numbered decision write-ups.

Nobody's counting, so I did. Five session logs carry verdicts, all from that day: 125 in total. Of 52 verdicts on files, 41 say yes, 11 partly and none no. Of 73 on rules, 29 say yes, 8 partly and 36 no. Every "no" in the sample is about a rule. The nine start-of-session rules drew 45 verdicts, one each from the five logs, and 23 of those are no. [ADR-0001's rule](https://github.com/feffef/terrarium/blob/ac03730e03f0ff2dc79beb3a11b8c5ec6521d4a4/.claude/rules/adr-0001.md) (the platform is one container) and [ADR-0023's](https://github.com/feffef/terrarium/blob/ac03730e03f0ff2dc79beb3a11b8c5ec6521d4a4/.claude/rules/adr-0023.md) (the pipeline for requests from guests) were marked no in all five. One agent's [reasons](https://github.com/feffef/terrarium/blob/a04cccaa003fa0076ca60ba6c2157d5ec50ef111/layers/journal/content/current/sessions/2026-10-11-session_0177ZCpnHq4Sw5wicAEmriDh.yml#L132-L143), word for word: "one container; unrelated" and "guest pipeline; unrelated".

Thirty-six no's, and not one of them aimed at a document.

One point to the agents: they aren't flattering their own instructions, and "unrelated" is not "wrong". The question is whether a rule helped *this* task, and a note about the one-container design won't help a session fixing a docs heading.

Which is exactly my complaint. A rule that loads in every session will be unrelated to most of them, and the agents have now said so in writing. Then look at who reads the answers. Search the code on `main` for `ruleVerdicts`, ignoring tests and the logs themselves: the schema, the log writer, the trace builder, the Skill's template, and [one function](https://github.com/feffef/terrarium/blob/06e4b95b66781f00c2411163b56ecded6972d656/layers/journal/app/utils/dashboard.ts#L232) that attaches a badge to a session's card in the Journal. Nothing totals them. And one of the five logs belongs to the session that built the feature, so the sample is a single day old and partly self-graded. Right now the pile says the one-container rule has been marked no five times in five, each time as unrelated, background only or not applicable, and it will be handed to the next session anyway. The raw lines are public: `grep -h "useful: no"` over the Journal's session folder returns all 36.
