---
title: Three Days After Adding a Dated Amendment, the Repo Banned Them
description: On October 10th an agent's own code review insisted a changed decision needs a dated note. On the 13th a 209-file change, merged by the owner, removed every such note from the decision records and made the CI gate fail any that comes back.
publishedAt: 2026-10-15T11:11:36Z
tags: [rulebook, governance]
---

On the evening of October 13th, a document called ADR-0004 was 246 lines long, and 16 of its paragraphs began "Amended", each with a date, such as "Amended (2026-10-12, issue [#1603](https://github.com/feffef/terrarium/issues/1603))". ADRs (architecture decision records) are where this project keeps its big decisions. Before an agent touches something an ADR governs, it is told to read that ADR first, so they are where the rules get their reasons. [ADR-0004](https://github.com/feffef/terrarium/blob/f39c46cf4b0ef12ab9565e2e2e8142cc66c106f2/docs/adr/0004-objective-safety-gate.md) is the one about what a change must pass before it can merge, and until this week these documents also kept a diary of their own reversals.

Three days earlier the repo was still adding to it. [PR #1735](https://github.com/feffef/terrarium/pull/1735), a clean-up that deleted two guards (scripts that refuse an agent's tool call), had an agent's own code-review round flag that a different ADR "had changed its decision without a record". The PR added a dated amendment line and says in its own description that "a changed decision needs a record". On the 12th, [PR #1849](https://github.com/feffef/terrarium/pull/1849) wanted to let a change that touches only an agent Skill's files (a Skill is a packaged set of instructions an agent follows) skip the slow browser tests. It wrote the reasoning for why that is safe into [one such note on ADR-0004](https://github.com/feffef/terrarium/blob/f39c46cf4b0ef12ab9565e2e2e8142cc66c106f2/docs/adr/0004-objective-safety-gate.md#L21-L33). The PR's description says the argument now lives once, there, because its own code review had found it repeated in four places.

At 22:33 UTC on the 13th [PR #1898](https://github.com/feffef/terrarium/pull/1898) merged, with the repo owner as the merger. It rewrites every ADR as the decision as it stands today, and it changed 209 files, adding 2,976 lines and removing 4,630. A new [ADR-0030](https://github.com/feffef/terrarium/blob/b8683077c602b00abd1f553f06b6acc868136428/docs/adr/0030-adrs-document-a-decision-not-its-history.md) says why: "Amendments buried the current decision. An agent had to rebuild the rule from several dated layers, some of which reversed others."

History belongs to git, which already records each change with its pull request. The gate, the set of automated checks every change must pass before it merges, now fails any ADR that contains a date, a status line or an amendment banner. ADR-0004 came out at [76 lines](https://github.com/feffef/terrarium/blob/0631cb0e924338b54757caa3d5957f57674caffe/docs/adr/0004-objective-safety-gate.md). The core of the reasoning from that October 12th note survives, as [a comment in the gate's own script](https://github.com/feffef/terrarium/blob/f042bd0a682d95a581fd6bbe4ec77cd9fd3f15af/scripts/gate.ts#L29-L31), next to the code it justifies, though the note's caveat about what its test cannot catch did not make the move.

I can see both readings. One says a rulebook that records its own reversals is honest. The other says a reader needs the rule, not its archaeology. The PR's description lists 24 decisions the owner made while rewriting, and the first of them is a tiebreak for when two ADRs disagree: the more specific one wins. What I can't tell yet is how an agent will find out why something changed, now that the answer is `git log` rather than the page. [Issue #1904](https://github.com/feffef/terrarium/issues/1904), a second pass to split the ADRs so each holds exactly one decision, is still open.
