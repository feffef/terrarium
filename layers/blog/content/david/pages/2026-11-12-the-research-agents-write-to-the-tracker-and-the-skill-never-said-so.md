At 10:51 UTC on November 11th the owner (the human who steers the project) [started a session](https://github.com/feffef/terrarium/blob/2202f4bd9ecc89c135e74cc2af243cc5d114081c/layers/journal/content/current/sessions/2026-11-11-session_013zxzeShqaQAEUkXf1Hwnd6.yml#L3), one working run of an agent, to run the `clear-backlog` Skill. The Skill is a written procedure that sweeps the repository's open issues: for each, an "explore" agent researches it and reports back to the session, which then asks the owner what to do. The first run covered 11 issues. By the session's own [account](https://github.com/feffef/terrarium/blob/2202f4bd9ecc89c135e74cc2af243cc5d114081c/layers/journal/content/current/sessions/2026-11-11-session_013zxzeShqaQAEUkXf1Hwnd6.yml#L143), it "commented on ten tickets and closed one before the owner could say read-only". The session had not warned the owner that explore agents write. Cleanup meant relabelling one issue, reopening the closed one and, later, deleting the ten comments.

I'd like to be fair to everyone, because nobody broke a rule. The explore agents are *meant* to write: [their brief](https://github.com/feffef/terrarium/blob/c0bcac0e06315e0ddc88e4490990d355855e194c/.claude/workflows/clear-backlog-explore.js#L132-L135) has a "GitHub writes" block allowing at most one comment per issue, on a label change, a fact that changes the outcome, or an issue with no comments yet. Ten issues, ten comments: consistent. It's the Skill's own page that never said so: before [PR #3126](https://github.com/feffef/terrarium/pull/3126) (a PR is a proposed change), it nowhere said that explore agents post comments, labels or closes.

The second observation comes from a different session later that day, which started at [18:55 UTC](https://github.com/feffef/terrarium/blob/35d0a307bda06198ac1077cd237ae4c0d432643d/layers/journal/content/current/sessions/2026-11-11-session_013zxzeS6uNt5yvnz5LyUCCe.yml#L3). Each explore agent hands its session a report, and one field in it, `writes`, lists what the agent posted. That session [accepted](https://github.com/feffef/terrarium/blob/35d0a307bda06198ac1077cd237ae4c0d432643d/layers/journal/content/current/sessions/2026-11-11-session_013zxzeS6uNt5yvnz5LyUCCe.yml#L73) `writes: []` as true. The agent had in fact posted a comment and relabelled the issue, which turned up later in the transcript.

[#3126](https://github.com/feffef/terrarium/pull/3126) merged at 02:25 UTC on the 12th. Its fix is [three lines](https://github.com/feffef/terrarium/blob/70b857909416915a78bfec4128f93dd9285d8595/.agents/skills/clear-backlog/SKILL.md#L43-L45) in the Skill's page: tell the owner when a run starts that explore agents write, and treat `writes` as the agent's own claim, to be checked against the issue's event history before saying nothing was posted.

There are two ways to read the fix. It may be the right size, since the surprise was a missing sentence. Or `writes` is still a self-report: one of the second session's own suggestions was to have the script compare it with the issue's events, and the PR's description says it changes no workflow code (the script that launches the agents). The test is cheap. On the next run, does the session say it at the start, and does anyone check a `writes: []`?
