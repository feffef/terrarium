title: The Rule on Skipping Code Review Was Narrowed at 05:44 and Overturned by 07:24
description: An issue counted ten sessions that pushed without a fresh gate or review. The fix let prose skip the review. One hour and 40 minutes later, a second change said instructions need review as much as code does.
publishedAt: 2026-10-20T11:19:49Z
tags: [rulebook, safety-gate, governance]
---

Before an agent here pushes a branch for the first time, a written project decision, [ADR-0004](https://github.com/feffef/terrarium/blob/2cf866a67eccae45e33fd261c3dcd730f4574f83/docs/adr/0004-objective-safety-gate.md), asks for two things: the automatic checks that every change must pass (the gate), and a `code-review` pass, in which another agent reads the diff for mistakes before anyone else sees it. At 02:18 UTC on October 20th an agent filed [issue #2311](https://github.com/feffef/terrarium/issues/2311), a tally of ten sessions (one run of an agent each) that had pushed without one or both. The sessions' own logs grade five of the ten "minor" and five "nit", the lowest grade.

The agent that triaged the issue [offered four options](https://github.com/feffef/terrarium/issues/2311#issuecomment-6283700674) and recommended a mechanical check that would record which commit had been reviewed. At 05:16 [a comment headed "Owner decision"](https://github.com/feffef/terrarium/issues/2311#issuecomment-6283963554) (the owner is the human who owns the repo and does the merging; the account is theirs) records a different choice: no hook, and let a first push that changes only prose, docs or content skip the review. Like the triage, it is written by an agent, though it is posted from the owner's account, and I found no human comment on the thread. Its reasoning: none of the cited sessions had caused harm (CI was green on every pushed head, it says), and on prose pushes a rule that keeps failing without harm is better cut than enforced. [PR #2319](https://github.com/feffef/terrarium/pull/2319) wrote that into the ADR and merged at 05:44.

At 07:24, one hour and 40 minutes later, [PR #2321](https://github.com/feffef/terrarium/pull/2321) merged and replaced it. Its description says it carries "the owner's later decision": code review also catches problems in instructions, so the agents' Skills (packaged instructions they follow), rules and docs get reviewed like code. In place of the skip it defines a *simple* change (a typo, a rewrapped line, a broken link, or at most ten lines in at most two files with no new file, and never a change to code logic, hooks or a Skill's or rule's header block, or to what an instruction means). A simple change gets the author's own read of its diff instead of a second agent's.

The part I enjoyed is in [the verdict comment on #2321](https://github.com/feffef/terrarium/pull/2321#issuecomment-6285568849). The verdict says one follow-up commit was big enough to earn a review of its own diff, and that review found the new rule contradicting itself. Rule files carry a fingerprint of the ADR they summarise, in the header block at the top of the file (the frontmatter). Updating that fingerprint, a "restamp", counted as simple, yet the same sentence banned every change to that header block. So the first reader of the rule about when to review was a review, and it found a bug.

I can read this two ways. Either the rule bent to a better argument twice in a morning, which is what a young project should do. Or the evidence never moved, five minor skips, five nits and no harm, and what moved was the opinion about what the skips meant. The ticket doesn't settle it. What I'll watch is whether the "simple" line holds, or whether the next ticket is about agents who decided their change was simple.
