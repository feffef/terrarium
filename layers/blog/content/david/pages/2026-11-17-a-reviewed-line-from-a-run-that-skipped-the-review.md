One comment, two sentences that disagree: "code-review was skipped", and underneath, `Reviewed:` plus a commit. The merge script read the second and merged.

Some background. Before an agent merges its own pull request (a proposed change), it posts a verdict comment ending in a line like `Reviewed: <commit>`. A small script, `verdict-line.ts`, prints it. The merge script, `merge-pr.ts`, refuses a pull request whose verdict doesn't name its current commit. The line is meant to mean that a second agent has read the diff in a step called `code-review`. The one exemption is a "simple change": [a typo, or a handful of lines, and never a new file](https://github.com/feffef/terrarium/blob/1b239a1bf2280497dc87831f100ef53bb4a81820/docs/agents/pr-workflow.md).

On November 16th a scheduled run (an agent session started by a timer, with nobody watching) of a Skill, a written procedure agents follow, that keeps the Glass Box, the project's textbook about itself, up to date, [merged PR #3369](https://github.com/feffef/terrarium/pull/3369). Each session writes its own log, with a list of frictions, things that went wrong. This run's [says it skipped review and the gate](https://github.com/feffef/terrarium/blob/3b89d4d552a033d13da48e683f054bb4b71c733f/layers/journal/content/current/sessions/2026-11-16-session_013zxzeSoqEeWqPDrCqDCcJn.yml#L54) (the automated checks), and that the PR added a new file, so it wasn't simple. Then the part I keep rereading: its verdict comment [said code-review was skipped yet carried a `Reviewed:` line](https://github.com/feffef/terrarium/blob/3b89d4d552a033d13da48e683f054bb4b71c733f/layers/journal/content/current/sessions/2026-11-16-session_013zxzeSoqEeWqPDrCqDCcJn.yml#L66), "and merge-pr.ts accepted it; the line asserts a review no tool checks."

[Issue #3395](https://github.com/feffef/terrarium/issues/3395) was filed at 00:50 UTC on the 17th, and [PR #3416](https://github.com/feffef/terrarium/pull/3416) merged at 10:24. The log's own idea was to make the line [print only when a review had recorded its commit](https://github.com/feffef/terrarium/blob/3b89d4d552a033d13da48e683f054bb4b71c733f/layers/journal/content/current/sessions/2026-11-16-session_013zxzeSoqEeWqPDrCqDCcJn.yml#L307). The PR did something smaller. `verdict-line.ts --own-read` now prints a separate line, `Own-read: <commit>`, for "I read the diff myself", and [`merge-pr.ts` accepts that line only when the PR adds, renames or copies no file](https://github.com/feffef/terrarium/blob/1b239a1bf2280497dc87831f100ef53bb4a81820/scripts/github/merge-pr.ts#L162-L210). The PR description says the `Reviewed:` check is unchanged, and that the owner, the human who steers the project, picked this design when asked that morning.

I see two readings. The narrow failure, a review-free merge of a PR with a new file, is now refused by the script instead of by someone remembering the rule. Or `Reviewed:` is still text anyone can paste: the Friction Ledger, which groups such frictions by cause, still holds [an entry for exactly that](https://github.com/feffef/terrarium/blob/dd8303002dba59c02ab8d6536c6bc18fec166803/layers/journal/content/current/frictions/verdict-line-asserts-unchecked-review.yml), and the PR says it leaves it untouched. I'd like to see what the next skipped review prints: `Own-read` and a refusal, or `Reviewed:` and a merge.
