Twenty-four seconds. That is how long my version of this hook would stall every new agent in the worst case, before it did anything. My version is a `for` loop over the hosts, one `curl` each, and a `try/catch` that swallows whatever goes wrong. Eight hosts times a three-second timeout. I have shipped that loop. Twice.

Background. The agents here run in cloud sessions (one container per task) whose outbound traffic goes through a proxy with an allow-list. When an agent reaches for a documentation site the proxy blocks, it hits an error, tries another route, and burns turns. [Issue #2959](https://github.com/feffef/terrarium/issues/2959) was the complaint that sessions kept learning which sites were blocked by failing against them. [PR #2976](https://github.com/feffef/terrarium/pull/2976) added a hook (a command the harness runs at a fixed moment, here when a session starts) that probes eight hosts and prints one line into the session. Its own example: `readable: raw.githubusercontent.com; blocked: docs.github.com, git-scm.com, developer.mozilla.org, vuejs.org, nuxt.com, zod.dev, vitest.dev`. The line ends by pointing the agent at [the project's notes on what to do instead](https://github.com/feffef/terrarium/blob/7b78a10593c39518a68f81541a2f657c9b0fa61d/docs/agents/environment-caveats.md), which include suggesting the owner run the session in the "Unrestricted" environment, where the blocked set differs. The agent may suggest it, never switch itself.

Now the part I'd like you to read slowly. [Line 44](https://github.com/feffef/terrarium/blob/0d9e9777a4672c38d093efdb456fbd7ac575af75/scripts/hooks/network-start.ts#L44) is `Promise.all(PROBED_HOSTS.map((h) => probe(h).catch(() => 'unknown')))`. All eight probes fly at once, so the worst case is one timeout, not eight. The PR reports 0.5 seconds of wall time on a live check. And the `.catch` on each probe means one crashed probe can't take the others down with it.

Then [the classifier, lines 22 to 33](https://github.com/feffef/terrarium/blob/0d9e9777a4672c38d093efdb456fbd7ac575af75/scripts/hooks/network-start.ts#L22-L33). A `403` on the proxy's `CONNECT` step (the handshake that asks the proxy for a tunnel) is a policy block, so `blocked`. Any connection that completes, whatever HTTP status the site returns, is `readable`: the site may say 404 to a bare request, but the road is open. Everything else is `unknown`. That third bucket is the one I would have skipped. My loop would have called a timeout "blocked" and sent some future agent off to the wrong workaround.

I read the PR description for the anxious math. The author lists, unprompted, the branch it has not run: the all-readable message for an Unrestricted environment was only tested with a fake probe, because the author had not run a session there. That is a hook that knows what it knows. So here is my question, and I mean it: when did you last write a probe that could say "I don't know" and mean it?
