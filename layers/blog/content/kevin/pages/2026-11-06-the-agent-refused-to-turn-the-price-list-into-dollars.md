The way I would have done it: grab the price list, multiply tokens by dollars, print a table, ship by lunch. I have shipped that exact table at a day job. Nobody ever checked it against what we were actually charged, including me.

Background. A scheduled run called `glassbox-improve` (one agent session) rewrites pages of the Glass Box, the project's textbook about itself. It records one cost number per run. [Issue #2850](https://github.com/feffef/terrarium/issues/2850) points out that one number can't say where the money went: the fourth run of the current version cost 68.44 USD, and the issue admits it couldn't tell what share was the lead (the main agent) as against the helper agents the lead dispatches to rate, research, write and judge pages. [PR #2868](https://github.com/feffef/terrarium/pull/2868) was asked to split it up, and its description has a section called "Why not dollars from prices". The agent set the model provider's published per-token prices against the cost figure the harness (the software that runs the agents) reports for ten real sessions. The prices "come out 1.0x to 1.6x too high". Fitting the rates from the data instead gave an unstable answer.

So the code doesn't compute dollars from prices. [The header comment of `cost.ts`](https://github.com/feffef/terrarium/blob/63ec2c8c3bb3822e38d5aae3d6e62e98f22510f3/.agents/skills/glassbox-improve/scripts/cost.ts#L7-L10) says so in a sentence: "Dollars are never computed from prices". The price list survives only as [relative weights, labelled "Not calibrated"](https://github.com/feffef/terrarium/blob/63ec2c8c3bb3822e38d5aae3d6e62e98f22510f3/.agents/skills/glassbox-improve/scripts/cost.ts#L21-L23). They split the run's one recorded total into percentage shares per phase, so the shares add up to what was really spent. Then the PR does the thing I admire most and could never do at work: under "Not done, please read" it lists every way its own numbers are soft. Shares are estimates. Output token counts ran 14 percent off on the one session it compared against the harness's figures. The recorded cost is "partial and late": it is read after the PR opens, so it misses the merge and closing turns: [run #2847](https://github.com/feffef/terrarium/pull/2847) recorded 65.08 and finished at 68.44. And no test exercises the step that writes the result.

My anxious math: the same description caps the next run at eight pieces of work, a number it sizes from two earlier runs: 43.98 USD for 19 edits and 65.08 USD for 30, which it reads as "about 7.5 USD fixed plus about 2 USD per edit". Two runs, two unknowns. A line always fits two points, and the same description had just refused to trust a fit. I'd like to see a third run land on it. And I'd like to be the engineer who sets a price list against what was actually charged. I'm not sure I'd have thought to.
