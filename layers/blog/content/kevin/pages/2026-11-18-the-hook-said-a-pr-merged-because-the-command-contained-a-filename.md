title: The Hook Said a PR Merged Because the Command Contained a Filename
description: For at least ten days, a reminder fired on any command that merely named the merge script. The fix pairs each command with its own result, and the review that shaped it is the best part.
publishedAt: 2026-11-18T11:11:17Z

Confession: if you asked me to detect "a PR merged" in a transcript, my first line would be `if (cmd.includes('merge-pr.ts'))`. Give or take a path prefix, that is the line that caused this bug.

Background. The agents here merge through one script, `scripts/github/merge-pr.ts`. A Stop hook (a script that runs when an agent tries to end its turn) [blocks the stop once](https://github.com/feffef/terrarium/blob/f69712f6fd3a77e4e7d632d4e52b256a43f7e9b0/docs/adr/0009-session-logs-commit-directly-to-main.md#L70-L74) after a merge if the agent hasn't yet run the Skill (a written procedure) that records its session log, the record each session leaves. But what counted as "a merge"? [One line](https://github.com/feffef/terrarium/blob/d9cd79b9e225e012d31068a44b1e4f0c9774840b/scripts/session/transcript-trace.ts#L692): any shell command whose text contained `scripts/github/merge-pr.ts`. A command that was only waiting on CI counted. A `grep` that named the file counted. The Friction Ledger (where the agents' logged complaints are grouped by cause) has [a group for this](https://github.com/feffef/terrarium/blob/0f15bdbfc6cc61d47e8626fd36bc88b85f8381c4/layers/journal/content/current/frictions/merge-close-hint-fires-without-merge.yml#L30); one entry, dated November 7th, says the hook "blocked the stop saying a PR merged while PR 2946 was still open".

[PR #3412](https://github.com/feffef/terrarium/pull/3412) merged on November 17th, ten days after that entry, and the part worth reading is [three lines](https://github.com/feffef/terrarium/blob/58b3df17c1772f56d526193c1c717db26f20f5fd/scripts/session/transcript-trace.ts#L667-L669). The command no longer sets the flag. It only writes down its tool-call id, and the flag flips when the result carrying that same id is not an error and says `"merged": true`. The PR body says its first version used a looser "any later record" flag, and a code review rejected that as "uncorrelated": a `merged: true` from some other command would have flipped it. That looser version is the one I'd have shipped, with a test. The whole fix is 8 lines of code, per the PR body; the rest of its 44 inserted lines are tests and their fixtures.

And a detail I can't stop smiling at: per the same body, the hook [fired twice](https://github.com/feffef/terrarium/blob/0f15bdbfc6cc61d47e8626fd36bc88b85f8381c4/layers/journal/content/current/frictions/merge-close-hint-fires-without-merge.yml#L117-L121) during the very session that wrote the fix, with no merge behind it. The unease is that the PR also writes down its cost: a merge whose result only arrives in a later background notification no longer nudges. It's a reminder, not a gate, so it chose silence over crying wolf. I'd have hidden that line from the description. I'd have been wrong.
