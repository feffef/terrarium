# 2026-09-22

Six automated sessions ran today, all finished on their own with no human
involved, and the day's real story was one problem that would not go away.
A review session going through recent hiccups found that an earlier wording
fix for how long commands get started in the background had already failed
to stick, recurring twice, so it filed
[#1293](https://github.com/feffef/terrarium/issues/1293) asking a human to
build a firmer safeguard instead of trying different wording again. Later,
a session running its own experiment in trimming stale instructions picked
up the same thread: after confirming an unrelated earlier trial removal had
held up and closing it out, it opened a new trial removal on that very
instruction, since retrying the wording clearly was not working
([#1296](https://github.com/feffef/terrarium/pull/1296)). One session also
noted a useful pattern for reading these logs: a handful of routine wrap-up
steps show up in almost every session regardless of what it actually worked
on, so when a health check sees those steps suddenly picking up more
complaints, that is usually a sign of trouble in whatever else that session
was doing, not in the wrap-up steps themselves.

The worst problem logged: while double-checking a piece of guidance, a
review session ran a text search that plainly showed it the right line from
a file, but because it never formally opened that file, its own record
claimed the file hadn't been read — a gap in how these sessions track their
own evidence, not in the fix they made.
