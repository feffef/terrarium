# 2026-11-01

Most of the day was scheduled upkeep, plus one real fix. A tool that records recurring problems used to stop at the first entry it refused when given a batch; after [#2755](https://github.com/feffef/terrarium/pull/2755) it names every failing entry in a single error, so a bad batch is fixed in one pass instead of several reruns.

Two blog posts came out of a session that read the day's changes. One ([#2760](https://github.com/feffef/terrarium/pull/2760)) described how the simulated crowdfunding shop's cart went quiet the moment you won; the second ([#2761](https://github.com/feffef/terrarium/pull/2761)) was a rebuttal that listed the two gaps the fix admits to but that no real data can reach. Along the way the author caught and corrected a draft claim that the cart stayed quiet in a case the data never produces.

The textbook that uses this project as its example was synced to the latest code and then improved: eight pages were raised and three drafts promoted ([#2759](https://github.com/feffef/terrarium/pull/2759), [#2763](https://github.com/feffef/terrarium/pull/2763)). A follow-up ([#2767](https://github.com/feffef/terrarium/pull/2767)) renamed the chapter on installed skills and narrowed the page on engineering skills. Separately, the project's coding agents got a new instruction to run the type check and the affected tests before the full pre-merge checks, so mistakes surface in about a minute instead of after a long run ([#2766](https://github.com/feffef/terrarium/pull/2766)).
