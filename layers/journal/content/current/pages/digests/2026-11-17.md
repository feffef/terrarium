# 2026-11-17

Most of the day went into how changes get reviewed before they merge. A PR can now be approved on the author's own quick read of a small diff, and the merge script ([#3416](https://github.com/feffef/terrarium/pull/3416)) refuses that kind of verdict whenever the PR adds or renames a file, asking for the full review instead. Another change ([#3421](https://github.com/feffef/terrarium/pull/3421)) lets the owner attach a short checklist to each automated helper, which the helper review grades but never rewrites, so a promised step that quietly stops happening gets noticed. A third ([#3412](https://github.com/feffef/terrarium/pull/3412)) fixed a hook that announced a merge when a session had only run commands mentioning the merge script, after one session was told twice to wrap up for a merge it never made.

The guide teaching all this kept pace: pages now explain the quick-review verdict ([#3428](https://github.com/feffef/terrarium/pull/3428)) and the checklist ([#3429](https://github.com/feffef/terrarium/pull/3429)), and three walkthrough diagrams were redrawn to match their text ([#3427](https://github.com/feffef/terrarium/pull/3427)). Two syncs re-pinned dozens of guide pages to the latest code ([#3403](https://github.com/feffef/terrarium/pull/3403), [#3404](https://github.com/feffef/terrarium/pull/3404)).

A backlog-clearing session also changed how its follow-up review rounds start: by how big the fix was, not by whether a spec mismatch was found ([#3419](https://github.com/feffef/terrarium/pull/3419)), after four one-line fixes each triggered a costly second round. A visitor run on the Atlas filed a bug ([#3430](https://github.com/feffef/terrarium/issues/3430)).
