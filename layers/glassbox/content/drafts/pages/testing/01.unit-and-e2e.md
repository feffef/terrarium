A test suite for several sites in one app has two questions to settle: which tests run fast enough for every change, and where each test lives so that the site it checks can be added or removed in one piece. Terrarium answers both with folder names.

Know Vitest and Nuxt's test utilities already? Skip to [In Terrarium](#in-terrarium).

## The concept

A unit test calls a function or module directly and checks what it returns. It needs no server and runs in milliseconds. An end-to-end test, *e2e* for short, builds the app, starts its server and drives a real browser through it, so it catches what only the running app shows, such as a page that throws while it loads. It is far slower, so a suite holds many unit tests and fewer e2e tests.

[Vitest](https://vitest.dev/) can run both. Its *projects* split one config into named parts, each with its own `include` globs and settings, and `vitest --project <name>` runs one of them. A filter on the command line, such as `vitest run tests/unit`, keeps only the test files whose path contains that text.

For e2e, Nuxt's `@nuxt/test-utils` gives a `setup()` call for each `describe` block. By default it builds the app and starts a server; its options can skip the build, launch a browser through Playwright, or point at a server already running.

Full reference: [Nuxt docs: Testing](https://nuxt.com/docs/4.x/getting-started/testing)

## In Terrarium

A test lives with the code it tests. Platform tests sit in :file[tests/]. A :term[Tenant]'s own tests sit in its layer, in `layers/<tenant>/tests/unit/` and `layers/<tenant>/tests/e2e/`, so its tests come and go with the Tenant's folder. :file[tests/README.md] sets out the rule. :file[vitest.config.ts] defines a `unit` and an `e2e` project, and their globs find every Tenant's folder without naming one:

::excerpt{path="vitest.config.ts" lines="41,46,52-54"}
```ts
          name: 'unit',
          // …
          include: ['tests/unit/**/*.spec.ts', 'layers/*/tests/unit/**/*.spec.ts', '.agents/skills/*/tests/unit/**/*.spec.ts'],
          // …
          name: 'e2e',
          include: ['tests/e2e/**/*.spec.ts', 'layers/*/tests/e2e/**/*.spec.ts'],
          globalSetup: ['tests/support/e2e-global-setup.ts'],
```
::

`pnpm test` in :file[package.json] runs `nuxt prepare`, then `vitest run tests/unit`. That filter is text in a path, so it also picks up the `tests/unit/` folders inside each layer and each Skill. `pnpm test:e2e` selects the e2e specs the same way.

The e2e tests share one build. :file[tests/support/e2e-global-setup.ts] runs once before them: it reuses the app in `.output` when that build is at least as new as every file git tracks or would add, and builds only when it isn't. Each spec then calls `setupL2()` from :file[tests/support/e2e.ts], which calls Nuxt's `setup()` with the build turned off, a Chromium browser, and its own copy of the content database, so specs running side by side don't share one file.

The Platform's spec, :file[tests/e2e/smoke.spec.ts], loads every Tenant and Space entry address in the browser and fails on a console error or a broken render. It reads that list from the manifests, so a new Space is covered without an edit. A Tenant's own e2e spec checks what only that Tenant has. Both kinds of test run in the :term[Gate]'s :term[Heavy] tier.

### Why it's built this way

Tests as part of the Gate: ADR-0004 (:file[docs/adr/0004-objective-safety-gate.md]).

Each Tenant in its own folder: ADR-0018 (:file[docs/adr/0018-tenant-layers-under-layers-directory.md]).

### What to watch for

- **Unit specs share one context.** The `unit` project turns Vitest's per-file isolation off for speed, so a spec that changes `process.env`, `PATH` or a global must put it back itself.
- **An e2e spec never builds.** Passing `build: true` to `setup()` would add a build per spec. To force a fresh build, set `E2E_FRESH_BUILD=1`.
- **Use Vitest's `expect`, not Playwright's matchers.** Assertions such as `toBeVisible` don't run here; :file[tests/README.md] shows `expect.poll` for a condition that settles over time.

## Try it in your project

Give each part of your app that could be removed on its own a `tests/` folder beside its code, and change your test config to find those folders by glob. Then delete one part's folder and check that no test config or script still names it.
