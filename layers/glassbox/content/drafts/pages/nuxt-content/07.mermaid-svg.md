A diagram written as text stays easy to change and to review in a diff. The usual cost is paid by every reader: the page downloads a diagramming library and draws the picture in the browser. Terrarium draws each diagram once, when someone writes it, and serves a plain SVG file.

Know Mermaid already? Skip to [In Terrarium](#in-terrarium).

## The concept

Mermaid turns a text definition, such as a flowchart's nodes and arrows, into a diagram. On a web page it usually runs in the browser: the library finds each definition and replaces it with an SVG. Your code can also call `mermaid.render(id, definition)`, which returns a promise of `{ svg }`: the SVG as a string, to place or save as you like.

To lay a diagram out, Mermaid measures the drawn width of each label in a real browser. So the result depends on the font that is loaded when it measures. The [usage docs](https://mermaid.js.org/config/usage.html) warn that a web font which hasn't loaded yet leaves labels out of bounds.

Colours and fonts come from a theme. Only the `base` theme can be customised, through `themeVariables` such as `primaryColor`, `lineColor`, `fontFamily` and `fontSize` ([theming docs](https://mermaid.js.org/config/theming.html)).

Full reference: [Mermaid docs: About Mermaid](https://mermaid.js.org/intro/)

## In Terrarium

A writer puts a `mermaid` code block in any :term[Tenant]'s Markdown, runs `pnpm render:mermaid`, and commits the SVG it writes to :file[app/assets/mermaid/]. The file is named after a hash of the diagram's source, `mermaidKey` in :file[app/utils/mermaid.ts]. The same source on two pages of one Tenant shares one file, and an edited diagram gets a new one. A diagram drawn in a Tenant's own font (below) adds that font to the hash; the default font adds nothing.

:file[scripts/gate/render-mermaid.ts] does the drawing. It opens Chromium, loads each Tenant's render font and waits until it is ready, then renders every diagram with the `base` theme. Each colour variable is first set to an unusual placeholder colour, then every placeholder in the SVG is rewritten to a CSS variable with a fallback:

::excerpt{path="app/utils/mermaid.ts" lines="16-24"}
```ts
export const DIAGRAM_TOKENS: Record<string, string> = {
  primaryColor: '--diagram-node-bg',
  primaryBorderColor: '--diagram-node-border',
  primaryTextColor: '--diagram-node-text',
  lineColor: '--diagram-line',
  edgeLabelBackground: '--diagram-edge-label-bg',
  clusterBkg: '--diagram-cluster-bg',
  clusterBorder: '--diagram-cluster-border',
}
```
::

So a committed SVG takes its colours from the page it sits on. The Journal points these variables at its own design tokens in :file[layers/journal/app/assets/theme.css], so its dark mode carries into its diagrams too.

A diagram is drawn in a font file the repo bundles, at a fixed size, and the page serves that same font under the same family name. A Tenant gets the default font unless its layer has a `mermaid-font.ts`, as :file[layers/glassbox/mermaid-font.ts] does. This is the default:

::excerpt{path="app/utils/mermaid.ts" lines="54-60"}
```ts
export const MERMAID_RENDER_FONT: MermaidFont = {
  face: 'Gelasio',
  fontFamily: 'Gelasio, Georgia, serif',
  fontSize: '20px',
  weight: '400',
  woff2: 'app/assets/fonts/gelasio-latin-400-normal.woff2',
}
```
::

On the page, :file[app/components/content/ProsePre.vue] hands each `mermaid` block to :file[app/components/MermaidDiagram.vue]. It hashes the source the same way, bundles every committed SVG, inserts the matching one as HTML, and ships Gelasio, the default, with an `@font-face` rule. If no SVG matches, it shows the source as plain text. `mermaid` is a development dependency only, so readers never download it.

:file[scripts/gate/validate-mermaid-svgs.ts] is a step of the :term[Floor], the part of the :term[Gate] that always runs. It reads files only, with no browser. It fails when a diagram has no SVG, an SVG matches no diagram or is empty, or an SVG could run code, which :file[app/utils/svg.ts] checks.

### Why it's built this way

Mermaid diagrams drawn once and committed as SVG: ADR-0024 (:file[docs/adr/0024-build-time-mermaid-prerender.md]).

### What to watch for

- **The Gate checks that an SVG exists, not that it is current.** A new source has a new hash, so a forgotten render fails. But after a change to the font, the theme or Mermaid itself, every old SVG still passes. Run `pnpm render:mermaid` to redraw stale ones (`--check` lists them).
- **Only colours can be themed from CSS.** Setting a font variable in a Tenant's CSS changes nothing; a Tenant's font comes from its `mermaid-font.ts`. A new font means redrawing every diagram drawn in it.
- **A wider font on the reader's side can clip labels.** If the bundled font fails to load, the browser falls back to the next font in its stack, which may be wider than the font the boxes were measured in. The renderer lets each node's label spill into its padding to soften that.

## Try it in your project

Install [mermaid-cli](https://github.com/mermaid-js/mermaid-cli), which draws Mermaid files in a headless browser, and render one diagram to a file:

```bash
npx -p @mermaid-js/mermaid-cli mmdc -i diagram.mmd -o diagram.svg
```

Commit `diagram.svg` beside `diagram.mmd`, show the SVG on your page instead of loading Mermaid, and add a CI check that fails when an `.mmd` file has no SVG.
