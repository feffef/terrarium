A diagram written as text stays easy to change and to review in a diff. The usual cost is paid by every reader: the page downloads a diagramming library and draws the picture in the browser. Terrarium draws each diagram once per source and font, when someone writes it, and serves a plain SVG file.

Know Mermaid already? Skip to [In Terrarium](#in-terrarium).

## The concept

Mermaid turns a text definition, such as a flowchart's nodes and arrows, into a diagram. On a web page it usually runs in the browser: the library finds each definition and replaces it with an SVG. Your code can also call `mermaid.render(id, definition)`, which returns a promise of `{ svg }`: the SVG as a string, to place or save as you like.

To lay a diagram out, Mermaid measures the drawn width of each label in a real browser. So the result depends on the font that is loaded when it measures. The [usage docs](https://mermaid.js.org/config/usage.html) warn that a web font which hasn't loaded yet leaves labels out of bounds.

Colours and fonts come from a theme. Only the `base` theme can be customised, through `themeVariables` such as `primaryColor`, `lineColor`, `fontFamily` and `fontSize` ([theming docs](https://mermaid.js.org/config/theming.html)).

Full reference: [Mermaid docs: About Mermaid](https://mermaid.js.org/intro/)

## In Terrarium

A writer puts a `mermaid` code block in any :term[tenant]'s Markdown, runs `pnpm render:mermaid`, and commits the SVG it writes to :file[app/assets/mermaid/]. The file's name is a hash made by `mermaidKey` in :file[app/utils/mermaid.ts]. The hash covers the diagram's source and, when a tenant's own font (below) differs from the default, that font's family and size, but never its font file. The same source on two pages of one tenant shares one file, and an edited diagram gets a new one:

::excerpt{path="app/utils/mermaid.ts" lines="72-77"}
```ts
export function mermaidKey(code: string, font: MermaidFont = MERMAID_RENDER_FONT): string {
  const isDefault =
    font.fontFamily === MERMAID_RENDER_FONT.fontFamily && font.fontSize === MERMAID_RENDER_FONT.fontSize
  const s = (isDefault ? '' : `${font.fontFamily} ${font.fontSize}\n`) + normalizeMermaidSource(code)
  return `${fnv1a(s)}${fnv1a(reverse(s))}`
}
```
::

:file[scripts/gate/render-mermaid.ts] does the drawing; it is the only code that loads the `mermaid` package, a development dependency in :file[package.json]. It opens Chromium, loads each tenant's render font and waits until it is ready, then draws every diagram with `mermaid.render` and the `base` theme:

::excerpt{path="scripts/gate/render-mermaid.ts" lines="112-122"}
```ts
      mermaid.initialize({
        startOnLoad: false,
        theme: 'base',
        themeVariables,
        securityLevel: 'strict',
        look: 'classic',
        layout: 'dagre',
        flowchart: { wrappingWidth: 200, minNodeWidth: 0 },
        handDrawnSeed: 1,
      })
      const { svg } = await mermaid.render(id, code)
```
::

`themeVariables` comes from a function of the same name in that file, which sets each colour variable to its placeholder colour from the `SENTINELS` map there: an unusual hex value, different for each variable, that the next step searches the drawn SVG for. `DIAGRAM_TOKENS` names the CSS variable each one stands for:

::excerpt{path="app/utils/mermaid.ts" lines="16-24"}
```ts
export const DIAGRAM_TOKENS: Record<string, string> = {
  primaryColor: '--diagram-node-bg',
  primaryBorderColor: '--diagram-node-border',
  primaryTextColor: '--diagram-node-text',
  lineColor: '--diagram-line',
  edgeLabelBackground: '--diagram-edge-label-bg',
  clusterBkg: '--diagram-cluster-bg',
  clusterBorder: '--diagram-cluster-border',
}
```
::

`themeSvg` then rewrites every placeholder in the drawn SVG to its CSS variable, with a fallback colour:

::excerpt{path="scripts/gate/render-mermaid.ts" lines="48-57"}
```ts
export function themeSvg(svg: string): string {
  let out = svg
  for (const name of TOKEN_NAMES) {
    const sentinel = SENTINELS[name]!
    const cssVar = DIAGRAM_TOKENS[name]!
    const fallback = DIAGRAM_TOKEN_FALLBACKS[name]!
    out = out.replaceAll(sentinelPattern(sentinel), `var(${cssVar}, ${fallback})`)
  }
  return out
}
```
::

A committed SVG then takes its colours from the page it sits on. The Journal points these variables at its own design tokens in :file[layers/journal/app/assets/theme.css], and its dark mode carries into its diagrams too.

A diagram is drawn in a font file the repo bundles, at a fixed size, and the page serves that same font under the same family name. A tenant gets the default font unless its layer has a `mermaid-font.ts`, as :file[layers/glassbox/mermaid-font.ts] does. This is the default:

::excerpt{path="app/utils/mermaid.ts" lines="54-60"}
```ts
export const MERMAID_RENDER_FONT: MermaidFont = {
  face: 'Gelasio',
  fontFamily: 'Gelasio, Georgia, serif',
  fontSize: '20px',
  weight: '400',
  woff2: 'app/assets/fonts/gelasio-latin-400-normal.woff2',
}
```
::

On the page, :file[app/components/content/ProsePre.vue] hands each `mermaid` block to :file[app/components/MermaidDiagram.vue]. That component bundles every committed SVG and each layer's `mermaid-font.ts`. It reads the tenant from the page's path, `/t/<tenant>/…`, hashes the source with that tenant's font the same way, and looks up the matching SVG:

::excerpt{path="app/components/MermaidDiagram.vue" lines="37-40"}
```ts
const svg = computed(() => {
  const font = layerFonts[`../../layers/${route.path.split('/')[2]}/mermaid-font.ts`]
  return bakedSvgs[`../assets/mermaid/${mermaidKey(props.code, font)}.svg`]
})
```
::

The template inserts that SVG as HTML. MermaidDiagram.vue itself ships Gelasio, the default font, with an `@font-face` rule. A tenant with its own font serves the font file from its own CSS; the family and size the diagram is drawn in still come from its `mermaid-font.ts`. If no SVG matches, it shows the source as plain text.

The :term[floor] is the part of the :term[gate] that always runs, and :file[scripts/gate/validate-mermaid-svgs.ts] is one of its steps. It reads files only, with no browser. It fails when a diagram has no SVG, an SVG matches no diagram or is empty, or an SVG could run code, which :file[app/utils/svg.ts] checks.

### Why it's built this way

- **Draw once, serve a file.** Mermaid needs a real browser to draw, which production lacks, and drawing in each reader's browser makes every reader download it. Terrarium draws each diagram when it is written and commits the SVG. The cost: an author needs Chromium to redraw. ADR-0024 (:file[docs/adr/0024-build-time-mermaid-prerender.md])
- **Colours follow the page.** A drawn SVG would bake in one palette, so Terrarium rewrites its placeholder colours to the `--diagram-*` variables that [CSS custom properties](/t/glassbox/guide/web-standards/css-custom-properties) explains. The cost: a variable a tenant doesn't map falls back to a fixed light colour from `DIAGRAM_TOKEN_FALLBACKS` in :file[app/utils/mermaid.ts], which ignores the tenant's palette and dark mode. ADR-0024 (:file[docs/adr/0024-build-time-mermaid-prerender.md])
- **Measured font, shown font.** Mermaid sizes each box to its label as measured in the loaded font, so a different font on the reader's side breaks the fit. Terrarium draws in the same font file the page serves, at a fixed size. The cost: one font and size per tenant. ADR-0024 (:file[docs/adr/0024-build-time-mermaid-prerender.md])

### What to watch for

- **The gate checks that an SVG exists, not that it is current.** A new hash fails until it is drawn: a new source, or a tenant font with a new family or size. A change that keeps the hash, such as a new font file, the default font, the theme or a Mermaid upgrade, lets every old SVG pass. Run `pnpm render:mermaid` to redraw stale ones (`--check` lists them).
- **Only colours can be themed from CSS.** Setting a font variable in a tenant's CSS changes nothing; a tenant's font comes from its `mermaid-font.ts`. Any change to that font means redrawing every diagram drawn in it, whether or not the gate fails.
- **A wider font on the reader's side can clip labels.** If the bundled font fails to load, the browser falls back to the next font in its stack, which may be wider than the font the boxes were measured in. The renderer lets each node's label spill into the node's padding instead of being cut off at its measured width.

## Try it in your project

Install [mermaid-cli](https://github.com/mermaid-js/mermaid-cli), which draws Mermaid files in a headless browser, and render one diagram to a file:

```bash
npx -p @mermaid-js/mermaid-cli mmdc -i diagram.mmd -o diagram.svg
```

Commit `diagram.svg` beside `diagram.mmd`, show the SVG on your page instead of loading Mermaid, and add a CI check that fails when an `.mmd` file has no SVG.

Keep Mermaid in the browser when diagrams change while the site runs, such as ones your users write: no file drawn in advance can show them. Do the same when the people who edit diagrams can't run a headless browser, or when so few pages hold a diagram that loading Mermaid on those pages costs less than keeping SVGs in step.
