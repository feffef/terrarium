When agents write most of the changes, nobody can read every one closely. A gate is a fixed set of machine checks that every change must pass before it merges, so a change can be trusted without trusting whoever wrote it.

Know merge gates already? Skip to [In Terrarium](#in-terrarium).

## The concept

A merge gate runs the same checks on every change: the code lints, type-checks and builds, the tests pass, the content is valid. A change merges only when every check is green. Because each check asks a question a machine can answer, the gate's verdict means the same thing whoever opened the change, a person or an agent.

The same checks run in two places. The author runs them before pushing, to find a failure early, and CI runs them on the pull request, where the result decides the merge. A gate is only as good as what it checks: it can't see intent, so a clean build can still do harm when it runs.

Slow checks tempt you to skip them. A safe skip needs proof that the change can't affect the check, not a guess that it probably doesn't.

Full reference: [GitHub Docs: Status checks](https://docs.github.com/en/pull-requests/reference/status-checks)

## In Terrarium

Terrarium's :term[Gate] is `pnpm gate` in :file[package.json]. Its steps split into two tiers, which :file[scripts/gate/gate.ts] names:

::excerpt{path="scripts/gate/gate.ts" lines="17-27"}
```ts
export const FLOOR = ['verify:skills-lock', 'verify:mermaid', 'lint', 'typecheck', 'validate:content'] as const
export const HEAVY = ['test', 'build', 'test:e2e'] as const
// …
export function isInert(path: string): boolean {
  return (path.endsWith('.md') && !path.startsWith('layers/')) || path.startsWith('.claude/skills/')
}
```
::

The :term[Floor] is the quick checks, including the [type check](/t/glassbox/guide/verification/type-checking) and [content validation](/t/glassbox/guide/verification/content-validation), and always runs. The :term[Heavy] tier is the slow checks: [the unit tests](/t/glassbox/guide/verification/unit-and-e2e-tests), the build and the browser tests. `pnpm gate:scoped` diffs the branch against `main` and skips Heavy only when every changed path is :term[Inert]: a Markdown file outside `layers/`, or a link in `.claude/skills/`. The comments beside `isInert` give the reason for each.

A change of only Inert paths and Skill files (`.agents/skills/`, `.claude/workflows/`) skips just the build and the browser tests, and anything the script can't settle, such as a missing diff base, runs every step.

CI runs the same steps from :file[.github/actions/gate/action.yml], and its run is the one that decides. It doesn't copy the Inert rule into YAML; it asks `scripts/gate/gate.ts --decide` and guards the Heavy steps on the answer. If that step fails, Heavy runs anyway, so a broken shortcut costs time and never skips a check. :file[tests/unit/gate-parity.spec.ts] fails when `package.json`, `scripts/gate/gate.ts` and the action disagree on the steps.

Before a branch's first push, the author also reviews its diff and runs `pnpm gate:scoped` on the final commit ([Pull requests](/t/glassbox/guide/git-github/every-change-a-pr)).

A green Gate is not always enough to merge: some PRs wait for a :term[Trusted] person. An agent merges with :file[scripts/github/merge-pr.ts], which polls the PR's checks, merges on green, and first refuses the PRs it can recognise, such as one that changes a :term[Human-only] file. It reads that list, the `paths` of :file[.claude/rules/adr-0004-human-merge.md], from `main` ([Protected paths](/t/glassbox/guide/terrarium-practice/human-only-list)).

### Why it's built this way

- **Checks, not judgement.** Agents open too many PRs for a person to read, so machine checks decide the merge. Checks can't see intent, and a clean build can still do harm, so a fixed list of exceptions waits for a person: a list is checkable, where rating risk rests on judgement. The cost: some exceptions, such as untested behaviour, rest on the agent noticing them. ADR-0004 (:file[docs/adr/0004-objective-safety-gate.md]).
- **Skip only on proof.** Slow checks make docs-only edits wait, but skipping on a guess would weaken green. So the Gate skips them only for :term[Inert] paths, proven unread by any check; any doubt runs everything. The cost: over-caution, since a comment-only script edit forced full reruns, so Skill files got the narrower skip above.
- **One skip rule.** Two copies of the skip rule would drift apart unnoticed. So CI asks the script for its answer instead of restating it in YAML, and treats a failed answer as "don't skip": a broken shortcut costs time, never an unrun check. :file[.github/actions/gate/action.yml].
- **Steps in an action file.** Agents can't edit GitHub's workflow files, so a new check reached the local gate while its CI step waited for a person, and CI checked less. The steps now live in an action file agents can edit, and a test fails when the copies disagree. The cost: that test sees which steps run, not what each does. ADR-0026 (:file[docs/adr/0026-gate-workflow-thin-shell.md]).

### What to watch for

- **Green means the checks passed, not that the change is right.** A PR can pass it and still wait for a person; ADR-0004 lists when.
- **Inert is about the path, not the size of the change.** A rewrite of a whole doc outside `layers/` is Inert; a one-character change to a page under `layers/` is not, because the build renders it.
- **A pass covers the tree it started on.** If `HEAD` or the working tree changes while `pnpm gate:scoped` runs, it aborts before its next step, or warns after the last one; re-run it on the final tree.
- **Changing the Gate needs a person.** :file[scripts/gate/gate.ts], the action and the workflow file are on the :term[Human-only] list. A change to what the Gate checks waits for a person to merge it.

## Try it in your project

Write down the one command that decides whether a change may merge in your project, make CI run exactly that command, and run it yourself before every push. If you add a skip, make it fail closed: run every check unless you can prove a change can't reach it.
