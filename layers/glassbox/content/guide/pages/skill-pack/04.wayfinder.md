Some work is too big for one agent session, and the way to the goal can't be seen yet. The `wayfinder` Skill, installed from `mattpocock/skills`, charts that work as a map of open questions on the issue tracker and settles them one session at a time, until the way is clear enough to write a spec.

Know this Skill already? Skip to [In Terrarium](#in-terrarium).

## The concept

**`wayfinder`** is an installed :term[Skill]{id="skill"} for work too big for one session, where the way to the goal can't be seen yet. It works with these parts:

- **Map**: one issue that names the destination and indexes the decisions made so far.
- **Decision ticket**: each open question, a child issue of the map, typed by the work it needs, such as research or a grilling, as the Skill's *Ticket Types* section defines.
- **HITL and AFK**: a ticket worked with a person is HITL (human in the loop); one the agent can drive alone is AFK.
- **Blocking**: tickets block each other through the tracker's own dependency links.
- **Claim**: a session claims a ticket by assigning it, and resolves at most one ticket, research tickets excepted.
- **Frontier**: every open ticket that is unblocked and unclaimed.
- **Not yet specified**: the map's section where questions that can't be phrased sharply yet wait until resolved tickets clear the way.

Each type has its own Skill: a grilling ticket (HITL) runs `grilling` ([Planning Skills](/t/glassbox/guide/skill-pack/planning-with-the-pack)), a prototype ticket (HITL) builds throwaway code with :file[.agents/skills/prototype/SKILL.md], a research ticket (AFK) is resolved by a subagent running :file[.agents/skills/research/SKILL.md], and a task ticket, manual work a decision waits on, is either.

The map produces decisions, not deliverables: when the way is clear, it hands off to `to-spec`, which writes the decisions up as a spec. [Planning Skills](/t/glassbox/guide/skill-pack/planning-with-the-pack) has that route, and why `wayfinder` runs only when a person types it.

Full reference: [mattpocock/skills on GitHub](https://github.com/mattpocock/skills)

## In Terrarium

`wayfinder` is an installed Skill in :file[.agents/skills/wayfinder/SKILL.md], kept exactly as installed ([Installed Skills](/t/glassbox/guide/skill-pack/skill-packs)). It reads where issues live from :file[docs/agents/issue-tracker.md].

Its *Wayfinding operations* section maps the map onto GitHub. The map is an issue labelled `wayfinder:map`. Each ticket is a [sub-issue](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/adding-sub-issues) of it, labelled with its type. Blocking uses GitHub's native [issue dependencies](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/creating-issue-dependencies). A claim is an assignment, and a resolution is a comment, a close and one line added to the map's index.

Terrarium's `auto-triage` sweep, a pass a person starts that labels every issue needing attention, also triages wayfinder tickets, under wayfinder's rules for which tickets an agent may take:

::excerpt{path=".agents/skills/auto-triage/SKILL.md" lines="74-81"}
```md
- **Skip** a **claimed** (assigned) ticket and a **blocked** ticket (an open
  native dependency *or* a `Blocked by:` body line; `docs/agents/issue-tracker.md`'s
  Wayfinding operations): wayfinder's frontier is open + unblocked + unclaimed,
  so a blocked ticket is not takeable and must not be stamped `ready-for-agent`.
- **Preserve** every `wayfinder:*` label — this is an overlay, never a replacement.
- Honour the ticket type: `wayfinder:grilling` and `wayfinder:prototype` are
  **HITL** (human-in-the-loop) → `ready-for-human`; `wayfinder:research` is
  **AFK** and, when unblocked and unclaimed, is eligible for `ready-for-agent`.
```
::

### Why it's built this way

- **Triage labels beside wayfinder's.** `wayfinder` keeps triage labels off its tickets, which hold decisions, but an issue without `ready-for-agent` is invisible to building agents. So the sweep adds its label beside the `wayfinder:` one instead of moving the wayfinder backlog out of the map. The cost: two label sets on one issue; if that proves noisy, the ADR says to move them out. ADR-0022 (:file[docs/adr/0022-autonomous-triage-sweep.md]).
- **GitHub's own links first.** `wayfinder` wants the tracker's native dependencies, which show what's takeable in the tracker's own view without opening the map. Terrarium uses GitHub sub-issues and issue dependencies, with body lines only where those aren't available. The cost: the frontier query, and the sweep, must check both the native link and a `Blocked by:` line. :file[docs/agents/issue-tracker.md]

### What to watch for

- **A dependency link needs the issue's database id.** GitHub's endpoint takes the blocker's numeric id, not its `#number`. Write cross-references only once the issues exist: a placeholder `#n` links to whatever unrelated issue has that number.
- **Name a kept branch by the rules.** `wayfinder`'s research findings and the code `prototype` keeps each sit on a branch that gets no PR; name it as ADR-0003 (:file[docs/adr/0003-agent-operating-model-and-governance.md]) says.
- **Keep both label sets.** Never swap a ticket's `wayfinder:` label for a triage label: `wayfinder` reads a ticket's type from its label alone, never from its body.

## Try it in your project

Next time an idea is too big for one session, open one issue that names where it should end, and a child issue for each question you can already state sharply. Write the rest down as not yet specified, and settle one unblocked question per session.
