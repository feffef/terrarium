An agent that starts building before it knows what you want builds the wrong thing quickly. The planning Skills installed from `mattpocock/skills` slow that first step down: an interview settles the decisions, and the result is written to the issue tracker as a spec and tickets that a later session can pick up cold.

Know these Skills already? Skip to [In Terrarium](#in-terrarium).

## The concept

These installed :term[Skills]{id="skill"} split planning into steps that each do one job.

**`grilling`** is an interview. The agent maps the plan as a design tree, where each decision branches into the decisions that depend on it. It asks in rounds: each round holds every question whose prerequisites are already settled, numbered, each with the agent's recommended answer, worded so that "yes" accepts it. Facts are the agent's job, so it looks them up instead of asking; decisions are the person's. The interview ends when no open question is left, and the agent acts only once the person agrees they share an understanding.

**`to-spec`** writes the conversation up as a spec, without asking anything new apart from checking the test seams, the public boundaries where tests will see the feature's behaviour. Its template covers the problem, the solution, a long list of user stories, implementation and testing decisions, and what is out of scope, and it leaves out file paths and code because they go stale, unless a throwaway prototype produced a snippet that states a decision more precisely than prose.

**`to-tickets`** breaks a plan or spec into tracer-bullet tickets: thin slices that each cut through every layer and can be checked on their own, each listing the tickets that block it. It shows the breakdown to the person, revises it until they approve, then publishes blockers first. A wide refactor that no single slice can land green goes through expand, migrate and contract steps instead: add the new form beside the old, move the callers over in batches, then delete the old.

**`triage`** posts an Agent Brief on an issue it marks `ready-for-agent`; an issue marked `ready-for-human` gets the same structure plus why it can't be delegated. The brief is a comment that serves as the contract for an agent working alone; the issue's body and discussion are only context. It gives the current and desired behaviour, the types or interfaces involved, testable acceptance criteria and what is out of scope. It names no file paths or line numbers, because the issue may wait for weeks while the code moves, and it says what the system should do, not how to write it.

The guide installed with these Skills, :file[.agents/skills/ask-matt/SKILL.md], routes a build too big for one session through them: grill, then `to-spec`, then `to-tickets`, then build ticket by ticket. `grilling` can be reached for by the agent itself; `wayfinder`, `to-spec` and `to-tickets` set `disable-model-invocation: true`, so they run only when a person types them ([Claude Code docs: Skills](https://code.claude.com/docs/en/skills)). Both `to-spec` and `to-tickets` label what they publish `ready-for-agent`.

Work whose way can't be seen yet first goes through a `wayfinder` map, which joins that route at `to-spec` once it clears: [Wayfinder](/t/glassbox/guide/skill-pack/wayfinder).

Full reference: [mattpocock/skills on GitHub](https://github.com/mattpocock/skills)

## In Terrarium

These are installed Skills in :file[.agents/skills/], kept exactly as installed ([Installed Skills](/t/glassbox/guide/skill-pack/skill-packs)). They don't hard-code a tracker. Each expects to be told where issues live, and Terrarium tells them in :file[docs/agents/issue-tracker.md], a doc the installed setup Skill seeded and Terrarium now owns. The same doc says how a spec looks here:

::excerpt{path="docs/agents/issue-tracker.md" lines="55-66"}
```md
## Specs

A spec is an ordinary GitHub issue with no dedicated label. Precedent: #64 (the
Atlas spec).

- **Label**: none while it is on hold (below): not `needs-triage`, not
  `ready-for-agent`.
- **Sub-issues**: link each user story to the spec as a native GitHub
  sub-issue (`sub_issue_write` / `gh api` on the sub-issues endpoint, as for
  [Wayfinding's child tickets](#wayfinding-operations)), and also put
  `Part of #<spec>` at the top of the child's body, so the link reads even where
  native sub-issues aren't rendered.
```
::

The `auto-triage` sweep ([Issue triage labels](/t/glassbox/guide/git-github/work-queue)) posts a full brief on every issue it marks `ready-for-agent` and leaves choices such as naming, which helper to use and exact wording to the agent that builds it. Each of its subagents returns the files a fix would touch to the sweep, not in its brief. When two open `ready-for-agent` issues share a file, the sweep marks the higher-numbered one blocked by the other until that one closes :file[.agents/skills/auto-triage/SKILL.md].

`grilling` also runs inside other Skills. The installed `triage` Skill grills a vague request into shape, together with `domain-modeling`, which writes the settled terms into `GLOSSARY.md` and ADRs. Terrarium's own :file[.agents/skills/clear-backlog/SKILL.md] gathers every open question from a backlog run into one grilling with the owner, and leaves out every issue with a `wayfinder:*` label. How much each planning Skill matters here is graded in the :term[Skill Inventory].

### Why it's built this way

- **Stock Skills, our tracker doc.** The planning Skills name no tracker and expect to be told where issues live, so Terrarium maps them onto GitHub in a doc it owns and leaves the Skills as installed. Why the Skills are never edited and that doc is never re-synced: [Installed Skills](/t/glassbox/guide/skill-pack/skill-packs#why-its-built-this-way). ADR-0015 (:file[docs/adr/0015-audit-skills-and-conditional-importance.md]), ADR-0005 (:file[docs/adr/0005-skill-model.md]).
- **A brief names behaviour, not files.** An issue can wait while its files are renamed, and a path in the brief would then point at nothing. The installed rule keeps paths and line numbers out. The cost: the agent explores the codebase fresh, from the types and functions the brief names, and is given no file to open. :file[.agents/skills/triage/AGENT-BRIEF.md]

### What to watch for

- **Ignore their `ready-for-agent`.** `to-spec` and `to-tickets` say to apply it, but a Terrarium rule overrides them: [Issue triage labels](/t/glassbox/guide/git-github/work-queue#in-terrarium) has the rule and who may set the label.

## Try it in your project

Before your next change that would take more than an afternoon, ask your agent to grill you: one round of numbered questions, each with its recommended answer. Write the spec only after the last round leaves nothing open.
