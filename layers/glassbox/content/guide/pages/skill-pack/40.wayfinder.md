Some work is too big for one agent session, and the way to the goal can't be seen yet. The `wayfinder` skill, installed from `mattpocock/skills`, charts that work as a map of open questions on the issue tracker and settles them one session at a time, until the way is clear enough to write a spec.

Know this skill already? Skip to [In Terrarium](#in-terrarium).

## The concept

**`wayfinder`** is an installed :term[skill]{id="skill"} for work too big for one session, where the way to the goal can't be seen yet. It works with these parts:

- **Map**: one issue that names the destination, such as a spec to hand off or a decision to lock before planning starts, and indexes the decisions made so far.
- **Decision ticket**: each open question, a child issue of the map, whose answer is a decision rather than a piece of the build. Its type names the work it needs: research, prototype, grilling (an interview, named after the `grilling` skill it runs) or task.
- **HITL and AFK**: a ticket worked with a person is HITL (human in the loop); one the agent can drive alone is AFK.
- **Blocking**: tickets block each other through the tracker's own dependency links.
- **Claim**: a session claims a ticket by assigning it before any work, so other sessions running at the same time skip it. A session resolves at most one ticket, research tickets excepted.
- **Frontier**: every open ticket that is unblocked and unclaimed, the edge of what is known; a session takes its next ticket from there.
- **Not yet specified**: the map's section for its fog, the questions you can tell are coming but can't phrase sharply yet. They wait there until resolved tickets clear the way.

Each type has its own skill: a grilling ticket (HITL) runs `grilling` ([Planning skills](/t/glassbox/guide/skill-pack/planning-with-the-pack)), a prototype ticket (HITL) builds throwaway code with :file[.agents/skills/prototype/SKILL.md], a research ticket (AFK) is resolved by a subagent running :file[.agents/skills/research/SKILL.md], and a task ticket, manual work a decision waits on, may be HITL or AFK: AFK where the agent can do the work alone, HITL where it hands the person a checklist.

The map produces decisions, not deliverables: when the way is clear, it hands off to `to-spec`, another installed skill, which writes the decisions up as a spec. `wayfinder` sets `disable-model-invocation: true`, so the agent never starts it on its own and it runs only when a person types it. [Planning skills](/t/glassbox/guide/skill-pack/planning-with-the-pack) has that route and that setting.

The idea works without the skill: keep one record of where the work should end, settle the questions you can already state sharply one at a time, and leave the rest written down but unspecified until earlier answers sharpen them. It is the wrong tool when the way is already clear. If a first broad pass finds no fog and the whole job fits one session, the skill says you don't need a map. `ask-matt`, an installed skill that says which skill fits a situation (:file[.agents/skills/ask-matt/SKILL.md]), saves `wayfinder` for huge, foggy efforts, never a well-scoped feature.

Full reference: [mattpocock/skills on GitHub](https://github.com/mattpocock/skills)

## In Terrarium

`wayfinder` is an installed skill in :file[.agents/skills/wayfinder/SKILL.md], kept exactly as installed ([Installed skills](/t/glassbox/guide/skill-pack/skill-packs)). It reads where issues live from :file[docs/agents/issue-tracker.md].

That doc's *Wayfinding operations* section maps the map, a ticket (a GitHub [sub-issue](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/adding-sub-issues)), a claim and a resolution onto GitHub. In the lines below, the map's *Fog* section is the one the skill calls Not yet specified. The driving dev is the GitHub account that claims a ticket, with `--add-assignee @me`. A context pointer is the line a resolved ticket adds to the map: its link and a gist, a one-line summary of its answer.

::excerpt{path="docs/agents/issue-tracker.md" lines="107-108,112-113"}
```md
- **Map**: an issue labelled `wayfinder:map` with a Notes / Decisions-so-far / Fog body. `gh issue create --label wayfinder:map`.
- **Child ticket**: an issue linked to the map as a GitHub sub-issue (`gh api` on the sub-issues endpoint). Where sub-issues aren't enabled, add it to a task list in the map body and put `Part of #<map>` at the top of the child body. Labels: `wayfinder:<type>` (`research`/`prototype`/`grilling`/`task`). Once claimed, it is assigned to the driving dev.
<!-- … -->
- **Claim**: `gh issue edit <n> --add-assignee @me`, the session's first write.
- **Resolve**: `gh issue comment <n> --body "<answer>"`, then `gh issue close <n>`, then append a context pointer (gist + link) to the map's Decisions-so-far.
```
::

A ticket that waits on another links to it with GitHub's native [issue dependencies](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/creating-issue-dependencies), or with a `Blocked by:` line at the top of its body where those aren't available.

Terrarium's `auto-triage` skill runs a *sweep*: one pass over every open issue that needs attention, which a trusted user (a person with write access to the repository) starts and which then labels issues without asking each time. It also triages wayfinder tickets, under wayfinder's rules for which tickets an agent may take. It skips a claimed ticket and one that waits on an open blocker, by native link or by `Blocked by:` line. On the rest, its labels go on top of the `wayfinder:` labels, an overlay, and follow the ticket type: `ready-for-human` means a person must act, `ready-for-agent` that an agent may build it.

::excerpt{path=".agents/skills/auto-triage/SKILL.md" lines="82-85"}
```md
- **Preserve** every `wayfinder:*` label — this is an overlay, never a replacement.
- Honour the ticket type: `wayfinder:grilling` and `wayfinder:prototype` are
  **HITL** (human-in-the-loop) → `ready-for-human`; `wayfinder:research` is
  **AFK** and, when unblocked and unclaimed, is eligible for `ready-for-agent`.
```
::

### Why it's built this way

- **Terrarium's sweep adds triage labels beside wayfinder's.** The installed `wayfinder` gives its tickets only `wayfinder:` labels, since they hold decisions, not build work. Terrarium's sweep adds its own beside them: `ready-for-human` (a person must act) on grilling and prototype tickets, `ready-for-agent` (an agent may build it) on unblocked, unclaimed research ones, rather than moving wayfinder tickets out of the map. The cost: two label sets on one issue. ADR-0022 (:file[docs/adr/0022-autonomous-triage-sweep.md]).
- **GitHub's own links first.** `wayfinder` wants the tracker's native dependencies, which show the tickets a session can take in the tracker's own view, without opening the map. Terrarium uses GitHub sub-issues and issue dependencies, with body lines only where those aren't available. The cost: the frontier query, and the sweep, must check both the native link and a `Blocked by:` line. :file[docs/agents/issue-tracker.md]

### What to watch for

- **A dependency link needs the issue's database id.** GitHub's endpoint takes the blocker's numeric id, which `gh api repos/<owner>/<repo>/issues/<n> --jq .id` prints, not its `#number`. Create the issues first and write cross-references after: a placeholder `#n` links to whatever unrelated issue has that number.
- **Start a kept branch's name with `research/` or `prototype/`.** `wayfinder`'s research findings and the code `prototype` keeps each sit on a pushed branch named with one of these prefixes; ADR-0003 (:file[docs/adr/0003-agent-operating-model-and-governance.md]) says such a branch gets no PR and is never merged.
- **Keep both label sets.** Never swap a ticket's `wayfinder:` label for a triage label: `wayfinder` reads a ticket's type from its label alone, never from its body.

## Try it in your project

Next time an idea is too big for one session, open one issue that names where it should end, and a child issue for each question you can already state sharply. Write the rest down as not yet specified, and settle one unblocked question per session.
