Some rules about content must hold on every page, every day: a link into the code shows the code the author saw. A rule that only lives in a writing guide holds until someone forgets it. Written as a test, it holds on every change, and the test can say exactly which link broke it.

Know permanent links already? Skip to [In Terrarium](#in-terrarium).

## The concept

A link to a file on a branch, such as `…/blob/main/src/app.ts`, always shows the file as it is now. Months later the lines it pointed at have moved, or the file is gone. A permanent link names a commit instead of the branch, as in `…/blob/<commit-sha>/src/app.ts`, and shows that exact version for good. On GitHub, pressing `y` while viewing a file turns its address into one.

A rule like "links to code are permanent" is an *invariant*: something that must be true of all the content, all the time. You can check an invariant with a test like any other: read every content file, find what breaks the rule, and fail with a message that names it. Keep the test beside the content it guards, so the two move together.

Full reference: [GitHub Docs: Getting permanent links to files](https://docs.github.com/en/repositories/working-with-files/using-files/getting-permanent-links-to-files)

## In Terrarium

The Blog's writing Skill, :file[.agents/skills/blog-post/SKILL.md], asks every link to a file or a line to name a full commit SHA, never `main`. The Blog checks that with a unit test in its own layer, :file[layers/blog/tests/unit/blog-immutable-links.spec.ts]. It reads every Markdown file under the Blog's content and fails on any file link whose ref is not a commit SHA:

::excerpt{path="layers/blog/tests/unit/blog-immutable-links.spec.ts" lines="21-26"}
```ts
// Only file-serving GitHub routes take a ref that can be a branch; `commit`,
// `pull`, `issues`, `compare`, … don't, so they can't rot this way.
const FILE_ROUTE_LINK = /github\.com\/[^/]+\/[^/]+\/(?:blob|tree|raw|blame|edit)\/([^/\s)]+)\//g
// An immutable pin is a hex commit SHA (7–40 chars). Anything else — `main`, a
// feature-branch name, a tag — is mutable and rejected.
const SHA = /^[0-9a-f]{7,40}$/
```
::

A first check fails if the walk finds no content at all, so a moved folder can't make the test pass by checking nothing. A second rule in the same file fails on a GitHub link to another Blog post, which must use the post's own site address instead.

The test adds no step to the :term[Gate]. It sits in `tests/unit/`, so `pnpm test` runs it with every other unit test, and the rule belongs to the :term[Tenant] whose content it checks ([Unit and e2e tests](/t/glassbox/guide/testing/unit-and-e2e)). Terrarium has turned down Gate steps that police documentation and metadata, such as a doc that uses a retired term: :file[.out-of-scope/ci-enforced-doc-invariants.md] records why, and prefers a guard that refuses the bad action when it is taken.

Glass Box, the site you are reading, works the same way. A unit test in its own layer checks every page against the code at the page's pinned commit, and fails on a hand-written link into the repo.

### Why it's built this way

The Gate runs only checks a machine can answer: ADR-0004 (:file[docs/adr/0004-objective-safety-gate.md]). Everything a Tenant owns, tests included, in its own folder: ADR-0018 (:file[docs/adr/0018-tenant-layers-under-layers-directory.md]).

### What to watch for

- **The test is looser than the Skill.** The Skill asks for a full 40-character SHA; the test accepts any hex run of 7 to 40 characters, so a short SHA passes.
- **A pinned link can still be wrong.** The test checks the shape of the ref, not that the commit exists or holds the quoted lines. The Skill has the author copy the SHA from git output for that reason.
- **Only file links are checked.** Commit, pull request and issue links name something that never changes, so the test skips them.

## Try it in your project

Pick one rule from your project's writing guide that a script could check. Write it as a test that reads every content file and fails with the offending text in its message, then break the rule once on purpose to see the message.
