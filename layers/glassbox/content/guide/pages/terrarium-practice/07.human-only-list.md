Some changes need a person to merge them, and a list of protected paths says which. If that list lives in the same repository as the changes it judges, a change can edit the list and let itself through. Terrarium reads the list from `main`, which an open pull request can't change.

Know protected-path lists already? Skip to [In Terrarium](#in-terrarium).

## The concept

A check that decides whether a change may merge reads some settings: which files are sensitive, who may approve them. If it reads them from the branch under review, the branch is judging itself. A pull request that removes a file from the sensitive list and changes that file at the same time passes, because the check sees the shortened list.

The fix is to read the settings from the branch the change merges into. That copy already went through review, and no open pull request can alter it. A change to the list itself then waits for review like any other, and takes effect only once it merges.

Two more habits keep such a check honest. It fails closed: if it can't read the list, it refuses rather than treating an empty list as "nothing is sensitive". And it counts every path the change touches, including the old path of a renamed file, so moving a file out of a protected folder still counts as touching it.

## In Terrarium

Terrarium calls its protected paths the :term[Human-only] list. It is the `paths` field of one file, :file[.claude/rules/adr-0004-human-merge.md]:

::excerpt{path=".claude/rules/adr-0004-human-merge.md" lines="3-4,17,22,25-26"}
```md
paths:
  - "content.config.ts"
  # …
  - ".claude/rules/**"
  # …
  - "scripts/github/merge-pr.ts"
  # …
---
# ADR-0004: Files that need a human merge
```
::

That file does two jobs. It is a [path-specific rule](/t/glassbox/guide/claude-code/path-scoped-rules), so when an agent reads or edits a listed file, Claude Code loads its text, which tells the agent that a person will merge the PR. And it is the list the merge script enforces. One list serves both, so the warning and the refusal can't disagree.

Agents merge their own PRs with :file[scripts/github/merge-pr.ts]. Before it waits for CI, it compares every file the PR touches, a rename's old path included, with the list as it stands on `main`:

::excerpt{path="scripts/github/merge-pr.ts" lines="410-417,502"}
```ts
function readHumanMergeGlobsFromMain(cwd: string): string[] {
  try {
    git(['fetch', 'origin', 'main'], cwd, { stdio: 'ignore' })
    return rulePaths(git(['show', `origin/main:${HUMAN_MERGE_RULE}`], cwd))
  } catch {
    return []
  }
}
// …
    const humanRefusal = humanMergeRefusal(prFilePaths(files), readHumanMergeGlobsFromMain(cwd))
```
::

The script fetches `main` first, then reads the rule with `git show`, so neither the branch's copy nor a stale local one counts. Any failure along the way returns an empty list, and `humanMergeRefusal` refuses the merge on an empty list. The globs are matched with Node's [`path.matchesGlob`](https://nodejs.org/api/path.html#pathmatchesglobpath-pattern). The rule file sits under `.claude/rules/`, which the list covers, so a PR that edits the list is itself merged by a person. :file[tests/unit/merge-pr.spec.ts] covers the refusals.

The same reading serves one more caller: :file[.agents/skills/clear-backlog/scripts/list-human-only-paths.ts] prints the Human-only paths a branch touches, also read from `origin/main` and also failing on an empty list, so a backlog run can say in its PR description that the PR waits for a person.

### Why it's built this way

- **Code enforces the line.** A person used to merge every PR, so risky files were named only in prose. Once agents merged on a green :term[Gate] ([Merge gate](/t/glassbox/guide/verification/gate) says why), code had to enforce that line. The cost: the list must also cover what keeps self-merging safe, such as the merge script, trust tiers, the Gate and the list's own file. ADR-0004 (:file[docs/adr/0004-objective-safety-gate.md]).
- **One list, one place.** :term[ADR] text repeated the list, and the copies went stale at each change. Now it exists once, as the `paths` of a :term[Rule], which Claude Code already reads to decide when to show that rule ([Path-specific rules](/t/glassbox/guide/claude-code/path-scoped-rules)). The cost: it is the one ADR summary rule that holds a fact of its own. ADR-0029 (:file[docs/adr/0029-instructions-load-with-the-files-they-govern.md]).
- **Old and new paths.** A security review found the gate checked only a renamed file's new path, so renaming a test into a docs folder skipped the tests. Now every file list feeding a decision counts both paths, and the merge script adds the old name GitHub reports. The cost: even a harmless rename out of a protected folder waits for a person. :file[docs/agents/git-conventions.md].
- **Code matches paths.** An agent reported no Human-only files for a branch that edited rules, so its PR description was wrong. Matching paths to patterns is a job for code, so a script works them out from the branch's changes and `main`'s list. The cost: it reads the local `origin/main` without fetching, so a stale clone can give an old answer. :file[.agents/skills/clear-backlog/scripts/list-human-only-paths.ts].

### What to watch for

- **A new entry protects nothing until it merges.** A PR that adds a path to the list is judged by `main`'s list, and so is every other open PR until it lands.
- **Only some reasons are enforced.** The script sees which files a PR touches, who opened it, from where, and its labels; other reasons a person merges, such as a change no test can observe, or a PR built from a Public request (an agent opens it as the owner, so it looks Trusted), are the agent's to notice ([Merge gate](/t/glassbox/guide/verification/gate)).
- **One kind of PR skips the list.** A same-repo Dependabot PR that changes only `package.json` and its lockfile, and moves each version within its major (a 0.x minor counts as a major), is checked by `dependabotBumpRefusal` instead; one from a fork, or with any other change, still goes to a person.
- **The refusal lives in the script.** It holds for merges that go through `merge-pr.ts`, the one merge path agents are told to use.

## Try it in your project

Find the check in your project that decides whether a change needs a second reviewer. Make it read its list from the target branch, not the change's own copy, make it refuse when the list can't be read, and put the list file on the list.
