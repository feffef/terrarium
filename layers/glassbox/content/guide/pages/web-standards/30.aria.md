A :term[screen reader] can't see a page. It reads what the browser tells it about each element: a button named "Notify me", pressed; a heading; an image called "Portrait of the inventor". Native HTML elements tell it most of that for free. ARIA adds attributes for what HTML alone can't say, such as a drawing's name or a message that just appeared. It changes only what assistive technology is told, never behaviour such as focus or keys.

Know ARIA already? Skip to [In Terrarium](#in-terrarium).

## The concept

WAI-ARIA, ARIA for short, is a W3C standard: a set of `role` values and `aria-*` attributes that the browser passes on to :term[assistive technology]. A role says what an element is (`button`, `img`, `status`), and attributes add its name (`aria-label`), its state (`aria-expanded`, `aria-pressed`, `aria-current`) or hide it (`aria-hidden="true"`).

The [first rule of ARIA use](https://w3c.github.io/using-aria/) is not to need it: if a native element or attribute already has the meaning and behaviour you want, use it. A `<button>`, `<details>` or `<dialog>` comes with its role, its states and its keyboard handling. ARIA only changes what assistive technology is told. A `<div role="button">` is announced as a button, but the browser gives it no focus and no Enter or Space key: you add `tabindex="0"` and the key handlers yourself. MDN quotes the saying "No ARIA is better than bad ARIA."

Three uses come up often:

- **Labels for graphics.** An inline SVG with `role="img"` and an `aria-label` is read as one image with that name, not as its many shapes. A purely decorative one gets `aria-hidden="true"`, which removes it from what assistive technology sees.
- **Live regions.** Text that changes without a page load is easy to miss without sight. An element with `role="status"` is announced politely, when the user is idle; `role="alert"` is announced at once and interrupts. A screen reader announces changes to a region that already exists, so an element inserted already holding its text may go unannounced, and the region is usually rendered empty first ([MDN: ARIA live regions](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Guides/Live_regions)).
- **State attributes.** `aria-expanded` on a disclosure, `aria-pressed` on a toggle and `aria-current` on the current link tell the listener what the eye sees from styling.

Mistakes fail silently. A misspelled role, a missing name or a stray `aria-hidden` raise no error.

Full reference: [MDN: ARIA](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA)

## In Terrarium

Native elements carry much of the work. The Platform's error dialog for a failed content load is a `<dialog>` opened with `showModal()`, named by its heading through `aria-labelledby`, with a `<details>` for the technical detail (:file[app/components/ContentLoadErrorDialog.vue]). Glass Box's sidebar folds each Subject into a `<details>` and marks the open Lesson's link with `aria-current="page"` (:file[layers/glassbox/app/components/glassbox/Sidebar.vue]), and the Journal's session cards fold their trace lists the same way.

The Journal's clickable row, which opens a session card or a digest row in place, is built by hand. Its head holds a heading and links, and it is a `<div>` given a button's role, focus and keys. `aria-controls` names the panel it opens. Of the [Vue event modifiers](https://vuejs.org/guide/essentials/event-handling.html#event-modifiers) on its key handlers, `.self` runs a key handler only when the event comes from the row itself, and `.prevent` cancels the browser's default action for the key:

::excerpt{path="layers/journal/app/components/journal/Disclosure.vue" lines="29-41"}
```vue
<template>
  <div
    role="button"
    tabindex="0"
    :aria-expanded="expanded"
    :aria-controls="controls"
    @click="emit('toggle')"
    @keydown.enter.self.prevent="emit('toggle')"
    @keydown.space.self.prevent="emit('toggle')"
  >
    <slot />
  </div>
</template>
```
::

Graphics get a name or are hidden. Tinkerfund's figure component switches on whether a caption was passed: with one the SVG is a labelled image, without one it is hidden.

::excerpt{path="layers/tinkerfund/app/components/tinkerfund/Figure.vue" lines="7"}
```vue
  <svg viewBox="0 0 400 300" :role="caption ? 'img' : undefined" :aria-label="caption" :aria-hidden="caption ? undefined : 'true'" v-html="svg" />
```
::

The large figure in a Campaign's gallery passes its caption. A thumbnail passes none: its button carries the label `Figure 2: …` and the drawing inside is hidden (:file[layers/tinkerfund/app/components/tinkerfund/campaign/FigureGallery.vue]). The Atlas's specimen plates and the Marquee's posters name their illustration the same way, and the Journal's Routine chart spells its data into the label: the Routine, the metric, the number of runs and the total (:file[layers/journal/app/components/content/RoutineChart.vue]). Small icons beside a text label carry `aria-hidden="true"`.

Changes are announced through live regions. Tinkerfund marks a refused action or a bad discount code with `role="alert"`, as in a Reward's card (:file[layers/tinkerfund/app/components/tinkerfund/campaign/RewardCard.vue]), and a result count or a confirmation with `role="status"`. A status with no visible text sits in a `.tf-sr` element, which :file[layers/tinkerfund/app/assets/theme.css] shrinks to one clipped pixel: it stays in the page for a screen reader and cannot be seen. The Deals banner announces "Code … copied" there while its button says only "Copied". An upcoming Campaign's reminder toggle shows both a state attribute and a status:

::excerpt{path="layers/tinkerfund/app/components/tinkerfund/campaign/Action.vue" lines="16-22"}
```vue
  <span v-else-if="state === 'upcoming'" class="notify">
    <button type="button" class="tf-btn" :aria-pressed="notify" @click="notify = !notify">
      <svg viewBox="0 0 24 24" aria-hidden="true"><path :d="notify ? 'M5 12.5l4.5 4.5L19 7.5' : 'M6 16V11a6 6 0 0 1 12 0v5l1.5 2h-15zM10 20.5h4'" /></svg>
      Notify me
    </button>
    <span class="said" :role="quiet ? undefined : 'status'">{{ notify ? 'We will tell you when it launches.' : '' }}</span>
  </span>
```
::

The status span is always rendered and starts empty; a click fills it. A second copy of the button on the same page passes `quiet` and drops the role.

The end-to-end tests read these attributes as the widget's state. They find elements with [Playwright's `getByRole`](https://playwright.dev/docs/locators), by role and name, and check `aria-pressed`, `aria-expanded` or `aria-current` where a user would see the state change:

::excerpt{path="layers/tinkerfund/tests/e2e/tinkerfund-flows.spec.ts" lines="217-222"}
```ts
      const notify = page.locator('.readout button[aria-pressed]')
      expect(await notify.getAttribute('aria-pressed')).toBe('false')
      await notify.click()
      expect(await notify.getAttribute('aria-pressed')).toBe('true')
      expect(await notify.textContent()).toContain('Notify me')
      expect(await page.locator('.readout [role="status"]').textContent()).toBe('We will tell you when it launches.')
```
::

The Journal's tests click a session card's heading and wait for `aria-expanded="true"` on its head, and press Enter on a link inside the head and expect the link, not the card, to open (:file[layers/journal/tests/e2e/journal.spec.ts]).

### Why it's built this way

- **One home for the hand-built row.** The session card and the digest row each wired their own `role="button"`, `tabindex`, `aria-expanded` and keys, identically. Terrarium moved that wiring into one component that renders only the interaction, and both callers pass their own markup and styling. :file[layers/journal/app/components/journal/Disclosure.vue]
- **Links in the row keep their own Enter.** A key handler on the whole row would catch Enter on a link inside it, cancel the navigation and toggle the card instead. The handlers take `.self`, and a test presses Enter on a link to prove it. :file[layers/journal/app/components/journal/Disclosure.vue]
- **One announcement, not two.** A page can show the reminder toggle twice, and two status regions would read the same message twice. The second copy passes `quiet`, which keeps its visible text and drops the role. :file[layers/tinkerfund/app/components/tinkerfund/campaign/Action.vue]
- **Wait for the state, not the panel.** A test's click once landed on a link in the card's head, navigated away and failed as a silent timeout. The test now clicks the heading, polls `aria-expanded`, which flips within a frame, and checks the page didn't leave. :file[layers/journal/tests/e2e/journal.spec.ts]

### What to watch for

- **Nothing checks ARIA for you.** No ADR, rule or doc sets an accessibility practice; Tinkerfund's glossary only asks for a high accessibility bar. :file[eslint.config.mjs] adds no accessibility lint rules, and neither the gate nor the tests run an automated checker such as axe. A wrong role, a missing label or a stray `aria-hidden` passes `pnpm gate:scoped`. The tests catch only the attributes they name.
- **Hidden means hidden for everything inside.** `aria-hidden="true"` hides an element's children too. Put it on an SVG with a link inside, or on a focusable element, and a keyboard user lands on something the screen reader can't name.
- **A live region added with its text may stay silent.** Render a `role="status"` element empty first, as Live regions above explains and the reminder toggle does. `role="alert"` is the exception: browsers generally announce it even when it appears with its message, as Tinkerfund's refusals do.
- **`alert` interrupts.** Keep it for refusals and errors. A count or a confirmation is a `status`.
- **Reach for the native element first.** A new disclosure is a `<details>`, a new modal a `<dialog>`. A `role="button"` you write yourself needs its focus, keys and tests written too, as the Journal's row shows.

## Try it in your project

Find a clickable `<div>` in your app and replace it with a `<button type="button">`; delete the `tabindex` and key handlers it no longer needs. Then add a live region for one action's result:

```vue
<button type="button" :aria-pressed="saved" @click="saved = !saved">Save</button>
<span role="status">{{ saved ? 'Saved to your list' : '' }}</span>
```

Turn on your system's screen reader (VoiceOver on macOS, Narrator on Windows), tab to the button and press Space: it reads the pressed state, then the message. In a Playwright test, `page.getByRole('status')` finds the message.
