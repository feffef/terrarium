Text is easy to read when it is much lighter or much darker than what lies behind it. WCAG, the web's accessibility guidelines, turns that into one number for any two colours, the contrast ratio, and sets the least that text and controls must reach. The number is plain arithmetic on the two colours, so a browser tool can measure it on a rendered page, and a test can check the pairs a stylesheet's colours are meant to form.

Know the 4.5:1 rule already? Skip to [In Terrarium](#in-terrarium).

## The concept

WCAG first gives each colour a [relative luminance](https://www.w3.org/TR/WCAG22/#dfn-relative-luminance), its brightness on a scale from 0 for black to 1 for white. Each of the red, green and blue channels is scaled to between 0 and 1 and converted to a linear value, then the three are added with weights of 0.2126, 0.7152 and 0.0722.

The [contrast ratio](https://www.w3.org/TR/WCAG22/#dfn-contrast-ratio) of two colours is (L1 + 0.05) / (L2 + 0.05), where L1 is the relative luminance of the lighter colour and L2 that of the darker. It runs from 1:1, for two identical colours, to 21:1, for black on white.

Success criterion [1.4.3 Contrast (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), at level AA, asks for at least 4.5:1 between text and its background. Large-scale text, at least 18 point or 14 point bold (about 24 and 18.5 CSS pixels), needs 3:1. Text that is pure decoration, part of an inactive control, part of a logo or not visible to anyone has no requirement. [1.4.11 Non-text Contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) asks for 3:1 against adjacent colours for what a visitor needs to identify a control and its state, such as a focus indicator, and for the parts of a graphic needed to understand it.

The Understanding page for 1.4.3 adds two points that matter when you check numbers. The thresholds are not rounded: 4.499:1 does not meet 4.5:1. And contrast is calculated so that hue is not a key factor; what counts is how light each colour is. Computed with the formula, pure red on white reaches only about 4:1, pure blue on white over 8:1.

Contrast is measured against the background the text is drawn over in normal use. A site with a light and a dark theme draws its text in two sets of colours, and each pair has to pass in both.

Hand tools measure one pair at a time. [WebAIM's Contrast Checker](https://webaim.org/resources/contrastchecker/) takes a foreground and a background colour and reports each WCAG level as a pass or a fail, and Firefox's [Accessibility Inspector](https://firefox-source-docs.mozilla.org/devtools-user/accessibility_inspector/index.html) shows the ratio for elements of the rendered page. Since the ratio needs nothing but the two colours, a unit test can compute it as well, for every pair in every theme, on every change. A test sees only the colours it is given, though. Text over an image or a gradient has no single background colour, and 1.4.11's Understanding page notes that gradients make contrast harder to test: check those on the rendered page.

Full reference: [MDN: Color contrast](https://developer.mozilla.org/en-US/docs/Web/Accessibility/Guides/Understanding_WCAG/Perceivable/Color_contrast)

## In Terrarium

Two :term[tenants]{id="tenant"} check their colours with a unit test in their own layer: :file[layers/tinkerfund/tests/unit/tokens-contrast.spec.ts] and :file[layers/atlas/tests/unit/atlas-contrast.spec.ts]. Neither test holds a copy of the colours. Each reads its tenant's stylesheet as text and takes the colour :term[tokens]{id="design-token"} out of it. Each also holds its own copy of the WCAG formula; Tinkerfund's reads:

::excerpt{path="layers/tinkerfund/tests/unit/tokens-contrast.spec.ts" lines="17-28"}
```ts
function luminance(hex: string): number {
  const [r, g, b] = [1, 3, 5].map((i) => {
    const c = parseInt(hex.slice(i, i + 2), 16) / 255
    return c <= 0.04045 ? c / 12.92 : ((c + 0.055) / 1.055) ** 2.4
  })
  return 0.2126 * r! + 0.7152 * g! + 0.0722 * b!
}

function contrast(a: string, b: string): number {
  const [hi, lo] = [luminance(a), luminance(b)].sort((x, y) => y - x)
  return (hi! + 0.05) / (lo! + 0.05)
}
```
::

Tinkerfund writes each colour token in :file[layers/tinkerfund/app/assets/theme.css] as a `light-dark()` pair, and the spec's `tokens()` reads both halves with a regular expression, one map per theme. The pairs to check are a hand-written list of foreground, background and minimum, with two thresholds. Its comment says which pair stays below the text threshold:

::excerpt{path="layers/tinkerfund/tests/unit/tokens-contrast.spec.ts" lines="30-36,45-46"}
```ts
// Text needs 4.5:1 (WCAG 1.4.3); the accent as a filled bar or chip border and
// the link-coloured focus ring need 3:1 (1.4.11). Hairlines (`line`, `grid`)
// are decoration. Accent text on accent-soft is the one pair that stays
// UI-only (light: 4.39:1), so never set text that way.
const TEXT = 4.5
const UI = 3
const PAIRS: [fg: string, bg: string, min: number][] = [
  // …
  ['accent', 'accent-soft', UI],
]
```
::

For each theme and each pair, the test requires the computed ratio to be at least the minimum, with `toBeGreaterThanOrEqual` on the unrounded number. A listed token that is not a `light-dark()` pair fails with a message naming it.

The Atlas writes its colours as plain values in :file[layers/atlas/app/assets/theme.css], once per :term[biome], with `prefers-color-scheme: dark` blocks for the dark theme. Its spec collects the custom properties of `:root` and of each biome's class, and for the dark theme adds the values from the dark blocks. The page's ground is not a token: the stylesheet mixes the biome's tint over the paper with `color-mix()`, and the spec's `ground()` repeats that mix channel by channel. For each biome in both themes, ink, muted text and the biome accent must reach 4.5:1 on that ground and on the second paper colour. A guard test fails if the stylesheet's `color-mix()` line for the ground no longer matches the one `ground()` copies.

The faint colour, `--atlas-faint`, reaches far less than 4.5:1 on the light paper and is in no checked pair. Another test limits where it may appear: across the `.css`, `.vue` and `.ts` files under the layer's `app` folder, exactly one line may use it, and that line must be the cover ornament's, a decorative row of tildes and dots on the Atlas's landing page.

Both specs run with the other unit tests in `pnpm test`. [Testing](/t/glassbox/guide/verification/testing#in-terrarium) shows how a layer's tests are found.

### Why it's built this way

- **The stylesheet stays the only home of the colours.** A copy of the palette inside a test could differ from the colours the page uses. Both specs read the stylesheet itself, as their opening comments say. The cost: the Atlas keeps a guard test on the one `color-mix()` line its arithmetic copies. :file[layers/atlas/tests/unit/atlas-contrast.spec.ts]
- **Contrast is checked by a test, not by eye.** Tinkerfund is a showcase held to a high accessibility bar (:file[layers/tinkerfund/GLOSSARY.md]), and the request behind its spec asked for contrast to be checked "with a script or test, not by eye". The spec recomputes every listed pair in both themes whenever the unit tests run. :file[layers/tinkerfund/tests/unit/tokens-contrast.spec.ts]
- **Text and controls get different minimums.** WCAG asks 4.5:1 of text and 3:1 of a control's visible parts, and the spec gives each pair its own minimum, citing 1.4.3 for text and 1.4.11 for the rest. The cost: a pair checked only at 3:1 must never carry text, and the spec's comment tells authors so. :file[layers/tinkerfund/tests/unit/tokens-contrast.spec.ts]
- **A colour too faint for text is fenced off.** Accent on its soft tint misses 4.5:1 in the light theme, the Atlas's faint colour by far. Both stay in the palette: Tinkerfund's deal badge, on that tint, is a filled chip, and a test confines the faint colour to the cover ornament. The cost: that pair and the faint colour can never carry text. :file[layers/atlas/tests/unit/atlas-contrast.spec.ts]
- **The formula is pinned to known answers.** A wrong luminance or ratio function could let every pair pass unnoticed. Tinkerfund's spec checks `contrast()` against WCAG reference values, 21:1 for black on white and 4.48:1 for a mid grey on white, before any pair is trusted. :file[layers/tinkerfund/tests/unit/tokens-contrast.spec.ts]

### What to watch for

- **A ratio just under the threshold fails.** WCAG doesn't round, and neither do these tests: `#777777` on white, at about 4.48:1, fails 4.5:1. Compare the raw number with `>=`, never a value rounded for display.
- **A pair list checks only the pairs it lists.** Tinkerfund's list is written by hand, and the test can't see which colours a component actually puts together. Text on a ground the list doesn't name is never measured: add the pair when a component sets text on a new ground, and check text over images or gradients in the browser.
- **The test reads the stylesheet the way it is written.** Tinkerfund's reader finds only `light-dark()` pairs of six-digit hex colours. The Atlas's finds a rule by its selector at the start of a line and its dark values inside `@media (prefers-color-scheme: dark)` blocks; a dark value it misses leaves the light value in its place, and the dark theme is checked with light colours. After reformatting a stylesheet, break one of its colours on purpose and check that the contrast spec fails. A ground made with `color-mix()` exists only as a formula, so the test repeats the arithmetic and pins the line it copies, as the Atlas's `ground()` does; otherwise a change to the mix goes unchecked.

## Try it in your project

Save this as `contrast.mjs`. It needs nothing but Node:

```js
import assert from 'node:assert/strict'

function luminance(hex) {
  const [r, g, b] = [1, 3, 5].map((i) => {
    const c = parseInt(hex.slice(i, i + 2), 16) / 255
    return c <= 0.04045 ? c / 12.92 : ((c + 0.055) / 1.055) ** 2.4
  })
  return 0.2126 * r + 0.7152 * g + 0.0722 * b
}

function contrast(a, b) {
  const [hi, lo] = [luminance(a), luminance(b)].sort((x, y) => y - x)
  return (hi + 0.05) / (lo + 0.05)
}

assert.equal(contrast('#000000', '#ffffff'), 21)
assert.equal(contrast('#ffffff', '#ffffff'), 1)
assert.ok(contrast('#777777', '#ffffff') < 4.5)
assert.ok(contrast('#767676', '#ffffff') >= 4.5)

console.log(contrast('#777777', '#ffffff').toFixed(3))
console.log(contrast('#767676', '#ffffff').toFixed(3))
```

Run `node contrast.mjs`. The assertions pass and it prints `4.478` and `4.542`: `#777777` on white just misses 4.5:1, and `#767676`, one step darker, passes. Then list your own stylesheet's text and background pairs, in each theme, and assert each against its minimum.
