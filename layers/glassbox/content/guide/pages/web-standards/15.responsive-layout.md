The same page is read on a phone a few hundred pixels wide and on a monitor several times wider. A responsive layout changes with the width it gets: columns stack on a narrow screen and sit side by side on a wide one, headings shrink and grow between two bounds, and a grid adds columns as room appears. CSS does all of it from the width of the window, or, with a container query, from the width of the box a component sits in.

Know media and container queries already? Skip to [In Terrarium](#in-terrarium).

## The concept

It starts with one tag in the page's head. Some phones lay a page out in a virtual :term[viewport] wider than the screen, such as 980 pixels, and then shrink the result to fit; a rule meant for narrow screens then never applies. The [viewport meta tag](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/meta/name/viewport) `<meta name="viewport" content="width=device-width, initial-scale=1">` sets the viewport to the screen's width in CSS pixels, and `initial-scale=1` starts the page at 100% zoom instead of letting the browser zoom out when content overflows.

A media query applies rules only when a test passes. `@media (min-width: 60rem) { … }` applies from a viewport 60rem wide upwards, and `max-width` up to a width. Both [include the value they name](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Media_queries/Using); the range syntax, `(width < 60rem)`, can exclude it. The width where a layout changes is a :term[breakpoint]. In a media query, a rem or em is [based on the initial font size](https://www.w3.org/TR/mediaqueries-4/#units), set by the browser or the reader's preferences, never on the page's own CSS.

Not every change needs a breakpoint. [`clamp(MIN, VAL, MAX)`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/clamp) resolves to `max(MIN, min(VAL, MAX))`: with a `vw` value in the middle, a heading grows with the window between a floor and a ceiling. A grid of `repeat(auto-fit, minmax(11rem, 1fr))` makes as many columns of at least 11rem as fit, and adds or drops one as the width changes. With [`auto-fill`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/repeat) the browser keeps columns that no item fills; `auto-fit` collapses them, so the items stretch across the row.

A media query reads the viewport. A [container query](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Containment/Container_queries) reads a box: `container-type: inline-size` makes an element a query container, and the rules in `@container (min-width: 30rem) { … }` apply to the elements inside it while it is at least 30rem wide. The same component can then lay itself out one way in a wide column and another in a narrow sidebar, at one window width.

Full reference: [MDN: Responsive web design](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/CSS_layout/Responsive_Design)

## In Terrarium

Terrarium writes no viewport tag. Nuxt adds `width=device-width, initial-scale=1` to every page unless the config sets its own ([Nuxt: SEO and Meta](https://nuxt.com/docs/4.x/getting-started/seo-meta)), and :file[nuxt.config.ts] sets only the page's language in `app.head`.

Each :term[tenant] picks its own breakpoints. Glass Box and the Blog write them in pairs: one query for wide screens and one for narrow, meeting at one width. Glass Box's frame gives the sidebar its own column from 1024px and turns it into a menu panel below (:file[layers/glassbox/app/assets/theme.css], :file[layers/glassbox/app/components/glassbox/Sidebar.vue]). The "Last updated" line uses the same pair to show in the page header when wide and at the page's end when narrow:

::excerpt{path="layers/glassbox/app/components/glassbox/Updated.vue" lines="13-18"}
```vue
@media (min-width: 1024px) {
  .end { display: none; }
}
@media (max-width: 1023.98px) {
  .header { display: none; }
}
```
::

The Blog's pair is in rem, `max-width: 59.99rem` and `min-width: 60rem`. From 60rem up, a Blog landing page sets its feed beside a 15rem side panel:

::excerpt{path="layers/blog/app/assets/theme.css" lines="374-385"}
```css
@media (min-width: 60rem) {
  .bl--landing { max-width: 60rem; }
  .bl--landing .landing-grid {
    display: grid;
    grid-template-columns: minmax(0, 1fr) 15rem;
    grid-template-areas:
      "masthead about"
      "feed     about";
    grid-template-rows: auto 1fr;
    column-gap: 2.75rem;
    align-items: start;
  }
```
::

Below 60rem the panel sits between the heading and the posts, and on the Blog's front door the `max-width: 59.99rem` rules shrink it: the writers' cards show names only, two by two, and the tags move into a disclosure.

Big headings use `clamp()`, such as the Blog's masthead at `clamp(2.1rem, 5vw, 3rem)` (:file[layers/blog/app/assets/theme.css]); the Atlas, the Journal and the Midden size theirs the same way. Grids that only need more columns on more room use no query at all: Tinkerfund's footer is `repeat(auto-fit, minmax(180px, 1fr))` (:file[layers/tinkerfund/app/components/tinkerfund/shell/Footer.vue]), and its figure thumbnails and an inventor's campaigns use `auto-fill` (:file[layers/tinkerfund/app/components/tinkerfund/campaign/FigureGallery.vue], :file[layers/tinkerfund/app/components/tinkerfund/inventor/Profile.vue]). The profile's `minmax(min(100%, 280px), 1fr)` asks for 280px or the whole box, whichever is less.

The Blogger Network panel, the box of cards linking each writer's blog, is the Blog's container. Its cards start from an `auto-fit` grid and switch to two, then four, columns as the panel itself widens:

::excerpt{path="layers/blog/app/components/blog/Network.vue" lines="59-60,70,82-88"}
```vue
.bl-network {
  container-type: inline-size;
  /* … */
}
/* … */
.net-cards { list-style: none; margin: 0; padding: 0; display: grid; grid-template-columns: repeat(auto-fit, minmax(11rem, 1fr)); gap: 0.6rem; text-align: left; }
@container (min-width: 30rem) {
  .net-cards { grid-template-columns: repeat(2, minmax(0, 1fr)); }
}
@container (min-width: 46rem) {
  .net-cards { grid-template-columns: repeat(4, minmax(0, 1fr)); }
}
```
::

The panel closes each post page, across the post's column, and on the front door it fills the 15rem side panel (:file[layers/blog/app/pages/t/blog/index.vue]). There it stays under 30rem, too narrow for two 11rem columns, and its cards stack in one.

A Tinkerfund campaign page uses both kinds. A media query on the window splits the page body into the story column and a 360px reward column; inside the story, a container query on the story's own width sets the specifications table beside the text:

::excerpt{path="layers/tinkerfund/app/components/tinkerfund/campaign/Campaign.vue" lines="183-188,200,208-210"}
```vue
@media (min-width: 1000px) {
  .body {
    grid-template-columns: minmax(0, 1fr) 360px;
    grid-template-rows: auto auto 1fr;
    column-gap: 32px;
  }
/* … */
}
/* … */
.story { container-type: inline-size; }
.story-grid { display: grid; gap: 24px; }
@container (min-width: 620px) { .story-grid { grid-template-columns: minmax(0, 1fr) 240px; align-items: start; } }
```
::

### Why it's built this way

- **One component, boxes of different widths.** The Blogger Network panel renders at the foot of each post and inside the front door's narrow side panel, while the window can be the same width for both, so a media query can't tell them apart. Terrarium gives the panel a container query, and its cards follow the panel's own width. :file[layers/blog/app/pages/t/blog/index.vue]
- **On a phone, the first post starts on the first screen.** On narrow screens the front door's panel comes before the posts, and four cards with their taglines pushed the first post a screen and a half down. Terrarium's narrow rules show names only, two by two, and fold the tags into a disclosure. :file[layers/blog/app/assets/theme.css]

### What to watch for

- **Paired breakpoints must leave no gap.** `max-width` and `min-width` both include their value, so `max-width: 1023px` with `min-width: 1024px` leaves widths in between, which zoom can produce, that [match neither](https://www.w3.org/TR/mediaqueries-4/#mq-min-max): there, both "Last updated" lines would show. A value such as `1023.98px` narrows that gap; the range syntax, `(width < 1024px)` beside `(width >= 1024px)`, closes it.
- **A rem breakpoint ignores the page's font size.** The Blog's `60rem` follows the reader's default font size, not a `font-size` set on `html`: a reader who raises it gets the narrow layout on a wider window.
- **A container can't query itself.** `@container` tests the [nearest ancestor](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@container) that is a query container, so its rules style what is inside, such as `.net-cards`, never `.bl-network` itself.
- **A container's width no longer comes from its content.** [`inline-size`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/container-type) works out the element's width ignoring its children: in headless Chromium, an `inline-block` with text measured 0 pixels wide once it became a container. Put it on a box whose parent sets the width, such as a block or a grid cell.
- **Keep the ceiling at least twice the floor.** MDN advises a `clamp()` font size whose maximum is at least twice its minimum, so text can still reach 200% when zoomed. The Blog's masthead, from 2.1rem to 3rem, is under that.
- **Tap targets are a separate check.** A layout that fits a phone can still hold links too small to hit; [minimum target size](/t/glassbox/guide/web-standards/minimum-target-size#in-terrarium) covers them.

## Try it in your project

Save this as `cards.html`. The same list of cards sits in a wide main column and, from 60rem, in a 15rem sidebar; each list is a container query's child:

```html
<!doctype html>
<meta name="viewport" content="width=device-width, initial-scale=1">
<style>
  .page { display: grid; gap: 1rem; }
  @media (min-width: 60rem) { .page { grid-template-columns: minmax(0, 1fr) 15rem; } }
  .box { container-type: inline-size; }
  .cards { display: grid; grid-template-columns: repeat(auto-fit, minmax(11rem, 1fr)); gap: 0.5rem; margin: 0; padding: 0; list-style: none; }
  @container (min-width: 30rem) { .cards { grid-template-columns: repeat(2, minmax(0, 1fr)); } }
</style>
<div class="page">
  <main class="box"><ul class="cards"><li>A</li><li>B</li><li>C</li><li>D</li></ul></main>
  <aside class="box"><ul class="cards"><li>A</li><li>B</li><li>C</li><li>D</li></ul></aside>
</div>
<script>
  const columns = [...document.querySelectorAll('.cards')].map((ul) => getComputedStyle(ul).gridTemplateColumns.split(' ').length)
  console.log(innerWidth, 'main:', columns[0], 'aside:', columns[1])
</script>
```

Opened in headless Chromium, the console reads `1200 main: 2 aside: 1` at 1200 pixels wide, `700 main: 2 aside: 2` at 700 and `390 main: 2 aside: 2` at 390. At 1200 the sidebar's list gets one column at the same window width as the main list's two; at 700 the sidebar spans the page and its container query applies; at 390 the `auto-fit` grid alone fits two. Delete the `container-type` line and reload at 1200: both lists now follow `auto-fit` alone, and the main one prints 5: four columns of 226 pixels and a fifth, empty, collapsed to 0.
