A page scrolls sideways on a phone when something in it sticks out past the right edge of the screen. The usual culprits are few: a long string that can't break, a flex or grid box that refuses to shrink below its content, and a table or code block that is simply wider than a phone. Each has a one-line CSS fix, and one number read in the browser tells you whether any is left.

Know `min-width: 0` already? Skip to [In Terrarium](#in-terrarium).

## The concept

The [viewport](https://developer.mozilla.org/en-US/docs/Glossary/Viewport) is the part of the page the browser window shows. When content is too big for its box, [CSS shows it rather than hide it](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Styling_basics/Overflow): a hidden button would be lost without anyone noticing. Content that runs past the viewport's right edge widens the page, and the reader can scroll sideways to it.

Three things usually cause it.

**A string that can't break.** By default a line breaks only at normal break points, such as a space. A long word, a URL or a piece of inline code has none, so it runs out of its box. [`overflow-wrap`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/overflow-wrap) lets the browser break such a string at any point when the line has no other break. It has two values for that. `anywhere` counts those breaks when the browser works out the box's min-content width, the narrowest the box can be with every possible line break taken. `break-word` doesn't, and that matters for the next cause.

**A flex or grid item that won't shrink.** A [flex item](https://developer.mozilla.org/en-US/docs/Glossary/Flex_Item) is a direct child of a box with `display: flex`. Its [`min-width`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/min-width) defaults to `auto`, and for flex and grid items that usually means the [min-content](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/min-content) width: the item never gets narrower than its longest word or its longest line that may not wrap. `min-width: 0` lets it shrink. A grid column sized `1fr` has the same automatic minimum, since [`1fr` alone means `minmax(auto, 1fr)`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/grid-template-columns); [`minmax(0, 1fr)`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/minmax) lets the column shrink. An item that scrolls its own content has an automatic minimum of 0 already. A shrunk item still has to wrap or clip its text, or the text spills out and widens the page anyway: [`text-overflow: ellipsis`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/text-overflow) cuts a line with "…", but only together with `overflow: hidden` and `white-space: nowrap`.

**An element that is wider than a phone.** A table with many columns, a code block whose lines must not wrap, or a diagram can't fit in 390 pixels. Give it a frame of its own with [`overflow-x: auto`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/overflow-x): the content is clipped at the frame's edge and can be scrolled into view, with a scroll bar only when there is more to see. Then the frame scrolls and the page doesn't. Or show less on a narrow screen, with a media query that hides some columns.

To find out whether a page overflows, read [`scrollWidth`](https://developer.mozilla.org/en-US/docs/Web/API/Element/scrollWidth) of `document.documentElement` with the viewport at phone width. It is the width the page needs to show all its content without a horizontal scroll bar, so at a 390-pixel viewport any value above 390 means the page scrolls sideways. When the content fits, `scrollWidth` equals `clientWidth`, the visible width.

Full reference: [MDN: Overflowing content](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Styling_basics/Overflow)

## In Terrarium

Each :term[tenant] styles its own pages, and the fixes above appear across them.

The Blog's post page ends with links to the previous and next posts by the same persona, side by side. Each link is a flex item with `flex: 1` and `min-width: 0`, and is itself a column of two lines: a direction label and the post's title. The title is cut with an ellipsis. Below 30rem the links stack, and the newer link's lines stretch to its full width:

::excerpt{path="layers/blog/app/assets/theme.css" lines="154-166"}
```css
.bl .post-nav-title {
  font-family: var(--bl-serif);
  font-size: 0.98rem;
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
}
.bl .post-nav-spacer { flex: 1; }
@media (max-width: 30rem) {
  .bl .post-nav { flex-direction: column; }
  .bl .post-nav-newer { text-align: left; align-items: stretch; }
  .bl .post-nav-spacer { display: none; }
}
```
::

With `align-items: stretch` the title is exactly as wide as its link, and a long title is clipped and ends in "…". With `flex-start` the title took the width of its unwrapped text, which never overflowed its own box, and the ellipsis never appeared.

A Blog post's inline code may break at any point, and a code block scrolls in its own frame. The block's code resets the wrapping, since the inline code rule reaches it too:

::excerpt{path="layers/blog/app/assets/theme.css" lines="453,460-462,467,470-471"}
```css

  /* … */
  overflow-wrap: anywhere;
}
.bl .prose pre {
  /* … */
  overflow-x: auto;
  /* … */
}
.bl .prose pre code { background: none; border: 0; padding: 0; font-size: 0.86rem; line-height: 1.55; overflow-wrap: normal; }
```

Browser tests in the Blog and Tinkerfund layers pin these at phone width. They set the viewport to 390 pixels and assert that `document.documentElement.scrollWidth` is at most 390. ::excerpt{path="layers/blog/tests/e2e/blog.spec.ts" lines="291-298"}
```ts
      await page.setViewportSize({ width: 390, height: 800 })
      const wide: string[] = []
      for (const route of routes) {
        await page.goto(url(route), { waitUntil: 'load' })
        const width = (await page.evaluate('document.documentElement.scrollWidth')) as number
        if (width > 390) wide.push(`${route} (${width}px)`)
      }
      expect(wide).toEqual([])
```

### Why it's built this way

- **Wide content scrolls in its own frame, never the page.** A table or diagram wider than a phone would otherwise widen the whole page. The Journal's stylesheet and Tinkerfund's flow test both say it: wide content scrolls instead of widening the page, inside its own frame. :file[layers/journal/app/assets/theme.css]
- **A phone sees fewer columns, not a tiny table.** Tinkerfund's index on a narrow screen keeps only the columns that tell campaigns apart, as its stylesheet's comment says. The cost: the hidden columns appear only on each campaign's own page. :file[layers/tinkerfund/app/components/tinkerfund/browse/IndexTable.vue]
- **A long title is cut, not allowed to widen the post.** A long "Newer" title made Blog posts scroll sideways at 390 pixels: aligned to the start, the title took its unwrapped width and the ellipsis never applied. Stretching it to the link's width restored the cut, and a test now loads such a post. :file[layers/blog/tests/e2e/blog.spec.ts]
- **Inline code breaks; code blocks scroll.** Inline code in a Blog post could also run past the page, so it now breaks anywhere, while code blocks keep their own scroll and unbroken lines. A test loads a post with a long code string at phone width. :file[layers/blog/tests/e2e/blog.spec.ts]
- **The Blog's sweep is a sample, not every post.** Loading every post costs about a minute of browser-test time. Overflow comes from the HTML and CSS, so the test skips hydration and loads only the kinds of post that have overflowed: each persona's longest title and longest code span. :file[layers/blog/tests/e2e/blog.spec.ts]

### What to watch for

- **`min-width: 0` alone can still widen the page.** It lets the item shrink, but a line that may not wrap then spills out of it. Pair it with `overflow-wrap: anywhere`, or with `overflow: hidden` and an ellipsis, and measure again.
- **`break-word` doesn't help inside a flex item.** Its breaks don't count toward the min-content width, so the item's automatic minimum stays as wide as the long string. Use `anywhere` there.
- **A rule for inline code also reaches code blocks.** `code` inside `pre` matches a plain `code` selector. Reset `overflow-wrap` inside the block, as the Blog does, or its lines break mid-word.
- **The page-wide number misses what a box clips.** Content cut off inside an element with `overflow: hidden` doesn't widen the page, so `document.documentElement.scrollWidth` stays at 390. To find clipped text, compare an element's own `scrollWidth` with its `clientWidth`.
- **A sample checks only what it samples.** The Blog's sweep finds a title's older neighbour by sorting filenames, assuming date-prefixed names sort as the page orders posts. A post that overflows for another reason is caught only if it happens to be in the sample.
- **A test browser can hide or invent the problem.** A desktop Chromium ignores the page's `<meta name="viewport">`, so set the width through the driver's viewport, not a window-size flag. On Linux the fallback fonts are narrow and can hide overflow that a wider font shows (:file[docs/agents/verifying-ui-changes.md]).

## Try it in your project

Save this as `page.html`. It has two of the causes: a flex item with a long title that may not wrap, and a long URL:

```html
<!doctype html>
<style>
  body { margin: 0; font: 16px sans-serif; }
  .row { display: flex; gap: 8px; }
  .row a { flex: 1; }
  .title { white-space: nowrap; overflow: hidden; text-overflow: ellipsis; }
</style>
<div class="row">
  <a><div class="title">A post title far too long to fit on one line of a phone</div></a>
  <a><div class="title">Older</div></a>
</div>
<p>See https://example.com/a/very/long/address/with/no/spaces/in/it/at/all</p>
```

Save this beside it as `check.js`, with [Playwright](https://playwright.dev/docs/library) installed:

```js
const { chromium } = require('playwright')

;(async () => {
  const browser = await chromium.launch()
  const page = await browser.newPage({ viewport: { width: 390, height: 800 } })
  await page.goto('file://' + __dirname + '/page.html')
  const width = () => page.evaluate(() => document.documentElement.scrollWidth)
  console.log('as written:', await width())
  await page.addStyleTag({ content: 'p { overflow-wrap: anywhere }' })
  console.log('overflow-wrap:', await width())
  await page.addStyleTag({ content: '.row a { min-width: 0 }' })
  console.log('min-width: 0:', await width())
  await browser.close()
})()
```

Run `node check.js`. On our machine it printed `as written: 465`, then `overflow-wrap: 403` and `min-width: 0: 390`; your numbers depend on the fonts, but the last is 390. The URL was the widest thing; once it breaks, the title's link is still as wide as its unwrapped title, and the ellipsis shows only once `min-width: 0` lets the link shrink. Then point the same script at your own pages and fail on any width above 390.
