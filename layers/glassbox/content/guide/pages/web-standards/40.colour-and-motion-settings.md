A visitor can set their system or browser to light or dark, and to less motion, and a page can follow both settings. Following the colour setting takes two jobs: swapping the page's own colours, and telling the browser which scheme the page is in, so the parts the browser draws itself, such as scrollbars and form controls, match. CSS has a separate tool for each, and a third that ties them together.

Know `color-scheme` and `light-dark()` already? Skip to [In Terrarium](#in-terrarium).

## The concept

The [`prefers-color-scheme`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-color-scheme) media feature reports the setting: `light`, which also covers a visitor who never chose, or `dark`. Rules inside `@media (prefers-color-scheme: dark)` apply only in dark mode, and redefining a site's colour :term[tokens]{id="design-token"} there swaps the palette without editing each rule that uses a colour ([CSS custom properties](/t/glassbox/guide/web-standards/css-custom-properties)). That changes only the colours the page sets.

The `color-scheme` property tells the browser which schemes an element can be drawn in. The browser then picks the colour of the page's background canvas, of scrollbars, of form controls and of other parts it draws. `color-scheme: light dark` on `:root` says the page supports both, so the browser follows the visitor's setting; `color-scheme: light` or `dark` holds the element in one scheme, whatever the setting. The property is inherited, so a single element can opt out of its page's scheme.

The [`light-dark()`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/color_value/light-dark) function joins the two. `light-dark(#fff, #111)` gives the first colour when the element's scheme is light and the second when it is dark, so one declaration replaces a light rule and a dark override. It reads the element's `color-scheme`, not the media query. With no `color-scheme` set the element counts as light, so it gives the first colour. That makes a theme switch cheap: change `color-scheme` on one element, and every `light-dark()` inside it changes too.

The [`color-mix()`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/color_value/color-mix) function mixes colours in a colour space, by an amount: `color-mix(in srgb, var(--link) 60%, currentColor)` is 60% link colour and 40% text colour. A tint or border mixed from tokens follows them into dark mode, so the dark block needs fewer values.

Colour is one of several preferences the browser reports. [`prefers-reduced-motion`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion) is `reduce` when the visitor has asked their device for less motion, and works the same way: CSS reads it in a media query, and script reads any media query with `window.matchMedia('(…)').matches`.

Full reference: [MDN: color-scheme](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/color-scheme)

## In Terrarium

Terrarium uses both ways of following the setting. Most :term[Tenants]{id="tenant"} redefine their tokens in a `prefers-color-scheme` block, as [CSS custom properties](/t/glassbox/guide/web-standards/css-custom-properties) shows for the Journal, and leave `color-scheme` unset. Tinkerfund writes each colour token as a `light-dark()` pair and sets `color-scheme` on `<html>`:

::excerpt{path="layers/tinkerfund/app/assets/theme.css" lines="36-40,67,77-80"}
```css
.tf-page,
.tf-tokens {
  --tf-bg: light-dark(#f2f4f3, #0c1013);
  --tf-surface: light-dark(#ffffff, #13191d);
  --tf-ink: light-dark(#11171b, #e1e7ea);
  /* … */
}
/* … */
:root:has(> .tf-page),
.tf-tokens { color-scheme: light dark; }
:root[data-tf-theme='light']:has(> .tf-page) { color-scheme: light; }
:root[data-tf-theme='dark']:has(> .tf-page) { color-scheme: dark; }
```
::

`.tf-page` is the class every Tinkerfund page puts on `<body>`, and `:root` is the `<html>` element, and `:has(> .tf-page)` matches it only when its `<body>` carries that class. `.tf-tokens` is the same set of tokens on Tinkerfund's tile on the Platform's home page. With no `data-tf-theme` attribute, the page follows the visitor's setting. The footer's theme switch, :file[layers/tinkerfund/app/components/tinkerfund/shell/ThemeSwitch.vue], offers System, Light and Dark, and sets or removes that one attribute:

::excerpt{path="layers/tinkerfund/app/components/tinkerfund/shell/ThemeSwitch.vue" lines="11-16"}
```ts
function apply(theme: TinkerfundTheme) {
  current.value = theme
  const root = document.documentElement
  if (theme === 'system') delete root.dataset.tfTheme
  else root.dataset.tfTheme = theme
}
```
::

A pick goes into `sessionStorage` under `tinkerfund-theme`, which keeps it until the tab closes (:file[layers/tinkerfund/app/utils/demo.ts]). The switch renders System on the server and applies the stored pick in `onMounted`, after the browser has taken over the server's HTML ([Hydration](/t/glassbox/guide/nuxt-vue/hydration)). The colours don't wait for it: the shell adds a one-line script to `<head>` that copies the stored pick onto `<html>` before the page is first drawn.

Two places hold one scheme. In `@media print`, `:root:has(> .tf-page)` gets `color-scheme: light !important`. An Inventor's portrait sets `color-scheme: light` on its own `<svg>` in :file[layers/tinkerfund/app/components/tinkerfund/inventor/Profile.vue], and keeps its light colours on a dark page.

`color-mix()` derives Glass Box's frosted panes from its tokens. In :file[layers/glassbox/app/assets/theme.css], `--gb-pane` is `color-mix(in srgb, #fff var(--gb-pane-white), transparent)`: white at the strength `--gb-pane-white` sets, the rest see-through. The dark block changes only that amount, to a much smaller one. The same file switches its code highlighting with the media query too, setting each highlighted span to its `--shiki-dark` colour; the highlighter's own dark rule keys on a `dark` class on `<html>`, which the Platform never sets.

Diagrams follow the scheme with no extra code: their committed SVGs read their colours from CSS variables, which each Tenant maps to its tokens ([Mermaid pre-rendering](/t/glassbox/guide/nuxt-content/mermaid-pre-rendering)).

Reduced motion uses the same two routes. Tinkerfund's stylesheet turns off every animation and transition on its pages inside `@media (prefers-reduced-motion: reduce)`. The Journal's expanding panels animate in script: :file[layers/journal/app/utils/expandTransition.ts] asks `matchMedia` first and skips the animation on `reduce`, and :file[layers/journal/app/composables/accordionDeepLink.ts] scrolls to an opened entry with `behavior: 'auto'` instead of `'smooth'`.

### Why it's built this way

- **One attribute pins the whole theme.** A switch that rewrote each token would need a second copy of the palette. Tinkerfund writes each colour as a `light-dark()` pair that follows `color-scheme`, so the switch sets one attribute on `<html>`, and the scrollbar and canvas follow the pick too. :file[layers/tinkerfund/app/assets/theme.css]
- **A pinned theme never flashes.** A pick applied only after the page loads would show the system scheme first. A script in `<head>` sets the attribute before the first paint. The cost: the server can't see the pick, so the switch itself shows System until the page mounts. :file[layers/tinkerfund/app/utils/demo.ts]
- **Portraits stay light.** Inventor portraits are drawn for a light background, and with dark colours they lose their faces. The portrait's `<svg>` sets `color-scheme: light`, which holds its tokens on their light values whatever the page's scheme. :file[layers/tinkerfund/app/components/tinkerfund/inventor/Profile.vue]
- **A receipt prints dark on paper.** Under `@media print` Tinkerfund forces `color-scheme: light` on its pages, and the stylesheet's comment gives the case: a printed receipt shows the page's content alone, dark on paper. :file[layers/tinkerfund/app/assets/theme.css]

### What to watch for

- **A dark palette doesn't darken the browser's parts.** Redefining tokens in a media query leaves scrollbars, form controls and the canvas behind the page in the browser's default light scheme. Set `color-scheme: light dark` on `:root` as well.
- **`light-dark()` needs `color-scheme`.** Set it wherever you use the function; unset, every pair gives its light colour, as The concept explains.
- **A library may switch on a class.** A dependency's dark mode can wait for a class or attribute your page never sets, as the code highlighter's `html.dark` does in Glass Box. Check how each one switches, and map it to your own media query or attribute.
- **Script can't read a preference on the server.** A media query in CSS is applied by the browser, but a value from `matchMedia` or storage exists only in the browser. Render a neutral value on the server and apply the real one after mount, or set it before paint from a `<head>` script, as Tinkerfund does.

## Try it in your project

Pick two colours from your stylesheet and turn them into pairs:

```css
:root {
  color-scheme: light dark;
  --surface: light-dark(#ffffff, #13191d);
  --ink: light-dark(#11171b, #e1e7ea);
}
:root[data-theme='light'] { color-scheme: light; }
:root[data-theme='dark'] { color-scheme: dark; }
body { background: var(--surface); color: var(--ink); }
```

In your browser's developer tools, emulate a dark `prefers-color-scheme`: the page, its scrollbar and an `<input>` all turn dark. Then run `document.documentElement.dataset.theme = 'light'` in the console, and the whole page returns to light while the emulation stays dark.
