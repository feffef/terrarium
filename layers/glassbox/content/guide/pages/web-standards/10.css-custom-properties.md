A site's colours, fonts and spacing are used in hundreds of rules across dozens of components. Write each value into every rule and a change of palette means editing them all. Name each value once, as a CSS custom property on an element above the components, and every component inside reads it from there.

Know CSS custom properties already? Skip to [In Terrarium](#in-terrarium).

## The concept

A [CSS custom property](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Cascading_variables/Using_custom_properties) is a property whose name starts with two dashes, such as `--accent: #356a4c`. A rule reads it with `var(--accent)`, or `var(--accent, teal)` to fall back to `teal` when it isn't set. Like `color`, a custom property set on an element is inherited by everything inside that element. Set on `:root`, it reaches the whole document; set on one class, it reaches only what that class wraps. A rule that sets it again on a narrower element, or inside a media query such as `prefers-color-scheme: dark`, overrides it there and below.

Vue's [`<style scoped>`](https://vuejs.org/api/sfc-css-features.html) limits what a component's selectors match, not what its elements inherit. It adds a data attribute to the component's elements and to its selectors, so the component's rules match only its own elements and the root element of each child component. Inheritance is untouched: a scoped component inside a themed wrapper reads the wrapper's custom properties with no extra code.

Vue uses custom properties for its own `v-bind()` in CSS too: a value bound to component state is compiled into a custom property, set on the component's root element.

A template can also set one on a single element with a style binding, `:style="{ '--x': value }"`, and the component's CSS reads it with `var(--x)`, inside `calc()` when it needs arithmetic.

Full reference: [MDN: Using CSS custom properties](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Cascading_variables/Using_custom_properties)

## In Terrarium

Each :term[tenant] brings its own look, and each keeps it in a stylesheet in its layer, :file[layers/journal/app/assets/theme.css] for the Journal. The custom properties there are the tenant's :term[tokens]{id="design-token"}: named values such as a colour. The Journal sets its tokens on one class, `.jd`, and its rules for the page itself read them:

::excerpt{path="layers/journal/app/assets/theme.css" lines="8,11-14,57-59,64"}
```css
.jd {
  /* … */
  --jd-ground: #f3f5ef;
  --jd-surface: #fbfcf9;
  --jd-surface-2: #ecf0e6;
  --jd-ink: #1a2420;
  /* … */
  background: var(--jd-ground);
  color: var(--jd-ink);
  font-family: var(--jd-serif);
  /* … */
}
```
::

Every Journal page in a space wraps its template in that class, as `<main class="jd jd-doc">` in the page that shows one Journal document. A component under it reads the tokens in its own scoped style, such as the stat tile, one of the boxes of figures on a space's landing page:

::excerpt{path="layers/journal/app/components/journal/StatTile.vue" lines="51-63"}
```vue
<style scoped>
.tile {
  grid-row: span 4;
  display: grid;
  grid-template-rows: subgrid;
  row-gap: 0;
  background: var(--jd-surface);
  border: 1px solid var(--jd-line);
  border-radius: var(--jd-radius);
  box-shadow: var(--jd-shadow);
  position: relative;
  transition: border-color 0.15s ease, transform 0.15s ease;
}
```
::

Dark mode, in the Journal, is the same tokens set again. Further down the same stylesheet, not shown here, a `@media (prefers-color-scheme: dark)` block redefines them on `.jd`, and no component changes. [Colour and motion settings](/t/glassbox/guide/web-standards/colour-and-motion-settings) shows Tinkerfund's other way, a `light-dark()` pair in each token.

A wrapper class can also carry a narrower theme. Each Atlas :term[space] is a biome, one place in the Atlas's fictional world, such as the canopy, and its pages add a class named after the space next to the base `atlas` class. The Atlas's base tokens sit on `:root`; the biome class sets some of them again on the page's wrapper, and inside it the biome's paper colour and accents replace the base values:

::excerpt{path="layers/atlas/app/assets/theme.css" lines="64-71"}
```css
.atlas--canopy {
  --atlas-paper: #e6e6cf;
  --atlas-paper-2: #eff0dd;
  --biome-accent: #3f6b3e; /* leaf */
  --biome-accent-2: #b8952f; /* dapple gold */
  --biome-tint: rgb(63, 107, 62);
  --biome-tint-amount: 5%;
}
```
::

Not every tenant puts its tokens on the wrapper. Some tenants, such as the Blog and the Atlas, set them on `:root`. Each keeps its tokens apart from other tenants' by a prefix, `--bl-` or `--atlas-`. Their rules still sit under a wrapper class, such as `.bl`. Tinkerfund sets its tokens on a class it adds to `<body>` (:file[layers/tinkerfund/app/components/tinkerfund/shell/Shell.vue]). It sets them on a second class too, `.tf-tokens`. The platform's home page puts that class on Tinkerfund's tile (:file[app/components/HomeShowcase.vue]).

A component can also set a custom property from a value only it knows. Tinkerfund's funding bar draws as many segments as its `segments` prop asks for. The excerpt opens on the last attribute of the bar's `<div>`, a `:style` that sets `--n` to that count. Each `<i>` segment sets `--i` to its place, and the scoped style reads both, next to Tinkerfund's own tokens:

::excerpt{path="layers/tinkerfund/app/components/tinkerfund/ProgressBar.vue" lines="16-18,22-25"}
```vue
    :style="{ '--n': segments }"
  >
    <i v-for="i in segments" :key="i" :class="{ on: i <= filled }" :style="{ '--i': i }" />
<!-- … -->
<style scoped>
.bar { display: grid; grid-template-columns: repeat(var(--n), 1fr); gap: 3px; height: 12px; }
i { border-radius: 2px; background: var(--tf-grid); }
i.on { background: var(--tf-accent); animation: tf-sweep calc(var(--tf-dur) * 3) var(--tf-ease) both; animation-delay: calc(var(--tf-dur) * var(--i) / 4); }
```
::

The grid gets one column per segment, and each lit segment starts its sweep a quarter of `--tf-dur` after the one before it.

A platform component can be themed the same way without knowing any tenant: Mermaid diagrams read their colours from `--diagram-*` properties, which a tenant maps to its own tokens with `var()` ([Mermaid pre-rendering](/t/glassbox/guide/nuxt-content/mermaid-pre-rendering)).

### Why it's built this way

- **Tokens set once, above the components.** Colours written into each component's style mean editing every component for a new palette or dark mode. Terrarium defines each tenant's tokens once, not per component, on an element above its pages (a wrapper class, `<body>` or `:root`), and scoped child styles inherit them. :file[docs/agents/tenant-layers.md]
- **One stylesheet for every page.** A layer's stylesheet loads on every tenant's pages ([Nuxt layers](/t/glassbox/guide/nuxt-vue/layers) says why), so Terrarium puts each tenant's component rules under its own wrapper class, such as `.jd` or `.bl`. :file[.claude/rules/tenant-layers.md]
- **Custom properties, not a class per segment.** The bar's segment count is a prop, so classes for each segment would fix the count in the CSS. ProgressBar sets `--n` and `--i` instead, and one grid rule and one delay formula serve any count. The cost: the CSS reads values only the template sets. :file[layers/tinkerfund/app/components/tinkerfund/ProgressBar.vue]

### What to watch for

- **Outside the wrapper, no theme.** A component that renders outside the wrapper element, for example through `<Teleport>` to `<body>`, doesn't inherit the tokens and falls back to browser defaults. A class on `<body>`, as Tinkerfund uses, covers teleported content too.
- **A wrong name fails silently.** `var()` with a name nobody sets gives the fallback, or nothing, and the browser reports no error. A rule that reads `var(--acent)` when the token is `--accent` gets the inherited or default colour, not the accent.
- **Unprefixed tokens on `:root` collide.** A token set on `:root` exists on every tenant's pages. Give it the tenant's prefix, or put it on the wrapper.
- **Map tokens with `var()`, not copies.** A token defined as `var(--jd-ink)` follows the dark-mode override; one defined as the same colour literally keeps the light value.

## Try it in your project

Pick one section of your app with its own look, such as an admin area. Move its colours into custom properties on a class, wrap the section's pages in it, and replace each colour in its components' scoped styles with `var(--…)`:

```css
.admin {
  --admin-surface: #ffffff;
  --admin-accent: #1f5fbf;
}
@media (prefers-color-scheme: dark) {
  .admin { --admin-surface: #13191d; --admin-accent: #8ab4ff; }
}
```

Switch your system to dark mode and check that the section follows with no component edited.
