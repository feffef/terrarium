A link or button is easier to hit when it is big enough, or far enough from its neighbours. WCAG, the web's accessibility guidelines, asks that a target for a pointer be at least 24 by 24 CSS pixels, and names the cases that are exempt, such as a link inside a sentence. In CSS, padding makes a small link's hit area taller, and a negative margin of the same size keeps everything around it in place.

Know the 24-pixel rule already? Skip to [In Terrarium](#in-terrarium).

## The concept

Success criterion 2.5.8 Target Size (Minimum), at level AA of WCAG 2.2, asks that the target for pointer inputs be at least 24 by 24 CSS pixels. Pointer inputs cover a mouse, a trackpad, a stylus and a finger. A target is big enough when a 24 by 24 square, aligned with the page, fits wholly inside it. Zoom doesn't count: zooming in leaves an element's size in CSS pixels the same.

It helps people with hand tremors, people whose specialised input devices are less accurate than a mouse, and anyone on a touchscreen. Research on target size mostly concerns touch and suggests larger sizes, but this criterion covers every pointer, so its minimum is smaller. The stricter [2.5.5 Target Size (Enhanced)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html), at level AAA, asks for 44 by 44.

There are five exceptions:

- **Spacing.** A target smaller than 24 by 24 passes if a circle 24 pixels across, centred on its bounding box, doesn't touch another target or the circle of another small target.
- **Equivalent.** Another control on the same page does the same thing and meets the criterion.
- **Inline.** A link in a sentence is exempt, as is any target whose size is held by the line height of the text around it. Text reflows with the window, so an author can't know where such links will fall.
- **User agent control.** The browser draws the control and the author hasn't resized it, such as the calendar of an `<input type="date">`.
- **Essential.** The size or position carries the information, such as pins on a map.

A box's hit area includes its padding. On an inline link, vertical padding [changes the size of the box without moving the content around it](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Styling_basics/Box_model), and can overlap it. On an `inline-block` or block element, the padding pushes what follows down. A [negative margin](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/margin) of the same size draws the neighbours back, so the box is taller while its place in the layout stays the same.

To measure a target, read [`getBoundingClientRect()`](https://developer.mozilla.org/en-US/docs/Web/API/Element/getBoundingClientRect) in the browser: the smallest rectangle around the element, padding and border included. Read it at a phone's width, such as 390 pixels.

Full reference: [W3C: Understanding SC 2.5.8 Target Size (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

## In Terrarium

Small links in several :term[tenants]{id="tenant"} and the site footer (:file[app/components/SiteFooter.vue]) are made at least 24 pixels tall the same way: `display: inline-block`, a vertical padding, and a negative vertical margin of the same size. The Blog's Back link is one:

::excerpt{path="layers/blog/app/assets/theme.css" lines="168-173"}
```css
.bl .post-nav-back {
  margin: 0.9rem 0 0;
  font-family: var(--bl-mono);
  font-size: 0.78rem;
}
.bl .post-nav-back a { display: inline-block; padding-block: 5px; margin-block: -5px; color: var(--bl-muted); text-decoration: none; }
```
::

The Blog's breadcrumb links carry the same three declarations, and Tinkerfund's heading links in long text (:file[layers/tinkerfund/app/assets/theme.css]) and inventor names use 4 or 5 pixels. Their comments call it a 24px tap target with no layout shift.

An element that already has a margin takes the padding out of it. A dig report's jump link on the Midden had margins of its own, and the pager's links sit in a flex row, which makes each one a block:

::excerpt{path="layers/midden/app/pages/t/midden/[space]/[...slug].vue" lines="232-236"}
```css
/* 24px tap targets (WCAG 2.5.8): padding makes up the height, the negative margin
   takes it back so nothing moves (as the breadcrumb does, theme.css). The jump
   link's margins are the old 0.6rem / 0.2rem less that 0.25rem each. */
.midden-report__jump { display: inline-block; padding: 0.25rem 0; margin: 0.35rem 0 -0.05rem; }
.midden-report__pager a { padding: 0.25rem 0; margin: -0.25rem 0; }
```
::

The Blog's tag label does the same in :file[layers/blog/app/assets/theme.css]: 4 pixels of padding, and a bottom margin of `calc(0.6rem - 4px)`, 0.6rem less the padding. On a narrow screen the label is the `<summary>` of a disclosure, its margin set to `-4px 0`, and `.net-tags[open] summary` sets the bottom margin back to `calc(0.6rem - 4px)` while it is open. The button below it that shows the tags' meanings uses 6 pixels the same way.

On Tinkerfund's campaign card, the title link stretches an empty `::after` over the whole card. The inventor link inside the card adds `position: relative` and `z-index: 1` to its padding, which places it above that layer (:file[layers/tinkerfund/app/components/tinkerfund/browse/CampaignCard.vue]).

End-to-end tests measure the fixed controls in a browser. Each loads a page at 390 by 844 pixels and reads every matching element's height:

::excerpt{path="layers/blog/tests/e2e/blog.spec.ts" lines="435-448"}
```ts
  it('keeps the breadcrumb and Back links at least 24px tall on a phone', async () => {
    const page = await createPage()
    try {
      await page.setViewportSize({ width: 390, height: 844 })
      await page.goto(url('/t/blog/karen/2026-07-05-after-themselves'), { waitUntil: 'hydration' })
      const heights = await page
        .locator('.crumb a, .post-nav-back a')
        .evaluateAll((els) => els.map((el) => el.getBoundingClientRect().height))
      expect(heights.length).toBeGreaterThanOrEqual(3)
      for (const h of heights) expect(h).toBeGreaterThanOrEqual(24)
    } finally {
      await page.close()
    }
  })
```
::

The `length` check fails the test if the selectors match too few links. The Midden's jump and pager links (:file[layers/midden/tests/e2e/midden.spec.ts]), Tinkerfund's campaign links in its index table (:file[layers/tinkerfund/tests/e2e/tinkerfund-flows.spec.ts]) and the friction ledger's select and pull-request links (:file[layers/journal/tests/e2e/journal.spec.ts]) have the same kind of test.

The small targets are found by the visitor-loop :term[skill]: read-only agents browse a production preview, and its brief tells them to measure sizes in the page at the width in question, 390px included, skipping hidden 0 by 0 links in tap-target scans (:file[.agents/skills/visitor-loop/visitor-brief.md]). A size it confirms is filed as a bug. [Usability testing](/t/glassbox/guide/verification/usability-testing#in-terrarium) shows the run.

### Why it's built this way

- **A taller target must not move the page.** Padding alone makes a link taller, and on an `inline-block` it pushes everything below it down. Terrarium pairs the padding with an equal negative margin, which the comments describe as a tap target with no layout shift. :file[layers/blog/app/assets/theme.css]
- **A margin the element already has absorbs the padding.** An element has one margin per side, so the Midden's jump link can't add a negative one to its old margins. Its margins are the old values less the padding, like the Blog tag label's `calc(0.6rem - 4px)`. The cost: each is worked out by hand, and the Midden's comment writes the sum out. :file[layers/midden/app/pages/t/midden/]
- **A link inside a card-wide link is lifted above it.** The campaign card's title link spreads its hit area over the whole card, so a tap on the inventor name would open the campaign. The inventor link sits above that layer, and its comment says so. :file[layers/tinkerfund/app/components/tinkerfund/browse/CampaignCard.vue]
- **Only a rendered page shows the height.** The size comes from font, line height, padding and margin together, and any later style edit can change one of them. Terrarium adds e2e tests that load a fixed page at phone width and require 24 pixels. :file[layers/blog/tests/e2e/blog.spec.ts]

### What to watch for

- **Nothing measures a new control.** No :term[ADR], rule or agent doc sets a target-size practice, and no lint rule or :term[gate] step measures targets. Only the e2e tests above do, each for the selectors it names: a new small link passes `pnpm gate:scoped` unmeasured, until a visitor run finds it.
- **Keep the two numbers equal.** A padding of 5 pixels with a margin of -4 pixels moves everything below by 2 pixels. Change both together, and redo the sum when the element has a margin of its own.
- **A big box is not always the target.** The negative margin leaves the padding reaching over its neighbours. Where two padded links overlap, the later one in the page takes the tap, and an element drawn on top, like the card's stretched link, takes it from both. `document.elementFromPoint(x, y)` names what a tap at a point would hit.
- **The tests read height only.** A link of one or two characters can be narrower than 24 pixels. Measure the width too.
- **Passing is not the same as easy to use.** A link in a sentence is exempt, and a small target with space around it passes.

## Try it in your project

Save this as `target.html` and open it in a browser:

```html
<!doctype html>
<meta name="viewport" content="width=device-width">
<body style="font: 14px/1.4 sans-serif">
  <nav><a href="#">Back to the list</a></nav>
  <p id="next">The next paragraph</p>
  <script>
    const a = document.querySelector('a')
    const next = document.querySelector('#next')
    console.log('before', a.getBoundingClientRect().height, next.getBoundingClientRect().top)
    Object.assign(a.style, { display: 'inline-block', paddingBlock: '4px', marginBlock: '-4px' })
    console.log('after', a.getBoundingClientRect().height, next.getBoundingClientRect().top)
  </script>
</body>
```

The console shows two lines. In headless Chromium at 390 pixels wide they read `before 16 41.59375` and `after 27.59375 41.59375`. The first height depends on the font; the second is the line height, 19.6 pixels, plus 8 of padding. The paragraph's top is the same in both. Then remove the `marginBlock` and reload: the height stays, and the paragraph moves down.
