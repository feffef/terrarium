An SVG is a picture written as text: shapes and lines described in markup, not pixels. It stays sharp at any size, it can sit right inside a page's HTML, and the page's CSS can colour it. That last strength is also the risk. Markup placed in the page can do anything the page's own code can, an attack called :term[cross-site scripting]. Markup that wasn't written to be safe has to be checked first. Terrarium keeps illustrations as SVG markup in content files. Each one must pass a filter before it can merge, and the filter runs in the :term[gate], the machine checks every change must pass.

Know SVG already? Skip to [In Terrarium](#in-terrarium).

## The concept

SVG (Scalable Vector Graphics) is an XML-based markup language for two-dimensional vector graphics. A file holds elements such as `<path>`, `<circle>` and `<text>`, each with coordinates, so it can be written in any text editor, searched and compressed. Unlike a PNG or JPEG, it renders at any size without losing quality.

The [`viewBox`](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Attribute/viewBox) attribute sets the coordinate system the drawing uses: four numbers, `min-x min-y width height`. `viewBox="0 0 400 300"` means the shapes are drawn on a 400 by 300 grid, and the browser stretches that grid to whatever box the `<svg>` element gets on the page. `preserveAspectRatio` decides how it fits when the box has a different shape.

A page can show an SVG two ways. As an image source, in `<img>` or a CSS `background-image`, it is kept apart from the page: browsers [disable its scripts and don't load its external resources](https://developer.mozilla.org/en-US/docs/Web/SVG/Guides/SVG_as_an_image). Written inline, as an `<svg>` element inside the HTML, its elements become part of the page's DOM. Page CSS then styles them, and they read the page's custom properties ([CSS custom properties](/t/glassbox/guide/web-standards/css-custom-properties)) and [`currentColor`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/color_value#currentcolor_keyword), the value of the element's `color` property. A drawing stroked in `currentColor` takes the colour of the text around it, in light mode and dark.

Inline SVG gets none of the protection an image gets. It can carry a `<script>`, an event handler such as `onload=`, a link, or a `url()` that fetches something from another site. A framework that inserts a string as raw markup, as Vue's [`v-html`](https://vuejs.org/api/built-in-directives.html#v-html) does, warns that this opens the door to cross-site scripting. To insert SVG you didn't write yourself, run it through a sanitiser such as [DOMPurify](https://github.com/cure53/DOMPurify) or a check of your own first.

Full reference: [MDN: SVG](https://developer.mozilla.org/en-US/docs/Web/SVG)

## In Terrarium

Several :term[tenants]{id="tenant"} draw their own art as inline SVG kept in content files. An Atlas :term[specimen]'s engraved plate, a Marquee :term[poster] and Tinkerfund's figures, portraits and icons are all SVG markup in a :term[frontmatter] field or a YAML file. A specimen's plate is the `illustration` field, and holds only the inner drawing:

::excerpt{path="layers/atlas/content/canopy/pages/folium-mendax.md" lines="38-42"}
```md
illustration: |
  <g stroke="currentColor" stroke-width="1.3" stroke-linecap="round" fill="none">
    <!-- the leaf that is not a leaf: the tinted feature is its wash -->
    <path d="M126 208 q-5 -44 34 -85 q38 -40 95 -50 q28 -5 41 2 q2 14 -12 41 q-28 52 -78 80 q-45 24 -80 12"
      fill="var(--sig-1)" fill-opacity="0.13" />
```
::

The lines are stroked in `currentColor`, and the one tinted shape is filled with `--sig-1`, the first colour of the specimen's colour signature, which the specimen's page sets on its wrapper from its `signature` field (:file[layers/atlas/app/utils/atlas.ts]). The component that draws the plate supplies the outer `<svg>` with its `viewBox`, and inserts the field inside it with `v-html`, Vue's way of putting a string into the page as raw HTML:

::excerpt{path="layers/atlas/app/components/atlas/SpecimenPlate.vue" lines="17-18"}
```vue
      <!-- eslint-disable-next-line vue/no-v-html -->
      <svg v-if="illustration" viewBox="0 0 400 300" preserveAspectRatio="xMidYMid meet" role="img" :aria-label="`Engraved plate of ${binomial}`" v-html="illustration" />
```
::

The Atlas stylesheet sets that `<svg>` to fill its frame and gives it `color: var(--atlas-ink)` (:file[layers/atlas/app/assets/theme.css]), which is the colour `currentColor` picks up. The Marquee's :file[layers/marquee/app/components/marquee/Poster.vue] and Tinkerfund's :file[layers/tinkerfund/app/components/tinkerfund/Figure.vue] work the same way. The wrappers also carry ARIA attributes such as `role="img"` and `aria-label`, which [ARIA](/t/glassbox/guide/web-standards/aria) explains.

The filter is :file[app/utils/svg.ts]. `svgHazard` reads the markup as text, and takes one option, `{ html: true }`, which the Mermaid check below uses. Its first step refuses any element not on an allowlist of static drawing elements:

::excerpt{path="app/utils/svg.ts" lines="9-13"}
```ts
const ELEMENTS = new Set(
  ('svg g defs path text tspan circle ellipse rect line polyline polygon marker use title desc '
    + 'lineargradient radialgradient stop clippath mask filter fegaussianblur feturbulence '
    + 'fedisplacementmap fecomposite fecolormatrix fedropshadow').split(' '),
)
```
::

Its second step tests the markup against each pattern in a list. In order, the patterns catch a character reference, a backslash escape, an `on…=` event handler, an `href` that leaves the document, and a `url()` or `@import` that loads something:

::excerpt{path="app/utils/svg.ts" lines="17-25"}
```ts
const HAZARDS: [RegExp, string][] = [
  // Browsers decode entities before acting on a value, so only the five that
  // can't spell a keyword pass; write any other character literally.
  [/&(?!(?:amp|lt|gt|quot|apos);)/i, 'uses a character reference'],
  [/\\/, 'uses an escape'],
  [/[\s/"']on[a-z]+\s*=/i, 'sets an event handler'],
  [/(?:^|[\s/"'])(?:xlink:)?href\s*=(?!\s*["']?#)/i, 'links outside the document'],
  [/url\((?!\s*["']?#)|@import/i, 'loads an external resource'],
]
```
::

A link or a `url()` may point only inside the same drawing, at an `#id`, such as a gradient. `safeSvg` wraps `svgHazard` in a string schema of [Zod](https://v3.zod.dev/), the validation library the content schemas are written in, and the Atlas and Marquee manifests declare `illustration: safeSvg.optional()`. Tinkerfund's :file[layers/tinkerfund/schemas.ts] calls the same check (`flagSvgHazard`) and adds rules of its own:

::excerpt{path="layers/tinkerfund/schemas.ts" lines="25-30"}
```ts
      flagSvgHazard(markup, ctx)
      for (const [, value] of markup.matchAll(COLOUR_VALUE)) {
        const colour = value!.trim()
        if (!THEME_COLOUR.test(colour)) ctx.addIssue({ code: z.ZodIssueCode.custom, message: `colour "${colour}" is not a theme token` })
      }
      if (/\sid\s*=/.test(markup)) ctx.addIssue({ code: z.ZodIssueCode.custom, message: 'must not set an id' })
```
::

`COLOUR_VALUE` is a pattern that finds each `fill`, `stroke` or `color` value in the markup. `THEME_COLOUR` accepts only `none`, `currentColor`, a `var(--tf-…)` token or a `color-mix()` of two tokens. The same schema also caps the markup's size in bytes: 4096 for a figure or a portrait, 1024 for a category icon.

The schemas run in `pnpm validate:content`, a step of the :term[floor]. The floor is the part of the :term[gate] that always runs (:file[scripts/gate/gate.ts]). How that step parses every content file is in [Content validation](/t/glassbox/guide/verification/content-validation).

Mermaid diagrams are SVG too, drawn once and committed ([Mermaid pre-rendering](/t/glassbox/guide/nuxt-content/mermaid-pre-rendering)). Their check calls the same filter with one option:

::excerpt{path="scripts/gate/validate-mermaid-svgs.ts" lines="41-44"}
```ts
  const unsafe = onDisk
    .map(svgPathFor)
    .map((file) => ({ file, hazard: svgHazard(readFileSync(join(root, file), 'utf8'), { html: true }) }))
    .filter((u) => u.hazard)
```
::

`html: true` adds the elements Mermaid's labels and theme need, `foreignObject`, `div`, `span`, `p`, `br` and `style`, and every pattern still applies inside them.

### Why it's built this way

- **List what may pass, not what may not.** A list of dangerous elements has to name each one, and SVG has many that link or animate. Terrarium lists the static drawing elements and refuses everything else, so anything that links, animates, styles the page or escapes the drawing is simply absent. :file[app/utils/svg.ts]
- **Refuse character references, don't decode them.** Browsers decode `&#104;` to `h` before acting on a value, so an encoded `href` would slip past a text check. Terrarium refuses every reference except `&amp;`, `&lt;`, `&gt;`, `&quot;` and `&apos;`, which can't spell a keyword. The cost: an author writes any other character literally. :file[app/utils/svg.ts]
- **One check for content and diagrams.** Authored SVG and Mermaid's committed files both reach the page through `v-html`. One function serves the content schemas and the Mermaid check, which differ only in Mermaid's extra label elements. :file[app/utils/svg.ts]
- **Theme tokens only, in Tinkerfund.** A fixed colour reads well in one theme and badly in the other. Tinkerfund's schema accepts only its theme tokens or `currentColor` in a figure, so every figure follows light and dark mode. :file[layers/tinkerfund/schemas.ts]

### What to watch for

- **The check runs in the gate, not the build.** Nuxt Content drops Zod refinements when it builds ([Content validation](/t/glassbox/guide/verification/content-validation) says why), so `pnpm build` accepts an unsafe illustration; the gate's `pnpm validate:content` is what stops it merging. Run that after editing one.
- **Scoped styles stop at `v-html`.** Vue doesn't apply a component's `<style scoped>` rules to markup inserted with `v-html`. Style the inner drawing through values it inherits, `currentColor` and custom properties, or from a global stylesheet.
- **An id in inline SVG is an id of the whole page.** Show one drawing twice and its ids repeat. Tinkerfund's schema refuses ids, since one figure can appear twice on a page, so a Tinkerfund figure can't define a gradient or anything else that a link to `#id` reaches.
- **The filter reads text.** A harmless backslash in a label is refused like the character references above. Write the character itself.

## Try it in your project

Draw an icon inline with `stroke="currentColor"` and set `color` on its parent: the icon follows, in both colour schemes.

```html
<p style="color: teal">
  <svg viewBox="0 0 24 24" width="1em" height="1em" fill="none" stroke="currentColor">
    <circle cx="12" cy="12" r="9" />
  </svg>
  Done
</p>
```

Before you insert SVG from anywhere but your own hands with `v-html` or `innerHTML`, sanitise it, and add a test that feeds your check two hazards and expects both refused. With Vitest, and a check that returns a reason or `undefined` as `svgHazard` does:

```ts
import { expect, test } from 'vitest'
import { svgHazard } from './svg'

test('refuses a handler and an off-site link', () => {
  expect(svgHazard('<path onload="alert(1)"/>')).toBeDefined()
  expect(svgHazard('<use href="https://example.com/x.svg#a"/>')).toBeDefined()
})
```

Terrarium's `svgHazard` returns `sets an event handler` for the first and `links outside the document` for the second, and `undefined` for a plain `<path d="M0 0h10"/>`.
