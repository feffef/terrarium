A page that renders on the server and then comes alive in the browser runs its setup code twice. Load data in setup the plain way and it is fetched twice too: once for the HTML, once more in the browser. Nuxt's `useAsyncData` fetches once and sends the result along. With a page cache, Nuxt can also send it as a file when the visitor clicks to the next page.

Know `useAsyncData` and payloads already? Skip to [In Terrarium](#in-terrarium).

## The concept

`useAsyncData(key, handler)` runs `handler`, an async function, and returns refs: `data` holds its result, `status` and `error` say how it went. On the server, Nuxt waits for the handler before it renders the HTML, then stores the result under `key` in the **payload**: the data Nuxt serializes into the page for the browser. When the browser takes over the page, `useAsyncData` finds its key in the payload and doesn't run the handler again. Calls with the same key share one result, so the key must be unique to the data. Without one, Nuxt makes a key from the call's place in the source.

That covers the first page. When the visitor follows a link, the browser builds the next page itself, and normally runs that page's handlers there. **Payload extraction** changes that for some routes: Nuxt writes the payload a server render produced to a `_payload.json` file next to the route, and on a client navigation fetches that file and uses its data instead of running the handlers. With `experimental.payloadExtraction: 'client'`, the first page keeps its payload inline in the HTML, and only navigations fetch the file.

Only some routes get that file: prerendered ones, and ones the server caches. Nuxt sets caching per route with `routeRules` in `nuxt.config.ts`, which its server engine, Nitro, applies. Nitro's [`cache` rule](https://nitro.build/guide/cache) keeps a rendered page for `maxAge` seconds, and with `swr: false` it renders a fresh copy once that time is up rather than serve the expired one. A cached copy serves every request for that URL: Nitro drops the request's headers when it renders a cached page, except those listed in `varies`.

Full reference: [Nuxt docs: useAsyncData](https://nuxt.com/docs/4.x/api/composables/use-async-data)

## In Terrarium

Terrarium's pages load their content inside `useAsyncData`, most of them keyed by the route's path. The Platform's catch-all page loads its Document, and on a Space's landing page the Space's other Collections too:

::excerpt{path="app/pages/t/[tenant]/[space]/[...slug].vue" lines="13-24"}
```ts
const { data, status, error } = await useAsyncData(route.path, async () => {
  const page = await queryCollection(pagesKey).path(path).first()
  const sections = atRoot
    ? await Promise.all(
        Object.entries(collections).map(async ([name, key]) => ({
          name,
          items: await queryCollection(key).all(),
        })),
      )
    : []
  return { page, collections: sections }
})
```
::

`queryCollection` is [Nuxt Content](https://content.nuxt.com/docs/advanced/database)'s query. On the server it reads the server's SQLite database. In the browser it downloads a SQLite runtime compiled to WebAssembly, and a dump of each Collection it queries, the first time it runs. The Platform's config sets up payloads and the page cache:

::excerpt{path="nuxt.config.ts" lines="14-25"}
```ts
  // In-app navigation reads a server-rendered `_payload.json` instead of
  // querying Content in the browser (ADR-0028).
  experimental: {
    payloadExtraction: 'client',
    defaults: { nuxtLink: { prefetchOn: { visibility: false, interaction: true } } },
  },
  routeRules: {
    '/': { cache: { maxAge: 60, swr: false } },
    '/t/**': { cache: { maxAge: 60, swr: false } },
  },
  // Bounds that page cache's memory (ADR-0028, #1446).
  nitro: { storage: { cache: { driver: 'lru-cache', max: 200 } } },
```
::

The two `cache` rules cover the home page and every Tenant page, and each has a payload file. Nuxt's docs name ISR and SWR routes as the ones that get a payload; :file[docs/research/content-client-queries-without-wasm.md] traces how a `cache` rule gets one too. A link fetches its route's code and payload when the pointer rests on it, a finger touches it or the keyboard focuses it, not when it scrolls into view. On the click, `useAsyncData` finds its key in the fetched payload, the handler never runs, and the browser loads no database. The cache sits in a store with a size cap, and :file[tests/unit/page-cache.spec.ts] checks that cap against the real config.

A Tenant changes the rules for its own pages in its layer's config. Tinkerfund formats money and dates in the visitor's language, and runs its search in the browser:

::excerpt{path="layers/tinkerfund/nuxt.config.ts" lines="10-14"}
```ts
  // Page cache (ADR-0028): money and dates follow the visitor's locale (#1365); search stays in the browser.
  routeRules: {
    '/t/tinkerfund/**': { cache: { varies: ['accept-language'] } },
    '/t/tinkerfund/*/search': { cache: false },
  },
```
::

The search route is not cached and has no payload: after a click to it, its `useAsyncData` handler runs in the browser and queries the browser database (:file[layers/tinkerfund/app/composables/search.ts]).

### Why it's built this way

In-app navigation that reads a cached server payload: ADR-0028 (:file[docs/adr/0028-navigation-reads-server-payloads.md]).

### What to watch for

- **Return what the page reads.** A handler that returns whole Documents sends every field. The Blog's front page, :file[layers/blog/app/pages/t/blog/index.vue], `.select()`s only the fields it lists.
- **One key per piece of data.** A page with two `useAsyncData` calls needs two keys, or the second gets the first's result. The Journal's Document page keys its second call `${route.path}:onramp` (:file[layers/journal/app/pages/t/journal/]).
- **Only queries inside `useAsyncData` are skipped.** What else still loads the browser database, and what a cached copy means for each visitor, is in ADR-0028 (:file[docs/adr/0028-navigation-reads-server-payloads.md]).

## Try it in your project

Take a page that loads its data in `useAsyncData`, and give its route a short cache and payload extraction:

```ts
export default defineNuxtConfig({
  experimental: { payloadExtraction: 'client' },
  routeRules: { '/blog/**': { cache: { maxAge: 60, swr: false } } },
})
```

Build and start the app (`nuxt build`, then `nuxt preview`). Open another page, then click a link to the cached one with the browser's network panel open: you should see its `_payload.json` and no request from the handler.
