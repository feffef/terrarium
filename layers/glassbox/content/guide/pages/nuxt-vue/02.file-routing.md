A site whose pages all share one layout needs only one page file: a catch-all that reads the address and fetches what it names. A site that wants a few of its pages to look different then needs a way to let a more specific file take over, without a list of exceptions anyone must keep in order. Nuxt's file routing gives both.

Know Nuxt file routing already? Skip to [In Terrarium](#in-terrarium).

## The concept

Nuxt makes a route for every file in `app/pages/`. The file's path is the route's path: `about.vue` answers `/about`, and an `index.vue` answers its folder's own path, so `app/pages/index.vue` is `/`. A part of the name in square brackets is a parameter: `posts/[id].vue` answers `/posts/1` and `/posts/hello`, and the page reads the value from `useRoute().params.id`. Folder names work the same way, so `[tenant]/[space]/` holds two parameters.

A file named `[...slug].vue` is a catch-all. It matches every path below its folder, however deep, and its parameter holds the segments as an array: `/hello/world` gives `['hello', 'world']`. With no segment left, the array is empty, so the catch-all also answers its folder's own path when no `index.vue` sits beside it.

Several pages often match one address. Nuxt's routing is built on [Vue Router](https://router.vuejs.org/guide/essentials/route-matching-syntax), which ranks routes by how specific their path is, not by the order they were found in: a fixed segment beats a parameter, and a parameter beats a catch-all. So `posts/new.vue` answers `/posts/new` even though `posts/[id].vue` matches it too. Pages from every layer join the same ranking, as if they sat in one `app/pages/`.

To send the visitor somewhere else from code, a page calls `navigateTo()`. During server rendering it answers with a redirect; in the browser it moves to the new route. Its result must be awaited or returned.

Full reference: [Nuxt docs: pages/ directory](https://nuxt.com/docs/4.x/directory-structure/app/pages)

## In Terrarium

Every Terrarium site lives under `/t/<tenant>/<space>/…`. The Platform, the code outside any layer, answers all of those addresses with one catch-all, `app/pages/t/[tenant]/[space]/[...slug].vue`. It turns the two parameters into one :term[Tenant] and one :term[Space] with `useSpace`, then reads that Space's Document at the remaining path:

::excerpt{path="app/pages/t/[tenant]/[space]/[...slug].vue" lines="7-14"}
```vue
const route = useRoute()
const tenant = String(route.params.tenant)
const { space, path, atRoot, pagesKey, collections } = useSpace(tenant)

// `status`/`error` let a failed client-side content load raise the
// ContentLoadErrorDialog rather than a silent "Not found" (issue #236).
const { data, status, error } = await useAsyncData(route.path, async () => {
  const page = await queryCollection(pagesKey).path(path).first()
```
::

Because the slug may be empty, the same file also renders each Space's front page, where it lists the Space's other Collections. A Tenant with no page files of its own still gets every address its :term[manifest] declares, plainly styled.

A Tenant that wants its own look adds pages to its layer under `app/pages/t/<tenant>/`. Their first segment is the fixed name of the Tenant where the catch-all has `[tenant]`, so they outrank it for that Tenant's addresses and no other. The Journal's folder, :file[layers/journal/app/pages/t/journal/], shows three levels of it: `[space]/index.vue` takes each Space's front page, `[space]/[...slug].vue` takes every other Document, and fixed pages such as `[space]/skills.vue` outrank the Journal's own catch-all. An override reads its Space through the same `useSpace` as the catch-all, with the Tenant's name written in:

::excerpt{path="layers/journal/app/pages/t/journal/[space]/[...slug].vue" lines="18-23"}
```vue
const route = useRoute()
const { space, path, pagesKey } = useSpace('journal')

const { data: page, error } = await useAsyncData(route.path, () =>
  queryCollection(pagesKey).path(path).first(),
)
```
::

The bare `/t/<tenant>` matches no Platform page, since the catch-all needs a Space. A Tenant answers it with an `index.vue` at the top of its folder, its root page. The Blog's shows one feed of every Persona's posts; the Journal's only sends the visitor on to its main Space:

::excerpt{path="layers/journal/app/pages/t/journal/index.vue" lines="1-5"}
```vue
<script setup lang="ts">
// Tenant-root route (ADR-0016): journal has no front door of its own, so its root
// sends visitors to its main Space.
await navigateTo('/t/journal/current')
</script>
```
::

On the server that call answers `/t/journal` with a redirect, which the Journal's own end-to-end test checks with `expectRedirect` in :file[layers/journal/tests/e2e/journal.spec.ts].

### Why it's built this way

Why the address names the Tenant and Space, and why every page resolves it through one resolver: ADR-0006 (:file[docs/adr/0006-runtime-routing-path-prefix.md]). Why a Tenant's root page lives in its own layer: ADR-0016 (:file[docs/adr/0016-tenant-root-layer-routes.md]).

### What to watch for

- **An override must set its own 404.** Nuxt matched the page, so the response is a 200 unless the page says otherwise. The catch-all calls `setResponseStatus(404)` when no Document exists at the path, and the Journal's override repeats that check; an override without it answers a missing Document with a 200.
- **A fixed page hides a Document at its path.** Once `[space]/skills.vue` exists, a Document whose path is `/skills` in any of that Tenant's Spaces can no longer be reached, because the fixed page always outranks the catch-all.
- **`navigateTo` doesn't end the script.** The rest of `<script setup>` still runs after the call. The Journal's root page puts nothing after it.
- **A root page needs its own test.** The smoke test in :file[tests/e2e/smoke.spec.ts] visits the Space addresses it derives from the manifests, and no manifest knows about a root page. Each Tenant tests its own, as the Journal does.

## Try it in your project

In a Nuxt app, add `app/pages/docs/[...slug].vue` that prints `useRoute().params.slug`, then `app/pages/docs/intro.vue`. Open `/docs/intro`, `/docs/a/b` and `/docs`, and see which file answers each. Rename the files so the catch-all sorts first; nothing changes, because the ranking comes from the paths.
