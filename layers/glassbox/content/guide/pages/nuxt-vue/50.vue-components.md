A Vue page is built from components, each one file that holds its markup, its code and its styles. The code in a component runs once for every instance of it, each time one is created (on a page the server renders, once there and again in the browser), and Vue redraws the markup when the data that code works with changes. Code that several components need can be pulled out into a composable.

Know Vue components and composables already? Skip to [In Terrarium](#in-terrarium).

## The concept

A **single-file component** is a `.vue` file made of [blocks](https://vuejs.org/api/sfc-spec.html#language-blocks), chiefly `<template>` for the markup, `<script setup>` for the code, and `<style>` for the CSS, which `scoped` limits to this component's elements. A compiler turns it into JavaScript and CSS at build time. Code in [`<script setup>`](https://vuejs.org/api/sfc-script-setup.html) runs once for each instance of the component, when Vue creates it (unlike a plain `<script>`, which runs once when the file is first imported), and the template can use every name it declares. In the template, a `:` before an attribute binds it to an expression, and `v-for` repeats an element once per item. `defineProps` declares the inputs a parent passes in, typed with TypeScript; it needs no import.

A template redraws when its data changes, because Vue tracks what each render reads. [`ref(value)`](https://vuejs.org/guide/essentials/reactivity-fundamentals.html) holds a value in `.value`; the template reads it without `.value`. A [`computed`](https://vuejs.org/guide/essentials/computed.html) derives a value from refs and props, keeps it, and works it out again only when one of them changes.

A [composable](https://vuejs.org/guide/reusability/composables.html) is a function, named `useSomething` by convention, that calls these APIs for whichever component calls it and returns the state. Lifecycle hooks such as `onMounted` attach to the component whose setup code is running, so a composable is [called from `<script setup>` or from another composable](https://vuejs.org/guide/reusability/composables.html#usage-restrictions), never later from a timer or a click handler.

Full reference: [Vue docs: Single-File Components](https://vuejs.org/guide/scaling-up/sfc.html)

## In Terrarium

Terrarium's pages and components are single-file components, and each that has code writes it in `<script setup lang="ts">`. [Nuxt renders every page on the server first](https://nuxt.com/docs/4.x/guide/concepts/rendering#universal-rendering), and a component's code runs there too; [Hydration](/t/glassbox/guide/nuxt-vue/hydration) says what that asks of it. Tinkerfund's funding bar shows the blocks at work:

::excerpt{path="layers/tinkerfund/app/components/tinkerfund/ProgressBar.vue" lines="1-4,18"}
```vue
<script setup lang="ts">
const props = withDefaults(defineProps<{ percent: number; segments?: number }>(), { segments: 20 })
const filled = computed(() => Math.round((Math.min(props.percent, 100) / 100) * props.segments))
</script>
<!-- … -->
    <i v-for="i in segments" :key="i" :class="{ on: i <= filled }" :style="{ '--i': i }" />
```
::

The parent passes `percent`; `segments` defaults to 20. `filled` counts the lit segments and changes only when a prop does. The bar's outer `<div>`, left out above, sets `--n` to the segment count, each segment sets `--i` to its place, and the scoped style reads both ([CSS custom properties](/t/glassbox/guide/web-standards/css-custom-properties) shows how). Nuxt names the component from its folder, and pages use it as `<TinkerfundProgressBar>` with no import ([Nuxt layers](/t/glassbox/guide/nuxt-vue/layers) says how).

Shared code goes in composables, in a layer's `app/composables/` folder, which Nuxt auto-imports like its components. The Journal's `useMaintainerView` decides whether to show maintainer-only links, and every session card calls it ([Hydration](/t/glassbox/guide/nuxt-vue/hydration) shows its code). `useSpace`, which every page inside a :term[Space] starts with, is in [File routing](/t/glassbox/guide/nuxt-vue/file-routing). Tinkerfund's `useTinkerfundClock` gives a page the Space's current time and a countdown that moves on unless the Space pins its clock. It registers its timer's start and stop on the calling component with `onMounted` and `onUnmounted`, then awaits the shop:

::excerpt{path="layers/tinkerfund/app/composables/clock.ts" lines="20-29"}
```ts
  const moved = ref(0)
  let ticking = false
  let timer: ReturnType<typeof setInterval> | undefined
  // Registered before the first await, while the component is still current.
  onMounted(() => {
    if (ticking) timer = setInterval(() => (moved.value = Date.now()), 60_000)
  })
  onUnmounted(() => clearInterval(timer))

  const { shop } = await useTinkerfundShop()
```
::

Once the component is mounted, the timer sets `moved` to the current time every minute unless the clock is pinned, and the countdown follows it; when the component unmounts, the timer stops.

### Why it's built this way

- **A composable keeps a timer and its cleanup together.** A live countdown needs a timer started on mount and stopped on unmount. `useTinkerfundClock` registers both, so a component that wants the time calls one function and never handles the timer. The cost: it can be called only while a component's setup runs. :file[layers/tinkerfund/app/composables/clock.ts]
- **TypeScript scripts get typed templates.** Vue's docs say a template's expressions get stricter type checking when its component's script is TypeScript. Every Terrarium component with code writes `<script setup lang="ts">`, so `pnpm typecheck` checks its template too ([Type checking](/t/glassbox/guide/verification/type-checking)). The cost: each prop's type is written out in `defineProps`. [Vue docs: Usage in Single-File Components](https://vuejs.org/guide/typescript/overview.html#usage-in-single-file-components).
- **Tinkerfund's composables carry its name.** Every one starts `useTinkerfund`, for the reason [Auto-imports](/t/glassbox/guide/nuxt-vue/auto-imports) gives.

### What to watch for

- **Register hooks before the first `await`.** In an async composable, Vue loses track of the calling component after an `await`, and a hook registered there is dropped, with only a warning in development. `useTinkerfundClock` in :file[layers/tinkerfund/app/composables/clock.ts] registers `onMounted` and `onUnmounted` first, then awaits, as above. A top-level `await` in `<script setup>` itself is safe: the compiler restores the component.
- **A module-level ref is shared by every visitor.** A `ref` created outside any function lives once per server process, so one request's value leaks into the next. State that belongs to a request goes in `useState`, [as the Nuxt docs advise](https://nuxt.com/docs/4.x/getting-started/state-management#best-practices), or in refs made during setup, as the Atlas's `provideAlmanac` does in :file[layers/atlas/app/composables/almanac.ts]. `useState` carries a value from the server to the browser ([Hydration](/t/glassbox/guide/nuxt-vue/hydration)).

## Try it in your project

In a Nuxt app, add `app/components/Percent.vue`:

```vue
<script setup lang="ts">
const props = defineProps<{ value: number; max?: number }>()
const percent = computed(() => Math.round((props.value / (props.max ?? 100)) * 100))
</script>

<template><p>{{ percent }}% done</p></template>
```

Use it in a page with `<Percent :value="3" :max="12" />`, which renders `25% done` with no import. Then give the page a `ref`: write `const n = ref(3)` in its script, pass `:value="n"`, and add `<button @click="n++">More</button>`. Each click redraws the text, and `percent` is worked out again only because `n` changed.
