When every page has to take the same first step, and getting it wrong is costly, a copy of that step in each page will one day differ from the others. A composable puts the step in one function. If every page calls it and none takes the step itself, the step is right in one place or wrong in one place.

Know Vue composables already? Skip to [In Terrarium](#in-terrarium).

## The concept

In Vue, a composable is a function that uses the Composition API to hold and reuse logic that has state, such as the current route or the position of the mouse. By convention its name starts with `use`. A component calls it from `<script setup>` and gets back what it returns, often refs it can read in its template.

Vue asks that a composable be called in `<script setup>` or `setup()`, and synchronously there: that is when Vue knows which component instance is running. [Nuxt's own composables](https://nuxt.com/docs/4.x/guide/concepts/auto-imports), such as `useRoute`, have the same need for the running app, so a composable that calls them inherits it. Nuxt also auto-imports every top-level file in `app/composables/`, so a page calls one without an import line.

A composable can also be a door. When a page may reach some data only after a check, the composable does the check and hands back only what passed. Pages that never do the check themselves can't do it differently.

Full reference: [Vue docs: Composables](https://vuejs.org/guide/reusability/composables.html)

## In Terrarium

Every page inside a Space, at `/t/<tenant>/<space>/…`, starts by asking which :term[Tenant] and :term[Space] the address names and which :term[Collections]{id="collection"} it may read. `useSpace` in :file[app/composables/space.ts] answers that:

::excerpt{path="app/composables/space.ts" lines="22-30"}
```ts
export function useSpace<T extends string>(tenant: T): SpaceContext<T> {
  const route = useRoute()
  const space = String(route.params.space)
  const resolved = resolveSpaceRoute(tenant, space, route.params.slug)
  if (!resolved) {
    throw createError({ statusCode: 404, statusMessage: `Unknown Tenant/Space: ${tenant}/${space}` })
  }
  return { ...resolved, space }
}
```
::

The composable does only the Nuxt part: it reads the route and turns a failed lookup into a 404. The lookup is `resolveSpaceRoute` in :file[shared/routing.ts], a plain function with no Nuxt in it. It reads only the requested Space's entry in the routing map, which the build writes from the manifests, and returns the keys of that Space's Collections: `pagesKey` for its pages and `collections` for the rest, with the page's `path` inside the Space. Because it is a plain function, :file[tests/unit/routing.spec.ts] tests it without starting Nuxt, including that it never names another Space's keys. The resolver is on the :term[Human-only]{id="human-only"} list; the composable, which only calls it, is not.

The Platform's catch-all page calls it with whatever Tenant the URL holds:

::excerpt{path="app/pages/t/[tenant]/[space]/[...slug].vue" lines="7-9"}
```ts
const route = useRoute()
const tenant = String(route.params.tenant)
const { space, path, atRoot, pagesKey, collections } = useSpace(tenant)
```
::

A Tenant's own pages pass their name as a literal, as the Journal's Skills page does with `useSpace('journal')`. The routing map has a precise type, and with a literal the keys come back typed for that Tenant: `collections.skills` exists and has the Skill Inventory's fields, with no cast. Each page then queries only those keys. A composable can build on it: Tinkerfund's `useTinkerfundSpace`, in :file[layers/tinkerfund/app/composables/shop.ts], calls `useSpace('tinkerfund')` and adds the shop's link helpers.

Pages above a Space don't use it. A Tenant's root page at `/t/<tenant>`, such as :file[layers/blog/app/pages/t/blog/index.vue], names each Space it shows and calls `resolveSpaceRoute` for it directly.

### Why it's built this way

- **One door.** Each :term[Collection]{id="collection"} is its own table ([One table per key](/t/glassbox/guide/nuxt-content/one-table-per-key)), so keeping Spaces apart means controlling which tables a page may query. One shared lookup gives one place to get right and one test that no Space reaches another's tables. The cost: every Space page must use it. ADR-0006 (:file[docs/adr/0006-runtime-routing-path-prefix.md]).
- **Testable resolver.** The lookup first lived in the catch-all page, where no test reached it and a type bug was found only by luck. It became a plain function, the resolver, that a unit test runs without Nuxt. It also serves a Tenant's root page, which can't use `useSpace` ([File routing](/t/glassbox/guide/nuxt-vue/file-routing) says why). :file[tests/unit/routing.spec.ts].
- **Copies drift.** Pages kept copying the same steps: read the address, look up the Space, 404 if none. `useSpace`, a composable (a reusable function a page calls), now holds them. Copies had drifted: one page hid a type error, and a Space front page showed a landing page for a missing Space.
- **Small reviewed core.** A resolver bug could show one Space's Documents in another, so a person merges any change to it ([The Human-only list](/t/glassbox/guide/terrarium-practice/human-only-list)). The composable decides nothing and keeps the Nuxt glue out of the resolver, so it merges like other code and the reviewed part stays small. The cost: even a type fix in the resolver waits for a human. ADR-0004 (:file[docs/adr/0004-objective-safety-gate.md]).

### What to watch for

- **The 404 covers the Space, not the Document.** `useSpace` throws only for an unknown Tenant or Space. A path with no Document in a known Space resolves fine, and the page decides what to show: below the Space root, the catch-all sets the 404 status itself when its query finds nothing.
- **A plain string widens the types.** The catch-all passes a `string`, so its keys are a union over every Tenant. In a Tenant's own page, pass the literal name, or the fields its template reads won't type-check.
- **Call it from setup.** It calls `useRoute`, so it needs the running Nuxt app: call it in a page's or component's `<script setup>`, or in a composable called from there, not in a click handler or a plain helper module.
- **Don't open a side door.** A page reaches another Space's keys only through `resolveSpaceRoute`, called once per Space, as the Blog's network footer does in :file[layers/blog/app/components/blog/Network.vue]. The Journal reads the routing map only for its Space names, never for keys. A key built by hand or read off the map skips the one check the tests cover.

## Try it in your project

Find a check that several of your pages repeat at the top, such as reading a locale from the route and rejecting one you don't support. Move the decision into a plain function you can unit-test, and the route reading and the 404 into a composable that calls it:

```ts
// app/composables/useLocale.ts
export function useLocale() {
  const locale = String(useRoute().params.locale)
  if (!isSupportedLocale(locale)) throw createError({ statusCode: 404 })
  return locale
}
```

Then replace each page's copy with `const locale = useLocale()`, and check that an unknown locale still gets a 404.
