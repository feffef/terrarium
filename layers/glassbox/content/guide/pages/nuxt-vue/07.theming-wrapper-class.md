A site's colours, fonts and spacing are used in hundreds of rules across dozens of components. Write each value into every rule and a change of palette means editing them all. Name each value once, as a CSS custom property on the element that wraps the page, and every component inside reads it from there.

Know CSS custom properties already? Skip to [In Terrarium](#in-terrarium).

## The concept

A [CSS custom property](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Cascading_variables/Using_custom_properties) is a property whose name starts with two dashes, such as `--accent: #356a4c`. A rule reads it with `var(--accent)`, or `var(--accent, teal)` to fall back to `teal` when it isn't set. Like `color`, a custom property set on an element is inherited by everything inside that element. Set on `:root`, it reaches the whole document; set on one class, it reaches only what that class wraps. A rule that sets it again on a narrower element, or inside a media query such as `prefers-color-scheme: dark`, overrides it there and below.

Vue's `<style scoped>` adds a data attribute to a component's elements and to its selectors, so the component's rules match only its own elements. That limits what a selector matches, not what an element inherits. A scoped component inside a themed wrapper reads the wrapper's custom properties with no extra code.

Vue uses custom properties for its own `v-bind()` in CSS too: a value bound to component state is compiled into a custom property, set on the component's root element.

Full reference: [Vue docs: SFC CSS Features](https://vuejs.org/api/sfc-css-features.html)

## In Terrarium

Each :term[Tenant] brings its own look, and each keeps it in a stylesheet in its layer, :file[layers/journal/app/assets/theme.css] for the Journal. A layer's stylesheet loads on every page of every Tenant ([a layer is not a sandbox](/t/glassbox/guide/nuxt-vue/layers)). The Journal sets its tokens on one class, `.jd`, and its rules for the page itself read them:

::excerpt{path="layers/journal/app/assets/theme.css" lines="8-19,56-61,66"}
```css
.jd {
  /* Palette — humus & foliage neutrals with a fern accent; earthy severity ramp.
     Tokens live on the wrapper so every child component inherits them. */
  --jd-ground: #f3f5ef;
  --jd-surface: #fbfcf9;
  --jd-surface-2: #ecf0e6;
  --jd-ink: #1a2420;
  --jd-muted: #586359;
  --jd-faint: #8a9488;
  --jd-line: #dbe0d5;
  --jd-accent: #356a4c;
  --jd-accent-bright: #4e9e6a;
  /* … */
  display: block;
  min-height: 100vh;
  margin: 0;
  background: var(--jd-ground);
  color: var(--jd-ink);
  font-family: var(--jd-serif);
  /* … */
}
```
::

Every Journal page in a Space wraps its template in that class, as `<main class="jd jd-doc">` in its Document page. A component under it, such as the dashboard's stat tile, reads the tokens in its own scoped style:

::excerpt{path="layers/journal/app/components/journal/StatTile.vue" lines="23-32"}
```vue
<style scoped>
.tile {
  background: var(--jd-surface);
  border: 1px solid var(--jd-line);
  border-radius: var(--jd-radius);
  padding: 1rem 1.1rem 1.05rem;
  position: relative;
  overflow: hidden;
  box-shadow: var(--jd-shadow);
}
```
::

Dark mode is the same tokens set again: a `@media (prefers-color-scheme: dark)` block redefines them on `.jd`, and no component changes. Tinkerfund gets the same result in one block, with CSS's `light-dark()` function in each token.

A wrapper class can also carry a narrower theme. Each Atlas :term[Space] is a biome, and its pages add a class named after the Space, which sets the room's paper colour and accents over the Atlas's base tokens:

::excerpt{path="layers/atlas/app/assets/theme.css" lines="64-71"}
```css
.atlas--canopy {
  --atlas-paper: #e6e6cf;
  --atlas-paper-2: #eff0dd;
  --biome-accent: #3f6b3e; /* leaf */
  --biome-accent-2: #b8952f; /* dapple gold */
  --biome-tint: rgb(63, 107, 62);
  --biome-tint-amount: 5%;
}
```
::

Not every Tenant puts its tokens on the wrapper. Some Tenants, such as the Blog and the Atlas, set them on `:root` and keep them apart by prefix, `--bl-` or `--atlas-`, while their rules still sit under a wrapper class such as `.bl`. Tinkerfund sets its tokens on a class it adds to `<body>` (:file[layers/tinkerfund/app/components/tinkerfund/shell/Shell.vue]), and on a second class, `.tf-tokens`, which the Platform's home page puts on Tinkerfund's tile (:file[app/components/HomeShowcase.vue]).

A Platform component can be themed the same way without knowing any Tenant. Mermaid diagrams read their colours from `--diagram-*` properties, listed in :file[app/utils/mermaid.ts], and the Journal maps them to its own tokens with `var()`.

### What to watch for

- **Outside the wrapper, no theme.** A component that renders outside the wrapper element, for example through `<Teleport>` to `<body>`, doesn't inherit the tokens and falls back to browser defaults. A class on `<body>`, as Tinkerfund uses, covers teleported content too.
- **A wrong name fails silently.** `var()` with a name nobody sets gives the fallback, or nothing, and the browser reports no error. A rule that reads `var(--acent)` when the token is `--accent` just gets no colour.
- **Unprefixed tokens on `:root` collide.** A token set on `:root` exists on every Tenant's pages. Give it the Tenant's prefix, or put it on the wrapper.
- **Map tokens with `var()`, not copies.** A token defined as `var(--jd-accent)` follows the dark-mode override; one defined as the same colour literally keeps the light value.

## Try it in your project

Pick one section of your app with its own look, such as an admin area. Move its colours into custom properties on a class, wrap the section's pages in it, and replace each colour in its components' scoped styles with `var(--…)`:

```css
.admin {
  --admin-surface: #ffffff;
  --admin-accent: #1f5fbf;
}
@media (prefers-color-scheme: dark) {
  .admin { --admin-surface: #13191d; --admin-accent: #8ab4ff; }
}
```

Switch your system to dark mode and check that the section follows with no component edited.
