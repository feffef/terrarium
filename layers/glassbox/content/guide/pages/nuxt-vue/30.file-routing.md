A site whose pages all share one layout needs only one page file: a catch-all that reads the address and fetches what it names. A site that wants a few of its pages to look different then needs a way to let a more specific file take over, without a maintained list of exceptions. Nuxt's file routing gives both.

Know Nuxt file routing already? Skip to [In Terrarium](#in-terrarium).

## The concept

Nuxt makes a route for every file in `app/pages/`. The file's path is the route's path: `about.vue` answers `/about`, and an `index.vue` answers its folder's own path, so `app/pages/index.vue` is `/`. A part of the name in square brackets is a parameter: `posts/[id].vue` answers `/posts/1` and `/posts/hello`, and the page reads the value from `useRoute().params.id`. Folder names work the same way, so `[tenant]/[space]/` holds two parameters.

A file named `[...slug].vue` is a catch-all. It matches every path below its folder, however deep, and its parameter holds the segments as an array: `/hello/world` gives `['hello', 'world']`. With no segment left, the parameter is absent, so the catch-all also answers its folder's own path when no `index.vue` sits beside it.

Several pages often match one address. Nuxt's routing is built on [Vue Router](https://router.vuejs.org/guide/essentials/route-matching-syntax), which ranks routes by how specific their path is, not by the order they were found in: a fixed segment beats a parameter, and a parameter beats a catch-all. So `posts/new.vue` answers `/posts/new` even though `posts/[id].vue` matches it too. Pages from every layer join the same ranking, as if they sat in one `app/pages/`.

To send the visitor somewhere else from code, a page calls `navigateTo()`. During server rendering it answers with a redirect; in the browser it moves to the new route. Await its result, or return it from a function such as route middleware, so that Nuxt applies the redirect. The call doesn't stop the code around it: the rest of `<script setup>` still runs.

Full reference: [Nuxt docs: pages/ directory](https://nuxt.com/docs/4.x/directory-structure/app/pages)

## In Terrarium

Every Terrarium site lives under `/t/<tenant>/<space>/…`. The platform, the code outside any layer, answers all of those addresses with one catch-all, `app/pages/t/[tenant]/[space]/[...slug].vue`. It turns the two parameters into one :term[tenant] and one :term[space] with `useSpace`, then opens a `useAsyncData` call whose first query reads that space's :term[document] at the remaining path ([Data fetching](/t/glassbox/guide/nuxt-vue/data-fetching)):

::excerpt{path="app/pages/t/[tenant]/[space]/[...slug].vue" lines="7-14"}
```vue
const route = useRoute()
const tenant = String(route.params.tenant)
const { space, path, atRoot, pagesKey, collections } = useSpace(tenant)
// …
const { data, status, error } = await useAsyncData(route.path, async () => {
  const page = await queryCollection(pagesKey).path(path).first()
```
::

`useSpace`, in :file[app/composables/space.ts], is the one lookup every page inside a space starts with. It is a Vue [composable](https://vuejs.org/guide/reusability/composables.html), a function a component calls from `<script setup>`: it reads the route, asks the resolver `resolveSpaceRoute` for that space's keys, and throws a 404 only when the tenant or space doesn't exist, not for a missing document. What the keys are, and why that keeps spaces apart, is in [Multi-tenant isolation](/t/glassbox/guide/nuxt-content/multi-tenant-isolation).

The slug may be missing, and then the same file renders each space's front page, where it lists the space's other collections. A tenant with no page files of its own still gets every address its :term[manifest] declares, plainly styled.

A tenant that wants its own look adds pages to its layer under `app/pages/t/<tenant>/`. Their first segment is the fixed name of the tenant where the catch-all has `[tenant]`, so they outrank it for that tenant's addresses and no other. The Journal's folder, :file[layers/journal/app/pages/t/journal/], shows three levels of it: `[space]/index.vue` takes each space's front page, `[space]/[...slug].vue` takes every other document, and fixed pages such as `[space]/skills.vue` outrank that `[space]/[...slug].vue`, the Journal layer's own catch-all. An override reads its space through the same `useSpace` as the platform's catch-all, with the tenant's name written in:

::excerpt{path="layers/journal/app/pages/t/journal/[space]/[...slug].vue" lines="18-23"}
```vue
const route = useRoute()
const { space, path, pagesKey } = useSpace('journal')

const { data: page, error } = await useAsyncData(route.path, () =>
  queryCollection(pagesKey).path(path).first(),
)
```
::

The bare `/t/<tenant>` matches no platform page, since the catch-all needs a space. A tenant answers it with an `index.vue` at the top of its folder, its root page. The Blog's shows one feed of every :term[persona]'s posts. The Journal's only sends the visitor on to its main space:

::excerpt{path="layers/journal/app/pages/t/journal/index.vue" lines="1-5"}
```vue
<script setup lang="ts">
// Tenant-root route (ADR-0016): journal has no front door of its own, so its root
// sends visitors to its main Space.
await navigateTo('/t/journal/current')
</script>
```
::

On the server that call answers `/t/journal` with a redirect, which the Journal's own [end-to-end test](/t/glassbox/guide/verification/testing) checks with `expectRedirect` in :file[layers/journal/tests/e2e/journal.spec.ts].

### Why it's built this way

- **Path prefix, not host.** Every request must reach one tenant's space, so the address starts with `/t/<tenant>/<space>/`. Subdomains need DNS setup and host-name code before a site works locally or in tests, and plain links and crawlers can't send a header. The cost: longer addresses, and a tenant wanting its own domain needs a new way in. ADR-0006 (:file[docs/adr/0006-runtime-routing-path-prefix.md]).
- **Overrides are files.** A tenant restyles addresses with more specific page files in its layer, not by registering them in its manifest or routing code. Nuxt's ranking picks the page, so the shared code that decides a request's space never changes; the override uses the same lookup. The cost: nothing lists overridden addresses. :file[layers/journal/app/pages/t/journal/].
- **One composable opens every space.** Pages copied the same steps (read the address, look up the space, 404 if none), and the copies drifted: one hid a type error, one showed a missing space a landing page. `useSpace` now holds the steps, so there is one place to get right. The cost: every space page must use it. ADR-0006 (:file[docs/adr/0006-runtime-routing-path-prefix.md]).
- **Each tenant answers its own root.** A root isn't a space; faking one as an empty space would put a contentless place into every list of spaces. An earlier platform page at `/t/[tenant]` skipped the shared lookup and picked whichever space came first. So each tenant answers its root from its own layer. The cost: a tenant without one gets a 404 there. ADR-0016 (:file[docs/adr/0016-tenant-root-layer-routes.md]).

### What to watch for

- **The 404 covers the space, not the document.** For a missing document, Nuxt matched the page, so the response is a 200 unless the page says otherwise. The catch-all calls `setResponseStatus(404)` when no document exists at the path, and the Journal's override repeats that check; an override without it answers a missing document with a 200.
- **Pass the tenant's name as a literal.** The catch-all passes a `string`, so its keys are a union over every tenant. In a tenant's own page, write the name, as in `useSpace('journal')`, or the fields its template reads won't type-check.
- **A fixed page hides a document at its path.** Once `[space]/skills.vue` exists, a document whose path is `/skills` in any of that tenant's spaces can no longer be reached: the fixed page outranks the catch-all, as above.
- **`navigateTo` doesn't end the script.** Even awaited, as The concept asks, it leaves the rest of `<script setup>` to run. The Journal's root page puts nothing after the call.
- **A root page needs its own test.** The smoke test in :file[tests/e2e/smoke.spec.ts] visits the space addresses it derives from the manifests, and no manifest knows about a root page. Each tenant tests its own, as the Journal does.

## Try it in your project

In a Nuxt app, add `app/pages/docs/[...slug].vue` that prints `useRoute().params.slug`, then `app/pages/docs/intro.vue`. Open `/docs/intro`, `/docs/a/b` and `/docs`, and see which file answers each. Add `app/pages/docs/[id].vue` too: `/docs/intro` still goes to `intro.vue`, `/docs/x` to `[id].vue`, and `/docs/a/b` to the catch-all.

File routing is the wrong tool when the routes don't come from files. An app with one screen can keep only `app.vue` and no `app/pages/`, and Nuxt then leaves Vue Router out of the bundle. Routes built from data, or matched in a way a file name can't spell, are added or changed with Nuxt's `pages:extend` hook or a `routes` function in `router.options.ts` ([Nuxt docs: Custom routing](https://nuxt.com/docs/4.x/guide/recipes/custom-routing)). A catch-all that looks its content up has a cost of its own: every address it matches, a mistyped one too, runs that query before the page can tell it is a 404.
