Left to its defaults, Dependabot opens one pull request for every dependency that has a newer version. Terrarium groups updates instead: its minor and patch npm updates share one group while a major npm update still arrives alone, and its GitHub Actions updates of every size share another. A 0.x minor joins the npm group, though an agent leaves it to a person like a major.

Know Dependabot groups already? Skip to [In Terrarium](#in-terrarium).

## The concept

Dependabot version updates are configured in `.github/dependabot.yml`. The file has `version: 2` and a list of `updates`. Each entry names one package :term[ecosystem] in `package-ecosystem`, with the `directory` or `directories` that hold its manifests, and a `schedule.interval` for how often to look. For GitHub Actions, the directory `/` covers `.github/workflows/` and an `action.yml` at the root.

By default each outdated dependency gets its own pull request. A `groups` entry names a rule, and every update that matches it is combined into a single pull request. `patterns` match dependency names, with `*` as a wildcard, and `update-types` limits a group to `major`, `minor` or `patch` releases. An update that matches several rules goes into the first; one that matches none still gets its own pull request.

`cooldown`, which the Actions entry below shows, delays version updates: a new release isn't considered until it is a set number of days old. A 3-day cooldown applies even when `cooldown` isn't set, and `default-days` changes it. It applies to version updates only, never to security updates.

Full reference: [GitHub Docs: Dependabot options reference](https://docs.github.com/en/code-security/reference/supply-chain-security/dependabot-options-reference)

## In Terrarium

In :file[.github/dependabot.yml], the npm entry has one group:

::excerpt{path=".github/dependabot.yml" lines="12-14"}
```yaml
    groups:
      npm-minor-patch:
        update-types: [minor, patch]
```
::

It takes every minor and patch update. A major update matches no rule and arrives as a pull request of its own. The Actions entry groups by name instead:

::excerpt{path=".github/dependabot.yml" lines="17-25"}
```yaml
  - package-ecosystem: github-actions
    directories: [/, /.github/actions/gate]
    schedule:
      interval: weekly
    cooldown:
      default-days: 3
    groups:
      github-actions:
        patterns: ["*"]
```
::

`patterns: ["*"]` takes every update, whatever its size. For Actions, `/` reads only `.github/workflows/` and a root `action.yml`; the second directory adds `.github/actions/gate`, where the :term[gate]'s composite action lives: a bundle of CI steps kept in a file of its own ([Composite actions](/t/glassbox/guide/git-github/composite-actions)). Both entries, npm and Actions, set `default-days: 3`, which restates the default cooldown.

A :term[routine] runs the `dependabot-sweep` :term[skill] (:file[.agents/skills/dependabot-sweep/SKILL.md]). That scheduled run, the sweep, reviews each Dependabot pull request and turns a major update into an issue. It lands an npm minor or patch pull request only when its checks are green, no release notes show a breaking or deprecation change that affects Terrarium, it adds no direct dependency and no bumped package is 0.x. ADR-0004 (:file[docs/adr/0004-objective-safety-gate.md]) counts a 0.x minor as a major, and [Semantic Versioning](https://semver.org/#spec-item-4) lets anything change while the major version is 0.

The sweep lands a pull request with :file[scripts/github/merge-pr.ts], whose `dependabotBumpRefusal` applies the Dependabot exception in ADR-0004. For an Actions pull request, the sweep posts its verdict and a person merges it. `merge-pr.ts` never checks a Dependabot pull request against the :term[human-only] list, and `.github/dependabot.yml` isn't on that list.

### Why it's built this way

- **The npm group holds the bumps an agent may merge, plus 0.x minors.** ADR-0004 (:file[docs/adr/0004-objective-safety-gate.md]) lets an agent merge a minor or patch npm bump but keeps a major, a 0.x minor included, for a person. The npm group takes every minor and patch. The cost: a group merges or waits as one, so one unsafe bump holds back the rest. :file[.github/dependabot.yml].
- **Actions updates wait for a person.** A Dependabot pull request for Actions edits workflow and action files, and `merge-pr.ts` refuses a Dependabot pull request that changes any file other than `package.json` and its lockfile, `pnpm-lock.yaml`. The cost: even an Actions patch waits for someone. :file[.agents/skills/dependabot-sweep/SKILL.md].

### What to watch for

- **A group is a pull request, not a review.** One grouped pull request can hold many updates; read every bumped package's release notes before you merge it.
- **`/` doesn't reach a nested action.** For the `github-actions` ecosystem, list every folder that holds an `action.yml` under `directories`.

## Try it in your project

Add one `groups` entry with `update-types: [minor, patch]` to the npm entry of your `.github/dependabot.yml`:

```yaml
version: 2
updates:
  - package-ecosystem: npm
    directory: /
    schedule:
      interval: weekly
    groups:
      npm-minor-patch:
        update-types: [minor, patch]
```

To see it work without waiting for the schedule, open your repository's **Insights** tab, then **Dependency graph**, then **Dependabot**; next to the manifest, click **Recent update jobs**, then **Check for updates** ([GitHub Docs: Re-running Dependabot jobs](https://docs.github.com/en/code-security/how-tos/secure-your-supply-chain/manage-your-dependency-security/re-run-dependabot-jobs)). Then list Dependabot's pull requests with the [GitHub CLI](https://cli.github.com/manual/):

```sh
gh pr list --search "author:app/dependabot"
```

The minor and patch updates arrive as one pull request whose title names the group, such as `bump the npm-minor-patch group`, while each major still arrives alone.
