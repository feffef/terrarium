When an agent works through a person's GitHub account, attribution, the mark that says an agent wrote a post, has to travel in the content. Terrarium puts a link to the session that wrote it on each agent post and commit.

Know git hooks and trailers already? Skip to [In Terrarium](#in-terrarium).

## The concept

The identity a platform shows comes from the credential that made the request. When an agent uses a person's token, the login, the avatar and GitHub's `author_association` all name that person. The only place left for attribution is the text itself. Such a mark is a claim, not proof: anyone who can type can copy it.

Commit messages have a standard place for such facts. A trailer is a `Key: value` line at the end of the message, in a block after a blank line, as with `Signed-off-by: Alice <alice@example.com>`. Tools read trailers without parsing the free text above them, and [`git interpret-trailers`](https://git-scm.com/docs/git-interpret-trailers) adds or parses them for you. GitHub reads one trailer itself: each `Co-authored-by: name <email>` line credits a co-author on the commit ([GitHub Docs: Creating a commit with multiple authors](https://docs.github.com/en/pull-requests/how-tos/commit-changes/creating-a-commit-with-multiple-authors)).

A git hook can add a trailer for you. Hooks are programs that git runs at fixed points, from `.git/hooks` unless the `core.hooksPath` setting names another folder. The `commit-msg` hook runs during `git commit` with the path of the file that holds the proposed message; it may edit that file in place, and a nonzero exit aborts the commit (`--no-verify` skips it). Hooks aren't copied when you clone a repository ([Pro Git: Git Hooks](https://git-scm.com/book/en/v2/Customizing-Git-Git-Hooks)), so a project that wants one in every clone commits it to a tracked folder and points `core.hooksPath` there.

Claude Code adds attribution of its own: by default a `Co-Authored-By` trailer on each commit it makes and a "Generated with Claude Code" line in each pull request description, plus, from a cloud session, the session's link. Its [`attribution` setting](https://code.claude.com/docs/en/settings-reference#attribution) changes or hides each part.

Full reference: [Git documentation: githooks](https://git-scm.com/docs/githooks)

## In Terrarium

Every agent write names its :term[session]{id="session"}, in one shape for GitHub bodies and one for commits; ADR-0017 (:file[docs/adr/0017-provenance-footer-on-agent-authored-content.md]) is the rule.

**On a GitHub body**, such as an issue, a PR description, a comment or a review, the first line is a header. :file[scripts/lib/provenance-header.ts] builds it:

::excerpt{path="scripts/lib/provenance-header.ts" lines="30-32"}
```ts
export function provenanceHeader(label: string, sessionUrl: string): string {
  return `${BOT_ICON} [${label}](${sessionUrl})`
}
```
::

It renders as a robot icon and a link such as `🤖 [Claude](https://claude.ai/code/session_…)`. A cloud session's link ends in `session_<id>`; a local session has no web page, and its link carries the raw session id in that place.

**On a commit**, the message ends with two trailers, built by :file[scripts/session/commit-trailer.ts]:

::excerpt{path="scripts/session/commit-trailer.ts" lines="132-134"}
```ts
export function provenanceFooter(modelName: string, sessionUrl: string): string {
  return [coAuthorLine(modelName), sessionLine(sessionUrl)].join('\n')
}
```
::

The first is a `Co-Authored-By:` line naming the model at `noreply@anthropic.com`, the second a `Claude-Session:` line holding the session's link.

**Posts are checked before they go.** :file[scripts/hooks/github-provenance-guard.ts] is a guard, Terrarium's name for a [blocking hook](/t/glassbox/guide/hooks/blocking-hooks). It runs as a `PreToolUse` hook, one that Claude Code runs before a tool call. :file[.claude/settings.json] attaches it by name to most GitHub tools that publish authored text, and to `Bash` calls that run `gh api` or `curl` to GitHub's REST API.

The tool that edits a posted comment isn't listed: an edit to a posted comment passes unchecked. Nor is the merge tool listed: agents merge through :file[scripts/github/merge-pr.ts], which normally sends no commit message of its own. When the owner tells a session in-session to merge a human-only PR, the flag `--owner-approved` puts the owner's quoted words in the merge commit.

The tools it checks sit in one registry, `GITHUB_PROVENANCE_TOOLS`, a row for each GitHub tool that publishes authored text. Each name comes from the tool's real schema, read with `ToolSearch`, which loads tool definitions ([MCP servers](/t/glassbox/guide/claude-code/mcp-servers)), never guessed.

The guard finds this session's id from the session's environment or transcript, and reads the mark only at its slot, the one place the guard looks: line one of a body, or the last `Claude-Session:` trailer of a commit made through the GitHub tools. It denies the call when the mark is missing, when it names another session, or when this session's link sits anywhere but its slot. It also denies the call when it can't find this session's id or can't read a shell command's body. A refusal holds the exact line to paste when the id is known, and otherwise says to report that instead of typing an id.

**Local commits are repaired, not checked.** `pnpm install` runs `git config core.hooksPath .githooks` from :file[package.json]'s `postinstall`, and :file[.githooks/commit-msg] hands the message file to `commit-trailer.ts`:

::excerpt{path=".githooks/commit-msg" lines="15-23"}
```sh
root=$(git rev-parse --show-toplevel 2>/dev/null) || exit 0
# …
common_dir=$(git rev-parse --git-common-dir 2>/dev/null) || exit 0
main_root=$(cd "$(dirname "$common_dir")" && pwd) || exit 0
"$main_root/node_modules/.bin/tsx" "$root/scripts/session/commit-trailer.ts" "$1" >/dev/null 2>&1 || exit 0
exit 0
```
::

The hook runs the script from the main checkout's `node_modules`. A linked [git worktree](/t/glassbox/guide/git-github/git-worktrees), a second working folder of the same repository, has none of its own. The script finds the session from its environment or its transcript, appends the footer when a trailer is missing, corrects a wrong session link or unknown model name when both trailers are present, and leaves the message alone when it finds no session, as on a person's own commit. Every path through the hook ends in `exit 0`, and an exit of 0 never aborts a commit.

**Reading the mark back.** Code that asks whether an agent wrote a post calls `hasAuthorshipMarker` in :file[scripts/lib/provenance-header.ts], or its wrapper `isAiAuthored` in :file[scripts/github/check-triage-drift.ts]. It accepts any of these marks:

- the header, only at the very start of the text;
- the older `Co-Authored-By` footer with a `noreply@anthropic.com` address, anywhere;
- Claude Code's own "Generated with Claude Code" line, anywhere.

A session link elsewhere doesn't count. The merge script asks a narrower question: does a verdict, the review comment an agent posts before it merges, carry a header naming this very session ([Pull requests](/t/glassbox/guide/git-github/pull-requests))?

### Why it's built this way

- **A mark in the content.** The login and `author_association` show the owner for every agent write, and agents misread who did what. A bot account would fix the login, but GitHub access is a connection set up outside the repo. Any reader can check a line in the text. The cost: anyone can type it, so it never decides who may direct an agent. ADR-0017 (:file[docs/adr/0017-provenance-footer-on-agent-authored-content.md]).
- **A header, not a footer.** GitHub posts first carried the mark as a footer, but Claude Code adds its own footer on the last line, and agents dropped theirs. Line one belongs to nobody else. The cost: a body copied from another session brings that session's header along. ADR-0017 (:file[docs/adr/0017-provenance-footer-on-agent-authored-content.md]).
- **Block posts.** A refusal at the call teaches the format where a written rule went unread ([Claude Code hooks](/t/glassbox/guide/hooks/hooks#why-its-built-this-way) says why). A guard that added the header was set aside: a hook [can rewrite its call](https://code.claude.com/docs/en/hooks#pretooluse-decision-control), but a post is public at once, so a wrong rewrite can't be fully undone. The cost: a session that can't find its own id can't post at all. ADR-0017 (:file[docs/adr/0017-provenance-footer-on-agent-authored-content.md]).
- **Repair local commits.** A commit hook can fix the message itself, so blocking would buy nothing, and a hook bug would stop every commit. The cost: when the hook fails, the commit lands unmarked. ADR-0017 (:file[docs/adr/0017-provenance-footer-on-agent-authored-content.md]).
- **Reading is wider than writing.** Old posts are never rewritten, so the reader keeps accepting every mark ever written, or old agent posts would read as human. It still refuses a bare session link: a pipeline that skips agent posts would otherwise drop a person's comment that merely pasted a link. The cost: the old shapes stay in the reader for good. :file[scripts/lib/provenance-header.ts].

### What to watch for

- **Check that the trailer landed**, as :file[docs/agents/git-conventions.md] asks. The hook gives up without a word when the main checkout has no `node_modules` or `node` isn't on the path, and `git commit --no-verify` skips it. Plain `git log -1` shows a commit's trailers; `--oneline` hides them.
- **A copied body carries the old header.** Rewriting an issue body from another session's text keeps that session's line one, and the guard denies it as a mismatch. Replace the header with your own before you post.
- **Only the link is checked.** The label in brackets is free text; write `Claude` there if you must not name the model. The link must be exactly this session's, taken from the deny message or your own environment, never typed from memory.
- **Line one or nothing.** A header lower down is denied, and quoting another agent's post doesn't make your post look like theirs.
- **The guard reads command text.** A `gh api` call inside a script goes unchecked, which is why agents write through the MCP tools ([MCP servers](/t/glassbox/guide/claude-code/mcp-servers)).

## Try it in your project

Commit a `.githooks/commit-msg` that adds a trailer only when your agent's session is known, and make it executable with `chmod +x .githooks/commit-msg`:

```sh
#!/bin/sh
[ -n "$AGENT_SESSION_URL" ] || exit 0
git interpret-trailers --in-place --if-exists=doNothing \
  --trailer "Agent-Session: $AGENT_SESSION_URL" "$1" || exit 0
```

Run `git config core.hooksPath .githooks`, make one commit with `AGENT_SESSION_URL` set and one without, and compare the two full messages with `git log -2`.
