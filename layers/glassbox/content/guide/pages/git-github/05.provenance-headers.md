When agents work through a person's own GitHub account, every issue, comment and commit they make shows that person as the author. Terrarium puts the missing fact into the content instead: each agent write names the session that made it, as a header on a GitHub post and a trailer on a commit.

Know git hooks and trailers already? Skip to [In Terrarium](#in-terrarium).

## The concept

Git runs hooks, programs in a hooks directory, at fixed points in its work. The directory is `.git/hooks` unless the `core.hooksPath` setting names another one. A hook that isn't executable is ignored.

The `commit-msg` hook runs during `git commit` and `git merge`. Git passes it one argument, the path of the file that holds the proposed commit message. The hook may edit that file in place, which is how a project brings every message into one format, and a nonzero exit aborts the commit. `git commit --no-verify` skips it.

A trailer is a `Key: value` line at the end of a commit message, in a block after a blank line, as with `Signed-off-by: Alice <alice@example.com>`. Tools read it back without parsing the free text above it, and [`git interpret-trailers`](https://git-scm.com/docs/git-interpret-trailers) adds or parses trailers for you.

Hooks live outside the tracked files, so a clone doesn't bring a project's hooks along ([Pro Git: Git Hooks](https://git-scm.com/book/en/v2/Customizing-Git-Git-Hooks)). A project that wants one hook in every clone commits it to a tracked folder and points `core.hooksPath` there.

Full reference: [Git documentation: githooks](https://git-scm.com/docs/githooks)

## In Terrarium

Agents post to GitHub through the owner's own connection, and the login and `author_association` read `OWNER` on every agent write ([Trust tiers and fork safety](/t/glassbox/guide/git-github/trust-tiers)). The mark that tells them apart has one shape per surface.

A GitHub body, such as an issue, a PR description, a comment or a review, opens with a header line. :file[scripts/provenance-header.ts] builds it:

::excerpt{path="scripts/provenance-header.ts" lines="30-32"}
```ts
export function provenanceHeader(label: string, sessionUrl: string): string {
  return `${BOT_ICON} [${label}](${sessionUrl})`
}
```
::

A commit message ends with two trailers, a `Co-Authored-By:` line and a `Claude-Session:` line holding the session's URL. :file[scripts/provenance-footer.ts] builds them.

:file[scripts/github-provenance-guard.ts] checks each post before it goes. It is a guard on each GitHub write tool, and on a shell `gh api` or `curl` call that sends a body. It denies a body that lacks this session's header, names another session, puts the right link in another shape or can't be read, and it denies the post too when it can't tell which session it is in. Its message holds the exact line to paste. [Guards that fail closed](/t/glassbox/guide/claude-code/guards) shows how such a guard blocks.

The `commit-msg` hook adds or corrects the trailer by editing the message file. `pnpm install` runs `git config core.hooksPath .githooks` from :file[package.json]'s `postinstall`, and :file[.githooks/commit-msg] hands the message file to `provenance-footer.ts`:

::excerpt{path=".githooks/commit-msg" lines="15-23"}
```sh
root=$(git rev-parse --show-toplevel 2>/dev/null) || exit 0
# …
common_dir=$(git rev-parse --git-common-dir 2>/dev/null) || exit 0
main_root=$(cd "$(dirname "$common_dir")" && pwd) || exit 0
"$main_root/node_modules/.bin/tsx" "$root/scripts/provenance-footer.ts" "$1" >/dev/null 2>&1 || exit 0
exit 0
```
::

The script finds the session from its environment or its transcript. It appends the trailers when they are missing, corrects a `Claude-Session:` line that names another session or a `Co-Authored-By:` line with a wrong model name, and leaves the message alone when it finds no session, as on a person's own commit. Every path through the hook ends in `exit 0`. A commit made through the GitHub API tools runs no local hook; the guard checks those messages for the trailer.

Code that asks whether an agent wrote something calls `hasAuthorshipMarker` in `provenance-header.ts`. It accepts the header at the very start of the text, the older two-line footer, and the "Generated with Claude Code" line that Claude Code adds itself; a session link elsewhere in the prose doesn't count. The `auto-triage` sweep uses it to skip an issue whose last comment is already an agent's, and :file[scripts/check-triage-drift.ts] uses it to find agent comments whose claimed label change never happened.

### Why it's built this way

The header, the trailer, and blocking one while repairing the other: ADR-0017 (:file[docs/adr/0017-provenance-footer-on-agent-authored-content.md]).

### What to watch for

- **Check that the trailer landed.** The hook gives up quietly when the main checkout has no `node_modules` or `node` isn't on the path, so read `git log -1` after a commit; :file[docs/agents/git-conventions.md] says so too.
- **A copied body carries the old header.** Rewriting an issue body from another session's text keeps that session's line one, and the guard denies it as a mismatch. Replace the header with your own before you post.
- **Line one or nothing.** The header counts only at the start of the body, so a post that quotes another agent's post isn't read as written by that agent, and a header placed lower down is denied.
- **`--no-verify` skips the hook.** A commit made that way lands without a trailer, and nothing blocks it.

## Try it in your project

Commit a `.githooks/commit-msg` that adds a trailer only when your agent's session is known, then run `git config core.hooksPath .githooks` from a setup script:

```sh
#!/bin/sh
[ -n "$AGENT_SESSION_URL" ] || exit 0
git interpret-trailers --in-place --if-exists=doNothing \
  --trailer "Agent-Session: $AGENT_SESSION_URL" "$1" || exit 0
```

Make it executable, commit once with the variable set and once without, and compare the two messages.
