Work an agent can't finish in one session has to wait somewhere a later session will find it. In Terrarium that place is a GitHub issue, and a label on the issue usually says what may happen to it next: wait for more facts, go to an agent, or go to a person.

Know GitHub labels already? Skip to [In Terrarium](#in-terrarium).

## The concept

A label is a name, a color and a description that you attach to issues, pull requests and discussions. Labels belong to one repository, and once a label exists there, it can go on any issue in that repository. Every new repository starts with a default set, such as `bug`, `enhancement`, `question` and `wontfix`, which you can edit or delete. Anyone with write access can create, edit or delete a label; anyone with triage access can apply one.

You can [filter an issue list by label](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/filtering-and-searching-issues-and-pull-requests#filtering-issues-and-pull-requests-by-labels), so a label can stand for a step in your own workflow, such as "ready to build", and the filter shows the queue for that step. GitHub doesn't know the labels mean that. Nothing stops an issue from carrying two steps at once or none at all, so the rules for moving between steps are yours to write down and keep.

Full reference: [GitHub Docs: Managing labels](https://docs.github.com/en/issues/using-labels-and-milestones-to-track-work/managing-labels)

## In Terrarium

Work that has to wait, such as a proposal, a bug or a follow-up, goes in an issue, and the open issues are the work queue. Its states come from the `triage` :term[Skill] of an outside Skill pack ([Skill packs](/t/glassbox/guide/skill-pack/skill-packs)): `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human` and `wontfix`. :file[docs/agents/triage-labels.md] maps each to the label string used here and says what it means.

The `triage` Skill, in :file[.agents/skills/triage/SKILL.md], also gives each issue one category, `bug` or `enhancement`, and expects one category and one state on every triaged issue. Moving an issue to `ready-for-agent` normally comes with an Agent Brief: a comment that states the behavior wanted and how to tell it is done, without file paths (:file[.agents/skills/triage/AGENT-BRIEF.md]).

A person runs `triage` on the issues they pick. :file[.agents/skills/auto-triage/SKILL.md] is the sweep: one unattended pass, started by a person, that applies `triage`'s rules to every issue that needs attention. It scans every open issue and in-scope external PR except a `wayfinder:map`, the index issue of a big piece of work that the `wayfinder` Skill plans as a map of child tickets, and picks the ones that need attention:

::excerpt{path=".agents/skills/auto-triage/SKILL.md" lines="26-37"}
```md
For everything else, fetch the **most recent comment** and check who wrote it:

- **No state label, `needs-triage`, or no comments.** Always eligible, whoever
  filed it or commented last, except an on-hold spec or sub-issue
  (`docs/agents/issue-tracker.md`'s Specs), which follows the next bullet.
- **Any other state** (`needs-info`, `ready-for-human`, even `ready-for-agent`)
  **is eligible when its most recent comment is human-authored.**
  Every agent comment carries an ADR-0017 mark, so a comment without one is human (`isAiAuthored`). Never go by the author or `author_association`: agents post as the owner.

Skip any other ticket whose most recent comment is already AI's own. That keeps
repeated sweeps **idempotent**: once an agent answers the human's comment,
the ticket stays quiet until a human writes again, whatever its label reads.
```
::

The mark is the session header every agent post carries ([Commit and PR attribution](/t/glassbox/guide/git-github/attribution)). A person can pass `full-sweep` to drop the skip on an agent's last comment for one run. The sweep also skips a `wayfinder` ticket that is claimed or blocked. It labels, comments and closes; it never builds. It closes only an issue that is already done or a duplicate.

The sweep sends a :term[Public] author's issue to `ready-for-human`. Which issues a sweep that a :term[Trusted] user started may mark `ready-for-agent` on its own: ADR-0022 (:file[docs/adr/0022-autonomous-triage-sweep.md]).

Agents then take work from the `ready-for-agent` queue. :file[.agents/skills/clear-backlog/SKILL.md] takes the issues a default sweep picks up and adds every open `ready-for-agent` issue; only when that set is empty does it run the full sweep instead. It leaves out any issue with a `wayfinder:*` label, and carries each to a merged PR, a closed issue or a question for the owner; it rechecks a `ready-for-agent` issue before it builds. Big work planned with `wayfinder` keeps its own map and ticket labels next to these, and the `wayfinder` Skill drives those tickets with the owner.

### Why it's built this way

- **The label is the approval.** A Trusted user approves a build by labelling its issue `ready-for-agent`, and the label stays the approval until someone removes it, so the queue itself holds the approval an agent builds on ([Human-in-the-loop agents](/t/glassbox/guide/terrarium-practice/human-in-the-loop)). ADR-0003 (:file[docs/adr/0003-agent-operating-model-and-governance.md]).
- **A sweep keeps the queue moving.** An unlabelled issue is invisible to the agents that build and the backlog grows faster than a person can label it, so a sweep a Trusted user starts may mark a Trusted-authored issue whose design the repo settles ready on its own ([Human-in-the-loop agents](/t/glassbox/guide/terrarium-practice/human-in-the-loop)). ADR-0022 (:file[docs/adr/0022-autonomous-triage-sweep.md]).
- **Public issues wait for a person.** Public text can try to steer an agent, and no check can tell whether an agent obeyed it. A Public issue reaches `ready-for-agent` only after a Trusted user approves it ([Author trust](/t/glassbox/guide/git-github/trust-tiers)). The cost: even once approved, a PR built from it waits for a person to merge. ADR-0020 (:file[docs/adr/0020-requester-trust-tiers.md]).
- **Guests skip the wait while the owner allows it.** While the owner runs the guest Skills, a guest's confirmation on their own issue puts it in the `ready-for-agent` queue with no per-issue approval, and stopping those Skills ends the exception ([Human-in-the-loop agents](/t/glassbox/guide/terrarium-practice/human-in-the-loop)). ADR-0023 (:file[docs/adr/0023-guest-driven-demo-pipeline.md]).

### What to watch for

- **A label write replaces the whole set.** Setting labels through the GitHub MCP tools sends the full list the issue ends with, so a call that names only the new state drops the category and any `wayfinder:` label; :file[docs/agents/github-integration.md] lists this trap.
- **A comment can claim a move that never happened.** An agent may write "moved to `ready-for-agent`" and fail to change the label. :file[scripts/github/check-triage-drift.ts] lists the issues whose most recent agent comment claims a label the issue doesn't carry. It is a command you run yourself. It checks a capped number of open issues, which its argument raises, and knows only a short list of phrasings, so a claim worded another way slips past.
- **Ready doesn't mean still needed.** An issue can wait long enough for other work to solve it, so :file[docs/agents/issue-tracker.md] has an agent check for a merged fix before it builds a `ready-for-agent` issue.
- **A missing label doesn't always mean untriaged.** An issue with no label is usually one nobody has triaged yet, but a spec on hold carries none either: its body says it is on hold (:file[docs/agents/issue-tracker.md]), and the sweep picks it up only when a person wrote its latest comment.

## Try it in your project

Create the state labels `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human` and `wontfix` in your repository and write one short doc that says, for each, who may set it and what an agent may do with an issue that carries it. Then tell your agent to take work only from the `ready-for-agent` filter, and to move an issue it can't finish to `needs-info` or `ready-for-human` with a comment that says why.
