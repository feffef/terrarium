Several agents editing one checkout at once trip over each other: one switches the branch under another. A git worktree gives each agent a working folder of its own, while they all share one repository.

Know git worktrees already? Skip to [In Terrarium](#in-terrarium).

## The concept

A worktree is a second working folder of the same repository, with its own files and its own checked-out branch, sharing one history. `git worktree add <path> <branch>` creates one, `git worktree list` shows them all, and `git worktree remove <path>` deletes one. Two worktrees can't check out the same branch at once.

A worktree is a fresh checkout, so it has none of the main folder's untracked files, such as installed dependencies. Uncommitted work in it shows only in that folder's `git status`, and deleting the folder deletes that work.

[Claude Code](https://code.claude.com/docs/en/worktrees#isolate-subagents-with-worktrees) can give each [subagent](/t/glassbox/guide/agents/subagents) a fresh worktree. It creates the worktree under `.claude/worktrees/`, from the default branch unless the settings say to branch from the current `HEAD`, the commit a worktree has checked out, and removes it when the subagent finishes without changes. Such a subagent keeps the instruction files the main conversation started it with: it doesn't load the `CLAUDE.md` or `.claude/rules/` at the worktree's root, even when the worktree's branch changes them.

Full reference: [Git docs: git-worktree](https://git-scm.com/docs/git-worktree)

`EnterWorktree` and `ExitWorktree` move the whole session into a worktree, not one subagent, and the Skill allows them only when the user asks for a worktree. :file[.gitignore] leaves `.claude/worktrees/` out of git. A subagent's brief has it check that its `HEAD` is the commit the brief names.

Worktrees are swept before a session ends. `pnpm check:worktrees` and the close step of :file[scripts/session/log-session.ts] both run :file[scripts/git/check-worktrees.ts]. It lists every worktree with `git worktree list` and runs `git status` in each. The rule it applies:

::excerpt{path="scripts/git/check-worktrees.ts" lines="159-161"}
```ts
    const uncommitted = s.dirty
    const unpushed = (s.unpushedCount ?? 0) > 0
    const needsRescue = !s.isPrimary && (uncommitted || unpushed)
```
::

The main folder never fails. A linked worktree fails on any uncommitted change, untracked files included. It also fails on a commit that no remote-tracking branch holds, the local copy of a remote's branch, such as `origin/main`. Cases that hold nothing to rescue, such as a worktree whose `HEAD` is already in `origin/main`, are reported but excused; the script's `EXCUSALS` table lists them.

At close, `log-session.ts` also removes each clean linked worktree whose `HEAD` is already in `origin/main`. It keeps the one it runs in and any whose `HEAD` is a commit on `origin/main`'s first-parent line, which may be a just-added worktree with no commit of its own. While a linked worktree holds work to rescue, it refuses a :term[session log], the session's closing record, whose status is completed or partial. It accepts a log marked in-review, blocked or abandoned, and adds a :term[Friction] to it.

The script also won't write a session log from a linked worktree; [Session logs](/t/glassbox/guide/terrarium-practice/session-logs#in-terrarium) shows how it tells.

### Why it's built this way

- **One checkout per agent.** Parallel agents in one checkout raced on branches. A worktree per agent that touches git ends the race. :file[.agents/skills/dispatch-subagents/SKILL.md].
- **Check the start commit first.** A new worktree can start from an older `main`, so an agent that trusted it would build on stale code. That check closes the gap. The cost: one more step in every brief. :file[.agents/skills/dispatch-subagents/SKILL.md].
- **Inside the project folder.** [Path-specific rules](/t/glassbox/guide/claude-code/path-scoped-rules) load only for files under the project folder, so an agent in a worktree beside the repo edited files with none of their rules loaded. Hand-made worktrees go under `.claude/worktrees/`, where Claude Code already puts a subagent's. The cost: the folder must stay git-ignored. :file[.agents/skills/dispatch-subagents/SKILL.md].
- **A sweep for lost work.** "Commit before you stop" as an instruction failed: one agent ended its turn waiting on a background check, then died silently once resumed. An instruction can't catch an agent that never returns, so a script reads git's own list of worktrees and fails on left-behind work. It shows the loss; it can't prevent it. :file[scripts/git/check-worktrees.ts].

### What to watch for

- **A fresh worktree has no `node_modules`.** Run `pnpm install` there before `pnpm gate:scoped` or any test.
- **A squash-merged worktree with leftover changes still fails the sweep.** A squash merge lands the PR as one new commit, so the worktree's `HEAD` never reaches `main` and the leftovers aren't excused; remove the worktree once its PR merges.

## Try it in your project

Add `.claude/worktrees/` to your `.gitignore`. Run `git worktree add .claude/worktrees/try-it -b try-it`, change a file there, and run `git status` in both folders: each sees only its own change. Then run `git worktree list`. `git worktree remove .claude/worktrees/try-it` refuses while that change is there: commit or discard it first, or add `--force`, which discards it. The `try-it` branch stays behind; `git branch -D try-it` deletes it.
