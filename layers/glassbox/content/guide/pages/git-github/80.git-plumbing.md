`git commit` records what you staged, on the branch you have checked out. A script that must commit one file to another branch, while your files, staged changes and branch stay exactly as they are, can't use it. Git's plumbing, the low-level commands that `git commit` is built from, can build that commit on a temporary index and push it to a branch by its id.

Know git plumbing already? Skip to [In Terrarium](#in-terrarium).

## The concept

Git splits its commands in two. Porcelain, such as `git add`, `git commit` and `git checkout`, is for people. Plumbing is for scripts: its input, output and options are meant to stay much more stable than porcelain's, which may change to suit users.

Plumbing works on git's objects, each named by a hash of its content. A blob holds one file's contents. A tree lists file names and modes, each pointing at a blob or another tree, the way a folder holds files. A commit points at one tree, at its parent commits, and records an author, a committer and a message. The index, also called the staging area, is a file listing the paths and blobs the next tree will hold.

Five commands build a commit by hand:

- [`git read-tree <tree-ish>`](https://git-scm.com/docs/git-read-tree) loads a tree-ish, a tree or anything that names one, such as a branch, into the index, without changing any file in your working tree.
- [`git hash-object -w <file>`](https://git-scm.com/docs/git-hash-object) stores a file's contents as a blob and prints its id; the file may sit outside the working tree.
- [`git update-index --add --cacheinfo <mode>,<blob>,<path>`](https://git-scm.com/docs/git-update-index) puts that blob into the index at a path, whether or not the path exists on disk. Mode `100644` is a plain file.
- [`git write-tree`](https://git-scm.com/docs/git-write-tree) writes the index out as a tree and prints its id.
- [`git commit-tree <tree> -p <parent> -m <message>`](https://git-scm.com/docs/git-commit-tree) creates a commit from that tree and prints its id. Each `-m` becomes its own paragraph. No branch moves.

`read-tree`, `update-index` and `write-tree` read and write the index named by the `GIT_INDEX_FILE` environment variable, `.git/index` when it is unset. Set it to a temporary file before `read-tree` and your real index stays as it was; none of the five writes a file in your working tree, and the objects they create go inside `.git`, which a checkout never shows.

The new commit is on no branch yet. [`git push`](https://git-scm.com/docs/git-push) takes a refspec `<src>:<dst>`, where the source can be any commit expression, a bare id included, and the destination is a ref name, such as `refs/heads/main`, the full name of the branch `main`. `git push origin <id>:refs/heads/main` sends that commit with any objects the remote lacks, and makes the remote's `main` point at it. Unforced, the remote accepts only a fast-forward, a commit that descends from the branch's current tip, its newest commit.

For everyday commits, porcelain is the better choice: it is shorter and runs your hooks, the scripts git runs at set moments. Plumbing pays off in a script that must commit without touching a checkout.

Full reference: [Git docs: Low-level commands (plumbing)](https://git-scm.com/docs/git#_low_level_commands_plumbing)

## In Terrarium

A :term[session log], the record each session writes of its work, goes straight to `main` without a PR. :file[scripts/session/log-session.ts] builds that commit in `buildLogCommit`, on a throwaway index:

::excerpt{path="scripts/session/log-session.ts" lines="280,282-285,294"}
```ts
  const idxEnv = { ...env, GIT_INDEX_FILE: indexFile }
  // …
    git(['read-tree', base], cwd, { env: idxEnv }) // start from main's tree
    const blob = git(['hash-object', '-w', absPath], cwd).trim()
    git(['update-index', '--add', '--cacheinfo', `100644,${blob},${relPath}`], cwd, { env: idxEnv })
    const tree = git(['write-tree'], cwd, { env: idxEnv }).trim()
    // …
    const commit = git(['commit-tree', tree, '-p', base, '-m', subject, '-m', trailer], cwd, { env }).trim()
```
::

`env` holds the process's own environment plus the author and committer variables, from `commitEnv` (below), and `idxEnv` adds `GIT_INDEX_FILE` to it for the three commands that use the index. `base` is `<remote>/main`, from the function's `remote` argument, which the command line sets to `origin` unless `--remote` names another; it is not the session's branch: the index starts as `main`'s tree, gains the one log file, and the commit's parent is `main`'s tip. The index file sits in a fresh temporary folder, deleted when the build ends. The second `-m` carries the commit's attribution trailer, a last paragraph naming the session, built by `provenanceFooter` in :file[scripts/session/commit-trailer.ts].

Before returning the commit, the function runs `git diff --name-only` between `base` and the new commit, and throws unless the only path changed is the log's own.

Git needs an author and a committer for `commit-tree`. `commitEnv` sets both from the configured `user.name` and `user.email`, and falls back to `terrarium-agent` and `agent@terrarium.local` when they are unset.

`pushWithRetry` pushes the bare commit id, the commit's id on its own with no branch name, to `main`:

::excerpt{path="scripts/session/log-session.ts" lines="334-337"}
```ts
      git(['fetch', remote, 'main'], cwd)
      const commit = buildLogCommit(relPath, absPath, remote, cwd)
      git(['push', remote, `${commit}:refs/heads/main`], cwd)
      return commit
```
::

If any step of an attempt fails, it waits, fetches `main` again and rebuilds the commit with the new tip as its parent, which makes the push a fast-forward again, a few times with growing waits, then gives up with the last error.

### Why it's built this way

- **The log commit ignores the checkout.** A session's checkout may hold unrelated, uncommitted work, and `git commit` would commit from the current branch. Building from `main`'s tree on a throwaway index leaves none of it in the commit. The cost: the script must build every part of the commit itself, trailer included. ADR-0009 (:file[docs/adr/0009-session-logs-commit-directly-to-main.md]).
- **A check before the push.** The owner's credential the script pushes with could push anything to `main`. Diffing the built commit and refusing any other path narrows that to the log alone. The cost: that limit lives only in this one script, which changes only through a PR that passes the :term[gate]. ADR-0009 (:file[docs/adr/0009-session-logs-commit-directly-to-main.md]).
- **Rebuild, don't rebase.** Parallel sessions land logs on `main` at once, so a push can be rejected. Each log has its own file name, so rebuilding on the fresh tip only changes the parent and never conflicts. The cost: a `main` that keeps moving can outlast every retry, and the push fails. :file[scripts/session/log-session.ts].
- **A missing git identity doesn't block the log.** A fresh autonomous session may have no git identity configured, and `commit-tree` refuses to run without one. A fixed fallback name and email let it still commit its log. The cost: such a commit names a placeholder author. :file[scripts/session/log-session.ts].

### What to watch for

- **Never use `commit-tree` to rewrite an existing commit.** It can re-parent the chain and drop commits. :file[docs/agents/git-conventions.md] forbids it, like any other history rewriting. Fix the tip commit with `git commit --amend -F <file>` instead.
- **Without `GIT_INDEX_FILE`, `read-tree` replaces your real index.** Your staged changes drop out of it: a modified file shows as unstaged, a new one as untracked.
- **No hooks run.** Git runs the `commit-msg` hook for `git commit` and `git merge`, not for `commit-tree`; add any trailer yourself ([Commit and PR attribution](/t/glassbox/guide/git-github/attribution)).
- **An unpushed commit is on no branch.** Until a ref points at it, it is unreachable, and `git gc` may delete it once it is old enough. Keep its id, or give it a branch with `git branch <name> <id>`.

## Try it in your project

In a scratch repository (`git init -b main`) with one tracked file, `a.txt`, committed on `main` and a git identity set (`user.name` and `user.email`), change `a.txt` but don't stage it, then run:

```sh
export GIT_INDEX_FILE=$(mktemp -d)/index
git read-tree HEAD
blob=$(echo "a note" | git hash-object -w --stdin)
git update-index --add --cacheinfo "100644,$blob,note.txt"
tree=$(git write-tree)
commit=$(git commit-tree "$tree" -p HEAD -m "Add a note")
unset GIT_INDEX_FILE
git status --short
git log --oneline
git diff --name-only HEAD "$commit"
```

`unset GIT_INDEX_FILE` points git back at your real index, so `git status` still shows only your unstaged change, `git log` doesn't list the new commit, and the diff names only `note.txt`. Run `git init --bare ../remote.git` and `git push ../remote.git "$commit:refs/heads/main"`: the bare repository's `main` now holds `a.txt` and `note.txt`.
