Several agents editing one checkout at once trip over each other: one switches the branch under another, or commits another's half-finished files. A git worktree gives each agent a working folder of its own, while they all share one repository.

Know git worktrees already? Skip to [In Terrarium](#in-terrarium).

## The concept

A worktree is a second working folder of the same repository, with its own files and its own checked-out branch, sharing one history. `git worktree add <path> <branch>` creates one, `git worktree list` shows them all, and `git worktree remove <path>` deletes one. Two worktrees can't check out the same branch at once.

A worktree is a fresh checkout, so it has none of the main folder's untracked files, such as installed dependencies. Uncommitted work in it shows only in that folder's `git status`, and deleting the folder deletes that work.

[Claude Code](https://code.claude.com/docs/en/worktrees#isolate-subagents-with-worktrees) can give each [subagent](/t/glassbox/guide/claude-code/subagents) a fresh worktree. It creates the worktree under `.claude/worktrees/`, from the default branch unless the settings say to branch from the current `HEAD`, and removes it when the subagent finishes without changes.

Full reference: [Git docs: git-worktree](https://git-scm.com/docs/git-worktree)

## In Terrarium

Terrarium keeps its worktrees under `.claude/worktrees/`, inside the project folder, which :file[.gitignore] leaves out of git. Claude Code puts a subagent's worktree there, and the dispatch :term[Skill], :file[.agents/skills/dispatch-subagents/SKILL.md], tells agents to put one made by hand there too. Its brief has the agent check that the new worktree's `HEAD` is the commit it names, then run `pnpm install`.

Worktrees are swept before a session ends. `pnpm check:worktrees` runs :file[scripts/git/check-worktrees.ts], which reads `git worktree list --porcelain` and decides for each worktree whether work would be lost:

::excerpt{path="scripts/git/check-worktrees.ts" lines="159-167"}
```ts
  const findings: Finding[] = states.map((s) => {
    const uncommitted = s.dirty
    const unpushed = (s.unpushedCount ?? 0) > 0
    const needsRescue = !s.isPrimary && (uncommitted || unpushed)
    const excusedBy: Excusal | null = !needsRescue
      ? null
      : s.headMergedToMain
        ? 'merged-to-main'
        : s.contentPushed && !unpushed ? 'content-pushed' : null
```
::

A linked worktree fails when it has uncommitted changes, untracked files included, or commits on no remote. The main folder never fails. Two cases are excused: a worktree whose `HEAD` is already in `origin/main`, and one whose uncommitted files equal a commit that is already pushed.

The session log refuses worktrees too: :file[scripts/session/log-session.ts] won't write a log from a linked worktree, which it detects when git's `--git-dir` differs from its `--git-common-dir`.

### Why it's built this way

- **One checkout per agent.** Parallel agents in one checkout raced on branches. A worktree per agent that touches git ends the race. The cost: each worktree needs its own install. :file[.agents/skills/dispatch-subagents/SKILL.md].
- **Excused, not just failed.** The sweep once failed on worktrees with nothing to rescue: a review agent's checkout left a stale index in a worktree whose work had merged, and another agent moving a branch made pushed work look uncommitted. So it excuses both cases. The cost: a squash-merged branch's `HEAD` is not in `main`, so it still fails. :file[scripts/git/check-worktrees.ts].
- **A sweep for lost work.** "Commit before you stop" as an instruction failed: one agent ended its turn waiting on a background check, then died silently once resumed. An instruction can't catch an agent that never returns, so a script reads git's own list of worktrees and fails on left-behind work. It shows the loss; it can't prevent it. :file[scripts/git/check-worktrees.ts].

### What to watch for

- **One git command per shell call.** Inside a worktree, Claude Code refuses a shell command when it can't tell from the text that every git command in it stays in that worktree. Plain, separate commands pass.
- **Make your own worktrees under `.claude/worktrees/`.** A worktree outside the project folder misses the project's [path-scoped rules](/t/glassbox/guide/claude-code/path-scoped-rules) when an agent reads its files.

## Try it in your project

Run `git worktree add ../try-it -b try-it` (a folder of your own; an agent's belongs inside the project, as above), change a file there, and run `git status` in both folders: each sees only its own change. Then run `git worktree list`, and remove the extra folder with `git worktree remove ../try-it`.
