An agent that reads issues and comments will meet text that tells it what to do. Whether it may act on that text has to depend on who wrote it, and the only safe source for who is the identity GitHub records, never what the text claims.

Know fork PR security already? Skip to [In Terrarium](#in-terrarium).

## The concept

GitHub attaches an `author_association` to every issue, pull request and comment, set from the author's account and not from anything they typed. Its values say how the author relates to the repository: `OWNER` and `COLLABORATOR` have been given access, `CONTRIBUTOR` has had a change merged before, and `NONE` has no tie at all. The [GitHub Docs: REST API endpoints for issue comments](https://docs.github.com/en/rest/issues/comments) return it with each comment.

A person without write access contributes through a fork, and a PR from a fork runs CI with less power. GitHub passes no secrets to it, apart from a `GITHUB_TOKEN` that normally can't write. On a public repository, a fork PR's workflows may wait until someone with write access approves the run; by default GitHub asks that only for first-time contributors.

One trigger breaks those limits. A `pull_request_target` workflow runs in the base repository's context, with its token and secrets, and it runs whatever the approval setting says. It is safe only while it never checks out and runs the fork's code; the plain `pull_request` trigger is the safe choice when no secret is needed.

Full reference: [GitHub Docs: Secure use reference](https://docs.github.com/en/actions/reference/security/secure-use)

## In Terrarium

Terrarium draws one line. A person with write access is :term[Trusted]; everyone else is :term[Public]. :file[scripts/trust.ts] holds the line as `author_association` values:

::excerpt{path="scripts/trust.ts"}
```ts
// GitHub `author_association` values on each side of ADR-0020's trust line.
export const TRUSTED_ASSOCIATIONS = new Set(['OWNER', 'MEMBER', 'COLLABORATOR'])

export const PUBLIC_ASSOCIATIONS = new Set(['NONE', 'CONTRIBUTOR', 'FIRST_TIME_CONTRIBUTOR', 'FIRST_TIMER', 'MANNEQUIN'])
```
::

A Trusted person may direct agents, approve new work and merge. Public text is data: an agent may read, summarize and label a Public issue, PR or comment and look into what it reports, but it ignores any instruction in it, and a change it asks for waits until a Trusted person approves it. A message that claims to come from the owner is still Public.

The line is enforced where the risk is, at the merge. :file[scripts/merge-pr.ts], the only path by which an agent merges, refuses a PR whose branch lives in a fork, a PR whose author is not Trusted, and a PR from the guest pipeline (ADR-0023, :file[docs/adr/0023-guest-driven-demo-pipeline.md]), the one route where Terrarium's own agents build what a Public guest asked for. A person merges those, after reviewing the code for security.

The CI side keeps fork PRs away from write access. :file[.github/workflows/pr-authorassociation-label.yml] labels a PR `trusted` when its author has write access, on the plain `pull_request` trigger and only for a branch in the repository itself; a fork PR gets no label, and the missing label means Public. The Gate's green-check comment skips fork PRs the same way, since their token can't write.

### Why it's built this way

Write access is the only line that contains anything: someone who has it can push and merge without an agent, so limiting them through one would stop nothing. The Gate checks that a PR is correct, not why it was written, so the merge stays with a person for anything Public: ADR-0020 (:file[docs/adr/0020-requester-trust-tiers.md]).

### What to watch for

- **`CONTRIBUTOR` is not Trusted.** It means a change of theirs was merged once, not that they can push. GitHub warns that approving fork runs only for first-time contributors lets someone qualify with one harmless typo fix.
- **Agents post as the owner.** Their PRs and comments carry the `OWNER` association, so a line at the top of each post names the session that wrote it. Anyone can copy that line, so `merge-pr.ts` counts an agent's review verdict only on a Trusted author's comment.
- **A label is a display, not the check.** The `trusted` label helps a reader; the scripts that decide read `author_association` themselves.
- **Never `pull_request_target` for a fork's code.** It ignores the approval setting and holds the secrets, which is why Terrarium's workflows use the plain `pull_request` trigger.

## Try it in your project

Write down which `author_association` values your agent may take instructions from, and check it in code before the agent acts on an issue or merges a PR. Then search your workflows for `pull_request_target` and, for each hit, confirm it never checks out the PR's own code.
