A type checker only checks the files its config names. A Nuxt app has code the app never loads, such as scripts, tests and the config that runs at build time, and Nuxt's own type check doesn't look at it. A second checker for that code closes the gap, as long as every file lands in one of the two.

Know Nuxt's type checking already? Skip to [In Terrarium](#in-terrarium).

## The concept

The TypeScript compiler checks a *program*: the files a `tsconfig.json` names with its `include` and `files` lists, plus whatever they import, under that file's compiler options. A file no program names, and nothing imports, is never checked, and nothing reports it. A glob that matches nothing is not an error while another glob in the list still matches something, so a renamed folder can drop out of a check without a sound. The [TSConfig reference](https://www.typescriptlang.org/tsconfig/) documents every option.

Nuxt doesn't check types when you run `nuxt dev` or `nuxt build`, for speed. `nuxt typecheck` runs `vue-tsc`, the TypeScript checker that also reads `.vue` files, against the tsconfig files Nuxt generates in `.nuxt/`. Those cover the app: its `app/` folder, its layers, its `shared/` code and its config files. You don't edit them by hand, since Nuxt rewrites them; you add to them from `nuxt.config.ts` with the `typescript.tsConfig` option.

Code that runs in plain Node, outside the app, needs different settings, such as Node's own types instead of the browser's. The usual answer is a second tsconfig with its own `include` list, checked by a plain `tsc -p` run.

Full reference: [Nuxt docs: TypeScript](https://nuxt.com/docs/4.x/guide/concepts/typescript)

## In Terrarium

`pnpm typecheck` in :file[package.json] runs both programs, one after the other:

::excerpt{path="package.json" lines="15-15"}
```json
    "typecheck": "nuxt typecheck && tsc -p tsconfig.node.json",
```
::

The first is Nuxt's. It covers each :term[Tenant]'s layer, its `app/` and its `nuxt.config.ts`, with no help. It can't see a Tenant's manifest, `tenant.config.ts`, which only loads at build time, so :file[nuxt.config.ts] adds one include for the manifests. The same block turns type checking off for `nuxt dev` and `nuxt build`; the check runs in the :term[Gate]'s :term[Floor] instead.

The second program is :file[tsconfig.node.json]. It checks the code that runs under Node and `tsx`: the scripts, `shared/`, every unit test, the helper scripts of Skills, and `content.config.ts`, which Nuxt evaluates at build time rather than compiling into the app:

::excerpt{path="tsconfig.node.json" lines="46-55"}
```json
  "include": [
    "scripts/**/*.ts",
    "shared/**/*.ts",
    "tests/unit/**/*.ts",
    "layers/*/tests/unit/**/*.ts",
    // A Skill's helper scripts and their unit tests (#1603).
    ".agents/skills/*/scripts/**/*.ts",
    ".agents/skills/*/tests/unit/**/*.ts",
    "content.config.ts"
  ],
```
::

Its options suit Node: Node's types, and imports that name a sibling file by its `.ts` path, as `tsx` runs them. Nuxt registers the `#routing` and `#catalog` aliases only for the app, so this file repeats them in its `paths`, pointing at the type files `nuxt prepare` writes. Both programs keep an incremental build cache, which CI keeps between runs.

Since a glob that matches nothing fails silently, :file[tests/unit/typecheck-coverage.spec.ts] reads the two configs and fails if the manifest include matches no real manifest, or if `content.config.ts` leaves the second program.

### Why it's built this way

Type checking the manifests, and the test that guards it: ADR-0018 (:file[docs/adr/0018-tenant-layers-under-layers-directory.md]). The type check as a Gate step: ADR-0004 (:file[docs/adr/0004-objective-safety-gate.md]).

### What to watch for

- **Some files are in neither program.** The end-to-end specs need Nuxt's and the browser's libraries, so :file[tsconfig.node.json] leaves them out, and Nuxt's program doesn't include them either. Two unit specs that test browser code are excluded the same way; they check their contract when they run.
- **Two files share a name.** Nuxt also generates a `.nuxt/tsconfig.node.json`, for `nuxt.config.ts` and the files outside its other contexts. Terrarium's :file[tsconfig.node.json] at the root is a different file, and only `pnpm typecheck` runs it.
- **An alias lives in three places.** A new `#` alias that Node code imports must be added to Nuxt, to :file[tsconfig.node.json] and, for tests, to :file[vitest.config.ts].
- **The root :file[tsconfig.json] extends the legacy `.nuxt/tsconfig.json`.** The Nuxt docs recommend the newer per-context files and say the legacy one will be removed in a future version.

## Try it in your project

For each tsconfig your type check runs, list the files it covers with `npx tsc --listFilesOnly -p <tsconfig>`, and search the lists for your scripts and tests. Any folder in none of them is code nothing checks.
