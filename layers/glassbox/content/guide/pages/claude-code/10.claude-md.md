Every :term[session] starts knowing nothing about the project. `CLAUDE.md` is read at the start of every session, so it is where the instructions every session needs belong, and nothing else.

Know `CLAUDE.md` already? Skip to [In Terrarium](#in-terrarium).

## The concept

Claude Code loads `CLAUDE.md` into every session at the start, from the directory it starts in and each one above it, and the project root's again after the conversation is compacted (summarized to fit the context window); a `CLAUDE.md` in a subdirectory loads once Claude works on a file there. You write it in plain Markdown: build commands, conventions, where things live, "always do X" rules. Claude reads it as context, not as enforced configuration. It tries to follow each line, and it follows short, concrete, consistent lines best.

So the docs send everything else elsewhere. A procedure, or an instruction that matters for only one part of the code, goes in a :term[skill] or a path-specific :term[rule]. Something that must happen at a fixed point whatever Claude decides, such as checking every shell command before it runs, goes in a hook: a handler, usually a shell command, that Claude Code itself runs at that point.

A first `CLAUDE.md` in your own project's root can be this small:

```md
# CLAUDE.md

- Run `npm test` before you commit.
- API handlers live in `src/api/handlers/`.
- Before you change the database schema, read `docs/migrations.md`.
```

Full reference: [Claude Code docs: How Claude remembers your project](https://code.claude.com/docs/en/memory)

## In Terrarium

Every Terrarium session, whether a person started it or a schedule did, begins with :file[CLAUDE.md]. It opens with the house style: write the least code and the fewest words that stay exact. Everything after that is short sections of instructions every session needs.

The section that does most of the work names *when* to read each doc rather than copying the doc in. A trigger binds a doc to an action:

::excerpt{path="CLAUDE.md" lines="24-28"}
```md
- **Before your first git command** beyond the read-only `status`, `diff`,
  `show`, `ls-tree`, `cat-file`, `grep` and `ls-files`, or `log`/`blame` used to
  draw a conclusion: `docs/agents/git-conventions.md`.
- **Before your first GitHub operation** (`mcp__github__*` tool or `gh`):
  `docs/agents/github-integration.md`.
```
::

The docs themselves sit in :file[docs/agents/], and only the sessions that reach a trigger read its doc. Rules and skills stay out of `CLAUDE.md`, which only points to them. Instructions about particular files are rules in :file[.claude/rules/]. Claude Code loads a rule with no `paths` field at session start, and a rule with `paths` when an agent reads or edits a file they match. The summary of each :term[ADR] is a rule too. Procedures are skills in :file[.agents/skills/].

For some triggers, :file[scripts/hooks/read-first-hint.ts] also points to the doc at the first matching call, such as a session's first git command beyond the read-only ones or its first GitHub call. It is a hint: a hook that adds a pointer beside the call's result and never blocks the call; [Hook-added context](/t/glassbox/guide/hooks/hook-added-context#why-its-built-this-way) shows how, and why.

### Why it's built this way

- **Short on purpose.** Every session reads all of `CLAUDE.md`, often skimming, and it had grown with rules, incident stories and copies of other docs. A :term[prune trial] cut it to rules that came from a serious problem and have no other home. The cost: an old mistake can return. The :term[frictions]{id="friction"} later sessions log catch it. ADR-0027 (:file[docs/adr/0027-prune-trials.md]).
- **Triggers, not topics.** Agents mostly skipped a read-first list grouped by topic and a line to read every ADR, so edits missed the ADRs that bound them. Each entry is now a trigger tied to an action: "before you do X, read Y". Lines tied to a file became rules, for the reason [Path-specific rules](/t/glassbox/guide/claude-code/path-scoped-rules) gives.

### What to watch for

- **Loaded is not obeyed.** A line can load and still be skipped. Where a slip is costly, Terrarium backs the line with something that runs: a hint or a guard (a hook that adds advice or refuses a call, see [Claude Code hooks](/t/glassbox/guide/hooks/hooks)), or the :term[gate].
- **Each incident tempts a new line.** Lines added after every mistake bury the ones that matter. Terrarium tests a line by removing it in a :term[prune trial]; the open trials are listed in :file[.agents/prune-trials.yml].
- **A path-specific rule can't order a step.** It loads only after its file is touched, so it can't say "before you touch it". A "before you do X" instruction stays in `CLAUDE.md`, however file-bound it looks. ADR-0029 (:file[docs/adr/0029-instructions-load-with-the-files-they-govern.md]).

## Try it in your project

Find the doc your agent most often forgets. Add one line to your `CLAUDE.md` that names the action and the doc ("Before you change the schema: read `docs/migrations.md`"), then delete any paragraph of `CLAUDE.md` that only repeats that doc.
