A Skill says what a job does. Something else has to say when it runs. Claude Code has several timers, and they differ in where they run and how long they last. Terrarium keeps the *what* in the repo and every *when* outside it.

Know Routines and `/loop` already? Skip to [In Terrarium](#in-terrarium).

## The concept

A **Routine** is a saved prompt with one or more repositories and connectors, run on Anthropic's cloud. Each run is a full cloud session on a fresh clone, so it works with your laptop closed. A trigger starts it: a schedule, an HTTP call to its endpoint, or a GitHub event such as a new pull request. You create one at claude.ai/code/routines or with `/schedule` in the CLI. A run doesn't stop for permission prompts: it runs commands and uses the Skills committed to the repo on its own. Pushes go to a branch prefixed `claude/` unless the prompt says otherwise.

**Scheduled tasks** live inside one open session instead. [`/loop`](https://code.claude.com/docs/en/scheduled-tasks) runs a prompt again and again while the session stays open:

```text
/loop 5m check whether the deploy finished
/loop check whether CI passed and address any review comments
```

With an interval, the prompt runs on a fixed schedule. Without one, Claude picks the next wait after each run and schedules it with the `ScheduleWakeup` tool. Underneath, `CronCreate`, `CronList` and `CronDelete` manage the tasks, and you can ask in plain words too: "remind me at 3pm to push the release branch". A task fires only between turns, only while the session runs, and a recurring one expires after seven days. A scheduled fire runs only Skills that Claude may start on its own; a Skill with `disable-model-invocation: true` arrives as plain text.

The Desktop app adds a third kind, scheduled tasks that run on your own machine.

Full reference: [Claude Code docs: Automate work with routines](https://code.claude.com/docs/en/routines)

## In Terrarium

Terrarium's scheduled jobs are Skills that a :term[Routine] starts. The Skill, in :file[.agents/skills/], holds everything the run does. The Routine lives in a claude.ai account, outside git, and holds only the timer. The :term[Skill Inventory] grades such a Skill's importance `routine`, so [its page](/t/journal/current/skills) shows which Skills the schedules drive.

A scheduled Skill says that it is scheduled, and never how often. The `digest` Skill opens like this:

::excerpt{path=".agents/skills/digest/SKILL.md" lines="15-17"}
```md
> **Command-only — follow the steps.** A scheduled Routine or a human runs
> `/digest`; `disable-model-invocation: true` keeps a session from invoking it
> unprompted.
```
::

A timer once leaked into the repo, in a Skill Inventory entry, so a check now holds the line there. :file[scripts/validate-skill-cadence.ts] runs in `pnpm validate:content` and fails any Skill Inventory sentence that pairs "Routine" with a cadence word such as "weekly" or "every 2 hours":

::excerpt{path="scripts/validate-skill-cadence.ts" lines="70-79"}
```ts
export function findCadenceViolations(text: string): { sentence: string; match: string }[] {
  const out: { sentence: string; match: string }[] = []
  for (const sentence of sentencesOf(text)) {
    if (!ROUTINE_RE.test(sentence)) continue
    CADENCE_RE.lastIndex = 0
    const m = CADENCE_RE.exec(sentence)
    if (m) out.push({ sentence, match: m[0] })
  }
  return out
}
```
::

Terrarium's scheduled Skills turn model invocation off, so no session starts one unasked. A session fired by a Routine or `/loop` then can't start one through the Skill tool. The Skills a Routine or `/loop` fires say so and tell the session what to do instead, as `guest-intake` does:

::excerpt{path=".agents/skills/guest-intake/SKILL.md" lines="19-23"}
```md
**`disable-model-invocation` above is deliberate** (ADR-0023: neither Skill
starts itself). A session fired by a Routine or `/loop` cannot invoke
this Skill via the Skill tool; that hard refusal is expected, not something to
route around. Follow this doc's steps directly as instructions instead (issue
#568).
```
::

Inside a session, Terrarium waits without `/loop`. A session that must check a PR's CI hours later schedules a check-in with the cloud host's `send_later` tool, which delivers a message back into the same session (:file[docs/agents/pr-workflow.md], step 3). `ScheduleWakeup` belongs to `/loop` alone: called outside one, its wakeup arrives as an unwanted turn that can re-run the session's whole prompt. :file[scripts/loop-only-tool-guard.ts] denies it unless the session's transcript shows a `/loop`, and its message names what to use instead.

### Why it's built this way

Why a schedule lives in a Routine and never in its Skill: ADR-0005 (:file[docs/adr/0005-skill-model.md]). What a scheduled run may change, and how starting one approves its work: ADR-0003 (:file[docs/adr/0003-agent-operating-model-and-governance.md]). Why `guest-intake` never starts itself: ADR-0023 (:file[docs/adr/0023-guest-driven-demo-pipeline.md]).

### What to watch for

- **The check covers one Collection.** Only Skill Inventory entries are scanned for a timer. A Skill, a doc or a page that says how often a Routine runs passes the check and goes stale the first time someone changes the schedule.
- **Session state can vanish on resume.** :file[docs/agents/environment-caveats.md] records a `/loop` or `CronCreate` job gone after a session resumed, with no error. Check that it is still there before you rely on it.
- **A Routine's run may not show as a turn.** A scheduled task that wakes an existing session can fire without a visible turn. The same caveats doc says to check the task's last run before you decide it didn't fire.

## Try it in your project

Pick a chore you repeat, such as a weekly dependency check. Write it as a Skill with `disable-model-invocation: true`, then create a Routine whose prompt runs that Skill. Keep the schedule in the Routine alone, and check that nothing in your repo says when it runs.
