An agent can't follow an instruction it never sees, and a `CLAUDE.md` that holds every instruction about every file grows too long to follow. A path-scoped rule puts an instruction in front of the agent when it works on the files the instruction is about.

Know path-scoped rules already? Skip to [In Terrarium](#in-terrarium).

## The concept

Claude Code reads each Markdown file in a project's `.claude/rules/` folder, including its subfolders, as a rule. A rule without a `paths` field loads at the start of every session, like `CLAUDE.md`. A rule whose frontmatter lists `paths` loads only when Claude works with a file that one of its globs matches: when it reads, writes or edits that file with its own tools, or views it with a simple shell read such as `cat` on that one file.

```md
---
paths:
  - "src/api/**/*.ts"
---
# API handlers

- Validate every request body before you use it.
```

`paths` is the only frontmatter field Claude Code reads. It ignores any other field without an error, and removes the frontmatter before the rule reaches Claude's context.

Full reference: [Claude Code docs: Path-specific rules](https://code.claude.com/docs/en/memory#path-specific-rules)

## In Terrarium

Terrarium gives each instruction one home, chosen by what it is about. An instruction about certain files is a :term[Rule] in :file[.claude/rules/] whose `paths` match those files. An instruction every session needs, or one tied to an action such as a commit or a PR, stays in :file[CLAUDE.md], because no glob can match an action. For example, :file[.claude/rules/tenant-layers.md] matches each Tenant layer's `nuxt.config.ts`, `tenant.config.ts` and `app/` folder, so an agent editing a :term[Tenant] learns that a layer's CSS loads on every page.

Every ADR has a summary rule too, `adr-NNNN.md`. It gives the ADR's key parts as instructions and says when to read the whole ADR. Its `paths` list the files the ADR governs, so the decision arrives when an agent works on something it binds. Only a summary whose ADR binds every session has no `paths`, and it loads at session start.

A summary is a copy of its ADR, and copies drift. So each one carries a second frontmatter field:

::excerpt{path=".claude/rules/adr-0002.md" lines="1-7"}
```md
---
adr: c3ee98a43b3d
paths:
  - "layers/*/tenant.config.ts"
  - "shared/manifest.ts"
  - "shared/expand.ts"
---
```
::

`adr` is a short hash of the ADR file. Claude Code ignores the field, so it costs no context. :file[scripts/validate-adr-rules.ts] recomputes every hash as part of `pnpm validate:content`, a step of the :term[Gate]. When an ADR changes, the check fails until someone re-reads its summary, updates it if the decision changed, and stamps the new hash with `--write`. The same script fails any other rule that has no `paths`.

Two hooks fill the gaps where Claude Code loads no rule. Running a :term[Skill] reads no file, so :file[scripts/skill-rules-hint.ts] adds the rules whose `paths` name that Skill's folder. A piped or chained shell command is not a simple read, so :file[scripts/bash-rules-hint.ts] adds the rules for the files such a command read. :file[.claude/settings.json] wires both in, and both fail open: an error adds nothing and never blocks the call.

### Why it's built this way

Which instructions become rules, which stay in `CLAUDE.md`, and why each summary is re-checked when its ADR changes: ADR-0029 (:file[docs/adr/0029-instructions-load-with-the-files-they-govern.md]).

### What to watch for

- **A rule can't order a step.** Why, and where such steps go instead: [CLAUDE.md as the every-session contract](/t/glassbox/guide/claude-code/claude-md#what-to-watch-for).
- **Read with the Read tool.** It always loads a file's rules. Terrarium's shell hook is a backstop, not the main path.
- **Keep rules short, and let globs be broad.** A rule a few lines long costs little where it doesn't apply. A long instruction stays in its doc, and the rule states the goal and points there.
- **A rule change waits for a person.** Every file in `.claude/rules/` is on the :term[Human-only] list, so an agent may edit a rule but not merge the change.

## Try it in your project

Find one line in your `CLAUDE.md` about a particular set of files. Move it into a file in `.claude/rules/` whose `paths` match those files, and delete the line from `CLAUDE.md`.
