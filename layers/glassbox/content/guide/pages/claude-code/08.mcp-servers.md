An agent that can only read files and run commands can't file an issue or review a pull request unless someone writes glue for each system it should reach. MCP is one plug for all of them: a system that speaks it offers its actions as tools, and the agent calls them like its own.

Know MCP already? Skip to [In Terrarium](#in-terrarium).

## The concept

The [Model Context Protocol](https://modelcontextprotocol.io/introduction) (MCP) is an open standard for connecting an AI tool to outside systems. An MCP server offers a set of tools, and Claude Code connects to it as a client. You add a server with `claude mcp add`. By default it is private to you and this project, kept in `~/.claude.json`. With `--scope project` it goes in a `.mcp.json` file at the project's root, which you commit so everyone gets the same servers:

```json
{
  "mcpServers": {
    "tracker": {
      "type": "http",
      "url": "https://tracker.example.com/mcp"
    }
  }
}
```

Each tool gets a full name, `mcp__<server>__<tool>`, such as `mcp__tracker__create_issue`. Permission rules and hook matchers use that full name. In a hook matcher, `mcp__tracker__.*` matches every tool from one server; a bare `mcp__tracker` is compared as an exact string and matches nothing.

Tool definitions cost context, so by default Claude Code defers them: a session starts with only each tool's name and each server's instructions, and Claude loads a tool's definition with the `ToolSearch` tool before it calls it. A result too large for the context is saved to a file, and Claude reads it from there.

Full reference: [Claude Code docs: Connect Claude Code to tools via MCP](https://code.claude.com/docs/en/mcp)

## In Terrarium

Terrarium commits no `.mcp.json`. Its MCP servers come with the [cloud session](https://code.claude.com/docs/en/cloud-environments) it runs in: GitHub's, whose tools are named `mcp__github__*`, and the cloud host's own server for sessions and scheduled tasks, named `mcp__claude-code-remote__*`. A local session has the GitHub tools only if its user configured them.

:file[docs/agents/github-integration.md] has a table of which GitHub tool works where. In a cloud session, `gh` subcommands built on GitHub's GraphQL API, such as `gh issue view`, fail with a 403, and the doc makes the MCP tools the default and maps each `gh` recipe to a tool:

::excerpt{path="docs/agents/github-integration.md" lines="28-33"}
```md
Write through MCP in the cloud (ADR-0017); `gh api` suits bulk reads in scripts,
where the MCP list tools overflow. Some cloud sessions lack `gh`; check with
`which gh`. In a cloud session, map the workflow docs' `gh` recipes
like this:

- **Create / edit / label / close an issue** → `issue_write`.
```
::

Scripts that need many GitHub records, such as :file[scripts/github/list-open-issues.ts], call GitHub's REST API with `gh api`, or with `curl` when `gh` is missing.

Several [hooks](/t/glassbox/guide/claude-code/hooks) in :file[.claude/settings.json] match MCP tools by their full names. The guard that checks every GitHub post for its session header, :file[scripts/hooks/github-provenance-guard.ts], lists each write tool one by one. The hint that points to the GitHub doc, at a session's first GitHub call if the doc is still unread, matches the whole server:

::excerpt{path=".claude/settings.json" lines="129-137"}
```json
      {
        "matcher": "Bash|mcp__github__.*",
        "hooks": [
          {
            "type": "command",
            "command": "cd \"${CLAUDE_PROJECT_DIR:-.}\" && sh scripts/hooks/read-first-hint.sh || true"
          }
        ]
      },
```
::

### Why it's built this way

- **No GraphQL in the cloud.** The cloud session's GitHub proxy refuses GitHub's GraphQL API, so `gh pr` and `gh issue` fail there. Terrarium's docs make the MCP tools the default in the cloud, and its scripts call the REST API. The cost: anything GitHub offers only through GraphQL is out of reach. :file[docs/agents/github-integration.md].
- **Scripts for bulk reads.** The GitHub list tools return whole records, bodies included, and listing open issues through them overflowed the tool's output limit again and again. So a script asks the REST API for only the fields it needs. The cost: one more tool to know, and it needs `gh` or a token. :file[scripts/github/list-open-issues.ts].
- **Writes the guard can see.** Agents post as the owner, so a guard makes each post name its session. Reading shell text, it misses a `gh api` call inside a script, but it sees every MCP call's body. So agents write through MCP. The cost: the guard lists write tools by name, so a new one goes unchecked until added. ADR-0017 (:file[docs/adr/0017-provenance-footer-on-agent-authored-content.md]).
- **Servers from the host.** GitHub access is a connection the owner sets up outside the repository, and the [cloud proxy](https://code.claude.com/docs/en/cloud-environments#github-proxy) adds the owner's credential to each request. Terrarium has nothing to put in a `.mcp.json`. The cost: a local session without its own GitHub server falls back to `gh`. :file[docs/agents/github-integration.md].

### What to watch for

- **Load a tool by its full name.** A deferred tool loads only by its full name, `mcp__github__list_issues`, not `list_issues`; a `select:` that mixes the two silently loads only the full one, and calling an unknown name fails with no hint. :file[docs/agents/github-integration.md] lists the query forms and the recovery.
- **Big results overflow.** `list_issues` and `list_pull_requests` have no compact mode. Pass `fields` that leave out `body`, and a small page size, as :file[docs/agents/github-integration.md] says.
- **The session server can fail once.** A `mcp__claude-code-remote__*` call can fail with a passing "permission stream closed" error. Retry once; :file[docs/agents/environment-caveats.md] says what to do if that fails too.

## Try it in your project

Add a server your team uses with `claude mcp add --scope project`, and commit the `.mcp.json` it writes. Add a `PreToolUse` hook whose matcher is `mcp__<server>__.*` and that logs each call, then ask Claude for something only that server can do and check the log.
