Claude Code's own tools read files and run commands. To work with an outside system, such as an issue tracker, a session needs tools for that system too, and every tool's definition costs context. MCP brings the tools in; tool search keeps them out of context until a session needs one.

Know MCP already? Skip to [In Terrarium](#in-terrarium).

## The concept

The [Model Context Protocol](https://modelcontextprotocol.io/introduction) (MCP) is an open standard for connecting an AI tool to outside systems. An MCP server offers a set of tools, and Claude Code connects to it as a client. You add a server with `claude mcp add`. By default it is private to you and this project, kept in `~/.claude.json`. With `--scope project` it goes in a `.mcp.json` file at the project's root, which you commit so everyone gets the same servers:

```json
{
  "mcpServers": {
    "tracker": {
      "type": "http",
      "url": "https://tracker.example.com/mcp"
    }
  }
}
```

Each tool gets a full name, `mcp__<server>__<tool>`, such as `mcp__tracker__create_issue`. Permission rules and hook matchers use that full name. In a hook matcher, `mcp__tracker__.*` matches every tool from one server; a bare `mcp__tracker` is compared as an exact string and matches nothing.

With many servers, the tool definitions alone would fill much of the context. So by default Claude Code defers them: at the start a session sees only each tool's name and each server's instructions. When Claude needs a tool, it calls the `ToolSearch` tool, which loads that tool's definition, and only then calls the tool itself. The `ENABLE_TOOL_SEARCH` variable turns this off or sets a threshold, and a server whose tools Claude needs on every turn can set `alwaysLoad` to skip it.

Full reference: [Claude Code docs: Connect Claude Code to tools via MCP](https://code.claude.com/docs/en/mcp)

## In Terrarium

Terrarium commits no `.mcp.json`. Its MCP tools come with the cloud session it runs in: the GitHub tools, named `mcp__github__*`, and the cloud host's own server for sessions and scheduled check-ins, named `mcp__claude-code-remote__*` (in some sessions, `mcp__Claude_Code_Remote__*`). [Cloud sessions, settings and permissions](/t/glassbox/guide/claude-code/cloud-sessions) says what else a cloud session brings and lacks.

For GitHub, the MCP tools are the default in the cloud, because the `gh` commands that use GitHub's GraphQL API are blocked there. :file[docs/agents/github-integration.md] sorts it out:

::excerpt{path="docs/agents/github-integration.md" lines="21-26"}
```md
| | Local CLI | Cloud session |
|---|---|---|
| GraphQL-backed `gh` subcommands (`gh issue view`, `gh pr list`, …) | yes | no: 403, GraphQL is blocked |
| `gh api` and REST-backed subcommands (`gh run list`) | yes | yes, though `gh auth status` reports a bad token |
| `mcp__github__*` tools | only if configured | yes |
| **Default** | `gh`; MCP for writes if configured | the MCP tools; `gh api` for REST a tool lacks |
```
::

Writes go through the MCP tools in particular. Several hooks in :file[.claude/settings.json] name MCP tools in their matchers. The guard that checks every GitHub post for its session header matches the write tools one by one; the hint that points to a doc at a session's first GitHub call matches the whole server:

::excerpt{path=".claude/settings.json" lines="110-118"}
```json
      {
        "matcher": "Bash|mcp__github__.*",
        "hooks": [
          {
            "type": "command",
            "command": "cd \"${CLAUDE_PROJECT_DIR:-.}\" && sh scripts/read-first-hint.sh || true"
          }
        ]
      },
```
::

These tools arrive deferred, and Claude Code holds back some of its own tools the same way, such as `Monitor`. :file[docs/agents/github-integration.md] records how loading one behaves here: `ToolSearch` with `select:` finds a tool only by its full name, so `select:mcp__github__list_issues` works and `select:list_issues` fails. A bare name works only as a plain keyword search.

A deferred tool called before its definition loads gets guessed arguments. One mistake kept coming back: `TaskCreate`, one of Claude Code's own deferred tools, called with the arguments of the `Agent` tool. :file[scripts/deferred-tool-guard.ts] denies a call that carries another tool's argument shape and says to load the real one first. It can only recognize a mistake by its shape, so it fails open: see [Guards that fail closed](/t/glassbox/guide/claude-code/guards).

### Why it's built this way

Why agents write to GitHub through the MCP tools: ADR-0017 (:file[docs/adr/0017-provenance-footer-on-agent-authored-content.md]).

### What to watch for

- **One bad name drops quietly.** A `select:` that mixes a full name with a bare one loads only the full one, with no error about the other. Check that every tool you asked for came back.
- **An unknown name gives no hint.** Calling a tool by a bare or misspelled name fails with `No such tool available`, and nothing suggests `ToolSearch`. Search for it by keyword before you decide it doesn't exist.
- **Big results overflow.** Claude Code warns when an MCP result is large, and saves one over its limit to a file. The GitHub list tools return full objects; :file[docs/agents/github-integration.md] says how to keep them small.

## Try it in your project

Add a server your team uses with `claude mcp add --scope project`, and commit the `.mcp.json` it writes. In a new session, ask Claude for something only that server can do, and watch it search for the tool before it calls it.
