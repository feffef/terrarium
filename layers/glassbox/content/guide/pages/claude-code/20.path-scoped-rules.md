An agent can't follow an instruction it never sees, and a `CLAUDE.md` that holds every instruction about every file grows too long to follow. A path-specific rule puts an instruction in front of the agent when it works on the files the instruction is about.

Know path-specific rules already? Skip to [In Terrarium](#in-terrarium).

## The concept

Claude Code reads each Markdown file in a project's `.claude/rules/` folder, including its subfolders, as a rule. A rule without a `paths` field loads at the start of every session, like `CLAUDE.md`. A rule whose frontmatter lists `paths` loads only when Claude works with a file that one of its globs matches: when it reads, writes or edits that file with its own tools, or views it with a simple shell read such as `cat` on that one file.

```md
---
paths:
  - "src/api/**/*.ts"
---
# API handlers

- Validate every request body before you use it.
```

`paths` is the only frontmatter field Claude Code reads. It ignores any other field without an error, and removes the frontmatter before the rule reaches Claude's context.

Full reference: [Claude Code docs: Path-specific rules](https://code.claude.com/docs/en/memory#path-specific-rules)

## In Terrarium

Terrarium gives each instruction one home, chosen by what it is about. An instruction about certain files is a :term[Rule] in :file[.claude/rules/] whose `paths` match those files. An instruction every session needs, or one tied to an action such as a commit or a PR, stays in :file[CLAUDE.md]. For example, :file[.claude/rules/tenant-layers.md] matches each Tenant layer's `nuxt.config.ts`, `tenant.config.ts` and `app/` folder, so an agent editing a :term[Tenant] learns that a layer's CSS loads on every page:

::excerpt{path=".claude/rules/tenant-layers.md" lines="1-8,25-29"}
```md
---
paths:
  - "nuxt.config.ts"
  - "layers/*/nuxt.config.ts"
  - "layers/*/tenant.config.ts"
  - "layers/*/app/**"
---
# Tenant layers
<!-- … -->
- **A layer is not a sandbox.** Its `css:` loads on every page (scope it under
  the wrapper class), its plugins and `nuxt.config` flags apply app-wide (keep
  them inert outside the Tenant's opt-in), its `package.json` can't scope a
  dependency (a new one escalates, ADR-0004), and storage is one origin
  (prefix keys, delete only yours, never `clear()`).
```
::

Every :term[ADR] also has a summary rule, `adr-NNNN.md`, that gives the ADR's key parts as instructions and says when to read the whole ADR. Its `paths` list the files the ADR governs. A summary whose ADR is relevant to every session has no `paths`, and it loads at session start.

In the summary of the ADR on Skills, below, the `adr` field is a hash of the ADR, which the gate checks and Claude Code ignores. Its Skill-specific `paths` at the end name single Skills' folders, which the Skill hook described after this excerpt looks for:

::excerpt{path=".claude/rules/adr-0005.md" lines="1-11"}
```md
---
adr: ef08a96f7751
paths:
  - ".agents/skills/**"
  - ".claude/skills/**"
  - ".claude/workflows/**"
  - "skills-lock.json"
  - ".agents/skills/frictions-to-fixes/**"
  - ".agents/skills/audit-docs/**"
---
# ADR-0005: Skills are Platform code, committed with the repo
```
::

:file[scripts/gate/validate-adr-rules.ts], part of `pnpm validate:content` and so of the :term[Gate], fails any rule that has no `paths` and isn't named for an ADR (`adr-NNNN…`). How it also keeps each summary in step with its ADR is in [Decision records](/t/glassbox/guide/terrarium-practice/decision-records).

Two [hooks](/t/glassbox/guide/hooks/hooks) fill the gaps where Claude Code loads no rule. Running a :term[Skill] reads no file, so :file[scripts/hooks/skill-rules-hint.ts] adds the rules whose `paths` name that Skill's own folder, not a glob over every Skill. A piped or chained shell command is not a simple read, so :file[scripts/hooks/bash-rules-hint.ts] adds the rules for the files such a command read. :file[.claude/settings.json] wires both in (the shell one through a `.sh` filter that runs the script only when a command could match), and both fail open: an error adds nothing and never blocks the call.

A third hook, :file[scripts/hooks/adr-read-hint.ts], points the agent to the full ADR after a change to a file its rules govern ([Hook-added context](/t/glassbox/guide/hooks/hook-added-context#in-terrarium)).

### Why it's built this way

- **Rules find the agent.** `CLAUDE.md` lines like "before you edit X, read Y" were often skipped. A :term[Rule] loads by itself when the agent touches its files, so file-specific instructions moved there. The cost: a rule arrives after a file is touched, so an agent can edit before reading the full ADR; a hint after each write points it there ([Hook-added context](/t/glassbox/guide/hooks/hook-added-context#why-its-built-this-way)). ADR-0029 (:file[docs/adr/0029-instructions-load-with-the-files-they-govern.md]).
- **Short ADR summaries.** Loading a whole ADR as a rule would fill the context, so the ADR would shrink to a summary and lose its reasons. A short summary loads instead, and the full ADR keeps the why; importing the ADR with `@` was rejected too, since the ADR would then load in every session. The cost: a summary can drift from its ADR. ADR-0030 (:file[docs/adr/0030-adrs-document-a-decision-not-its-history.md]).
- **One home per instruction.** `CLAUDE.md` loads every session, and no file pattern matches an action such as a commit, so those instructions stay there. Other rules loading at session start would give two homes and drifting copies, so only rules named for an ADR may skip `paths`; the gate fails any other. ADR-0029 (:file[docs/adr/0029-instructions-load-with-the-files-they-govern.md]).
- **Hooks add the rules a Skill or shell read misses.** Some ways an agent reads files load no rule, such as a chained shell command or running a :term[Skill]. Two hooks add the missing rules, as hints only: working out paths from a shell command is a guess, and a broken hint must never block a session. ADR-0029 (:file[docs/adr/0029-instructions-load-with-the-files-they-govern.md]).

### What to watch for

- **A rule can't order a step.** Why, and where such steps go instead: [CLAUDE.md](/t/glassbox/guide/claude-code/claude-md#what-to-watch-for).
- **Searching a folder loads none of its rules.** A command such as `grep -r` over a whole folder reads no single file, so neither Claude Code nor :file[scripts/hooks/bash-rules-hint.ts] adds a rule for it. The folder's rules arrive only when the agent reads or edits a file inside it.
- **A rule change waits for a person.** Every file in `.claude/rules/` is on the :term[Human-only] list, so an agent may edit a rule but not merge the change.

## Try it in your project

Find one line in your `CLAUDE.md` about a particular set of files. Move it into a file in `.claude/rules/` whose `paths` match those files, and delete the line from `CLAUDE.md`.
