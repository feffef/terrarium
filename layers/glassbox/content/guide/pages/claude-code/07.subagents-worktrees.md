One session can hand parts of its work to other agents and keep only their answers. Those agents start knowing nothing, and several of them editing one checkout at once trip over each other. A self-contained brief and a git worktree each solve one of those problems.

Know subagents and worktrees already? Skip to [In Terrarium](#in-terrarium).

## The concept

A subagent is a helper Claude starts inside a session. It runs in its own context window, with its own system prompt and tools. It doesn't see the conversation that started it, the Skills already run or the files already read: it gets a message describing the task and works from that. When it finishes, only its final report comes back, so the searching and reading it did stays out of the main conversation.

Subagents that edit files need room of their own. A [git worktree](https://git-scm.com/docs/git-worktree) is a second working folder of the same repository, with its own files and branch, sharing one history. Claude Code can give each subagent a fresh worktree: ask Claude to "use worktrees for your agents", or add `isolation: worktree` to a custom subagent's frontmatter. It creates the worktree under `.claude/worktrees/`, from the default branch unless the settings say to branch from the current `HEAD`, and removes it when the subagent finishes without changes. A worktree is a fresh checkout, so it has none of the main folder's untracked files, such as installed dependencies.

```md
---
name: refactorer
description: Applies one mechanical refactor across many files
isolation: worktree
---

Apply the refactor across every affected file, run the tests,
and report the results.
```

Full reference: [Claude Code docs: Create custom subagents](https://code.claude.com/docs/en/sub-agents)

## In Terrarium

Terrarium dispatches subagents for reviews, research, screenshots and whole branches of work. How to dispatch them is one :term[Skill], :file[.agents/skills/dispatch-subagents/SKILL.md], which `CLAUDE.md` says to read before dispatching any subagent that touches git or needs a worktree. Its goal is that every subagent's work lands, is right, and is never stranded: finished but uncommitted, or never seen by the session that asked for it.

It starts with the choice of isolation:

::excerpt{path=".agents/skills/dispatch-subagents/SKILL.md" lines="16-20"}
```md
## 2. Pick the isolation

- **A dispatched subagent that touches git:** pass `isolation: 'worktree'` on the
  Agent call. Without it, parallel agents share one checkout and race on
  branches.
```
::

Most of the Skill is a checklist for the brief, because the subagent sees nothing else. It names the exact commit to start from and has the agent check its checkout matches, since a new worktree can start from an older `main`. It has the agent run `pnpm install` first. It has every git command start with `cd <worktree-root> &&`, because the shell tool resets the working folder between calls. It says to commit before stopping, even halfway through a check, and to give every log and screenshot a name of its own, because subagents share the session's scratch folder.

The Skill also says who does what. A subagent building a branch hands it back committed and unpushed. The session that dispatched it reviews the branch and sends every fix back to the same agent, which pushes once a review comes back clean. The dispatching session then opens and lands the PR itself. Here a subagent can't dispatch subagents of its own, because the environment Terrarium's sessions run in sets `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1`, so a review or a nested dispatch is the dispatching session's job. Subagents don't write session logs either. A subagent shares its parent's session id, so its log would overwrite the parent's, and the log script refuses to write one from inside a linked worktree.

Two checks run outside the brief. A guard denies a dispatched subagent a background shell command, since a command it backgrounds can never wake it when it ends. And before it finishes, the dispatching session runs `pnpm check:worktrees`, which runs :file[scripts/git/check-worktrees.ts], which reads git's own list of worktrees and fails for any one left with uncommitted or unpushed work, including one whose agent stopped without reporting back. A sweep built from git's own list catches the case no brief can: an agent that never returns.

A stopped subagent is resumed with `SendMessage` to its agent id, never dispatched again. A new dispatch gets a new checkout and no memory, so it can start a second copy of a branch or leave the first one's commits behind.

### Why it's built this way

- **One checklist, read each time.** A subagent's mistakes are often silent: parallel agents wrote check output to one log file, each read another's overwrite, and the dispatching session published a wrong diagnosis. So the brief's rules sit in one Skill read before every dispatch, not in memory. The cost: a long brief even for a small task. :file[.agents/skills/dispatch-subagents/SKILL.md].
- **A sweep for lost work.** "Commit before you stop" as an instruction failed: one agent ended its turn waiting on a background check, then died silently once resumed. An instruction can't catch an agent that never returns, so a script reads git's own list of worktrees and fails on left-behind work. It shows the loss; it can't prevent it. :file[scripts/git/check-worktrees.ts].
- **No background commands.** A subagent's turn ends when it stops to wait, and nothing wakes it when a background command ends, even when the brief said how to check. So a guard refuses the command outright. The cost: a long check runs in the foreground, and one outlasting a single call needs a resume. :file[scripts/hooks/subagent-background-guard.ts].
- **Review by the dispatcher.** Every branch is reviewed before its first push, since pushing leads straight to a PR. A subagent can't start a reviewer, so the dispatching session reviews while the subagent waits unpushed. Fixes go back to the same agent, which still holds the worktree and its reasons. The cost: a round trip per review, all done by the dispatching session. ADR-0004 (:file[docs/adr/0004-objective-safety-gate.md]).

### What to watch for

- **The brief is all it knows.** A rule, a count or a source the dispatching session already holds has to be in the brief, or the subagent derives it again or misses it.
- **One git command per shell call.** Inside a worktree, Claude Code refuses a shell command when it can't tell from the text that every git command in it stays in that worktree. Plain, separate commands pass.
- **Its report is a claim.** A subagent's prose is checked against the source it cites before anything ships on it.
- **Make your own worktrees under `.claude/worktrees/`.** A worktree outside the project folder misses the project's path-scoped rules when an agent reads its files.

## Try it in your project

Next time you hand Claude a task with parallel edits, ask it to use a worktree for each agent. Write the brief as if to a stranger: the commit to start from, the setup command, what to commit, and what to report back. Then run `git worktree list` when they finish, and check that nothing is left uncommitted.
