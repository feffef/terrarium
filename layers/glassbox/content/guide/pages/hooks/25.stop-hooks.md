A `PreToolUse` hook ([Blocking hooks](/t/glassbox/guide/hooks/blocking-hooks)) looks at one tool call before it runs. A Stop hook looks at the whole turn once it is over: it runs when the agent finishes its reply, checks what the turn did and left undone, and can refuse the stop, so the agent keeps working on a reason the hook gives. Refusing a stop is a loop, so the hook must also know when to let go.

Know Stop hooks already? Skip to [In Terrarium](#in-terrarium).

## The concept

Claude Code fires `Stop` when the main agent has finished responding, and `SubagentStop` when a subagent has. `Stop` doesn't run when the user interrupts the turn, and an API error fires `StopFailure` instead. Beside the fields every [hook](/t/glassbox/guide/hooks/hooks) gets, such as `transcript_path`, a `Stop` hook receives `last_assistant_message`, the text of the final reply, and `stop_hook_active`. A `SubagentStop` hook also gets `stop_hook_active`, plus `agent_id`, `agent_type` and `agent_transcript_path`, the subagent's own transcript; its `transcript_path` is the main session's.

To refuse the stop, the hook exits 0 and prints a decision. `reason` is required: it tells Claude why to continue. Exiting 2 instead sends stderr to Claude as the reason.

```json
{ "decision": "block", "reason": "The tests have not run. Run them before finishing." }
```

A hook that is only giving guidance can print `hookSpecificOutput.additionalContext` instead. The conversation also goes on, but the transcript labels it hook feedback, and no hook error is shown.

Either way the hook has to let go. `stop_hook_active` is `true` when Claude is already continuing because a stop hook blocked; a hook that checks it, or the transcript, never blocks on a condition that will never resolve. Behind that check, Claude Code applies an 8-consecutive-continuation cap: after stop hooks have continued the turn eight times in a row, it ends the turn anyway. The count resets each time Claude calls a tool, and `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP` raises it. A shell hook can read the flag with `jq`:

```sh
[ "$(jq -r .stop_hook_active)" = true ] && exit 0
echo '{"decision":"block","reason":"…"}'
```

A Stop hook is for checking an outcome after the work. To prevent a wrong tool call, a `PreToolUse` hook denies it before it runs ([Blocking hooks](/t/glassbox/guide/hooks/blocking-hooks)); a standing instruction belongs in [CLAUDE.md](/t/glassbox/guide/claude-code/claude-md) or a rule ([Path-specific rules](/t/glassbox/guide/claude-code/path-scoped-rules)). Each block sends the agent back for another round of work.

Full reference: [Claude Code docs: Stop](https://code.claude.com/docs/en/hooks#stop)

## In Terrarium

The `Stop` hooks are wired in :file[.claude/settings.json] with an empty matcher. The first lands the :term[session log], the session's record in the Journal, on `main` with :file[scripts/session/log-session.ts], and never prints a decision. The others block the stop once each:

- :file[scripts/hooks/harness-tag-stop.ts] when the reply holds a `<task-notification>` or `<agent-message>` tag, which only Claude Code delivers, meaning the agent wrote a subagent's report itself;
- :file[scripts/hooks/merge-close-stop.ts] when the session merged a PR and has not run `close-session`, the skill that closes a session and records its log, since;
- :file[scripts/hooks/pr-subscribe-stop.ts] when it opened a PR and never subscribed to its activity.

One `SubagentStop` hook, :file[scripts/hooks/subagent-rule-use-stop.ts], blocks a subagent's stop once while it hasn't reported how it used each :term[rule] that loaded for it. :file[docs/agents/guards.md] is the live list.

The blocking `Stop` hooks share one pattern: read the payload with `readHookJson` from :file[scripts/hooks/hook-io.ts], return at once on a re-entered stop ([the loop check](#the-concept)), read the transcript, test the turn, and print the block decision. The PR-subscribe hook counts the tool calls in the transcript and blocks when one opened a PR and none subscribed. Its message cites ADR-0003, a decision record (:file[docs/adr/0003-agent-operating-model-and-governance.md]):

::excerpt{path="scripts/hooks/pr-subscribe-stop.ts" lines="11-21"}
```ts
export function main(): void {
  const read = readHookJson()
  if (read.kind !== 'ok' || prop(read.json, 'stop_hook_active') === true) return
  const path = prop(read.json, 'transcript_path')
  const records = readTranscript(typeof path === 'string' ? path : undefined) ?? []
  const names = Object.keys(extractTrace(records).toolCounts)
  if (names.some((n) => n.includes('create_pull_request')) && !names.some((n) => n.endsWith('subscribe_pr_activity'))) {
    const reason = 'You opened a PR and never called subscribe_pr_activity (ADR-0003). Subscribe now, or say why you cannot.'
    process.stdout.write(JSON.stringify({ decision: 'block', reason }))
  }
}
```
::

The merge-close hook makes its test by calling `closureRefusal` from :file[scripts/session/log-session.ts], the check the log script itself uses to refuse a completed log after a merge with no `close-session` since.

The `SubagentStop` hook makes the same loop check, and also counts its own blocks. It reads the subagent's transcript, found from `transcript_path` and `agent_id`, and before it blocks, it writes a marker file named for that `agent_id` in the operating system's temp folder; a marker already there means the subagent was blocked before, and it passes:

::excerpt{path="scripts/hooks/subagent-rule-use-stop.ts" lines="25-29"}
```ts
  // One block per agent_id, so the cap holds without trusting `stop_hook_active`
  // at SubagentStop and a subagent with no Bash tool is let go on its next stop.
  const marker = join(markerDir, `subagent-rule-use-stop-${agent.replace(/\W/g, '_')}`)
  if (existsSync(marker)) return null
  writeFileSync(marker, '')
```
::

Every one of these hooks ends in `|| true`, which turns any exit code into 0: a crash never blocks ([Claude Code hooks](/t/glassbox/guide/hooks/hooks#in-terrarium)). A hook that crashes, gets a payload that isn't JSON or can't read the transcript prints no decision, and the stop goes through.

Each hook has its own spec in :file[tests/unit/]. :file[tests/unit/pr-subscribe-stop.spec.ts] writes a small transcript, runs the real script with a payload on stdin, and checks the block, the passes, and that a re-entered stop prints nothing.

### Why it's built this way

- **Only a Stop hook sees what never happened.** A `PreToolUse` hook runs before a call and a `PostToolUse` hook after one, so neither sees a call never made, such as a PR subscription. The PR-subscribe and merge-close hooks check the finished turn instead; merge-close reuses the log script's test, so the two can't disagree. :file[scripts/hooks/merge-close-stop.ts].
- **Block once, then let go.** Instead of blocking until the condition holds and leaning on the continuation cap, Terrarium's `Stop` hooks make the loop check ([The concept](#the-concept)), and the PR-subscribe hook's message accepts a stated reason. The cost: an agent that ignores the message stops on its next try. :file[scripts/hooks/pr-subscribe-stop.ts].
- **The subagent hook counts its own blocks.** Instead of trusting `stop_hook_active` alone at `SubagentStop`, its comment says, one block per `agent_id` keeps the cap. The cost: a marker file per blocked subagent in the temp folder, and a subagent that still can't report, such as one with no `Bash` tool, is let go on its next stop. :file[scripts/hooks/subagent-rule-use-stop.ts].

### What to watch for

- **A user interrupt skips the hook.** `Stop` doesn't run when the user stops the turn, and an API error fires `StopFailure`, whose output Claude Code ignores.
- **The reason is the next instruction.** Claude reads it as why it should keep working, so write it as what to do ([Blocking hooks](/t/glassbox/guide/hooks/blocking-hooks#what-to-watch-for)).
- **Without the loop check, only the cap stops a loop.** A hook that skips the check ([The concept](#the-concept)) and keeps no count of its own leans on the cap, which resets each time Claude calls a tool.
- **The transcript may lag.** A hook that searches the transcript for the final reply may not find it yet; `last_assistant_message` holds it ([Session transcripts](/t/glassbox/guide/hooks/session-transcripts#the-concept)).

## Try it in your project

This hook blocks the stop once while the project has uncommitted changes. Save it as `.claude/hooks/uncommitted-stop.sh` and make it executable (`chmod +x`); it needs `jq`:

```sh
#!/bin/sh
[ "$(jq -r .stop_hook_active)" = true ] && exit 0
[ -z "$(git -C "$CLAUDE_PROJECT_DIR" status --porcelain)" ] && exit 0
echo '{"decision":"block","reason":"There are uncommitted changes. Commit them, or say why they should stay uncommitted."}'
```

Test it by hand in a project with an uncommitted file: `echo '{"stop_hook_active":false}' | CLAUDE_PROJECT_DIR=$PWD .claude/hooks/uncommitted-stop.sh` prints the block decision, the same command with `stop_hook_active` set to `true` prints nothing, and in a clean tree both print nothing. The new script is itself an uncommitted file until you commit it. Then add this matcher group under `hooks.Stop` in `.claude/settings.json`:

```json
{ "hooks": [{ "type": "command", "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/uncommitted-stop.sh" }] }
```

Ask Claude to create a file and end its turn. Instead of stopping, Claude gets the reason and either commits or explains; on its next stop `stop_hook_active` is true, and the turn ends whatever it chose.
